## Question 1: How big is the data?

```python
df.shape
# (891, 12)
```

`shape` returns a tuple `(rows, columns)`.

```python
n_rows, n_cols = df.shape
print(f"{n_rows} rows x {n_cols} columns, {df.size} cells")
```

### Why it matters

- **Memory and speed:** a 900-row file loads instantly; a 50-million-row file needs chunking or a database (see [[01.Working with CSV Files]]).
- **Model choice:** very small datasets (a few hundred rows) overfit easily with complex models.
- **Sanity check:** did the load work? If you expected 1,000 rows and see 999, the header may have been consumed as data, or a bad line was skipped.
- **Rows vs columns:** many more columns than rows (a "wide" dataset, e.g. genomics) calls for feature selection.

### Check actual memory use

```python
df.memory_usage(deep=True).sum() / 1024**2     # size in MB
```

## Question 2: How does the data look?

```python
df.head()          # first 5 rows
df.tail()          # last 5 rows
df.sample(5)       # 5 random rows
```

### Why `sample()` beats `head()`

Files are often sorted by date, category, or target. The first rows may all look alike and mislead you. Random rows give a fairer picture.

```python
df.sample(5)                      # different rows every run
df.sample(5, random_state=42)     # reproducible rows, good for notes and tutorials
df.sample(frac=0.1, random_state=42)   # a 10% random subset
```

### See every column when output is truncated

```python
pd.set_option("display.max_columns", None)
pd.set_option("display.width", 200)
df.sample(5, random_state=1).T       # transpose: columns become rows, easier on wide data
```

### What to look for

- Do the values match the column names? (e.g. a `Fare` column full of text)
- Odd placeholders such as `?`, `-`, `N/A`, `999`, `0` standing in for "unknown".
- Inconsistent formatting: `Male` vs `male`, `S` vs `Southampton`.
- Whether the data looks sorted or grouped.

### Wrong types to watch for

|Symptom|Likely cause|Fix|
|---|---|---|
|Numeric column is `object`|Stray text like `"N/A"` or `"$1,200"`|`pd.to_numeric(col, errors="coerce")`|
|Date column is `object`|Not parsed|`pd.to_datetime(col)` or `parse_dates` when loading|
|ID stored as `int64`|Leading zeros lost|Read with `dtype=str`|
|Category stored as `object`|Default text type|`astype("category")`|
|Integer column became `float64`|It contains `NaN`|Handle missing values, or use a nullable type like `Int64`|

### Optimisation tip: use smaller types

`Age` is `float64` by default, and many columns use `int64` when much smaller types would do. Smaller types use less memory and can speed up model training.

```python
before = df.memory_usage(deep=True).sum()

df_small = df.copy()
df_small["Survived"] = df_small["Survived"].astype("int8")
df_small["Pclass"] = df_small["Pclass"].astype("int8")
df_small["SibSp"] = df_small["SibSp"].astype("int8")
df_small["Parch"] = df_small["Parch"].astype("int8")
df_small["Age"] = df_small["Age"].astype("float32")
df_small["Fare"] = df_small["Fare"].astype("float32")
df_small["Sex"] = df_small["Sex"].astype("category")
df_small["Embarked"] = df_small["Embarked"].astype("category")

after = df_small.memory_usage(deep=True).sum()
print(f"{before/1024:.0f} KB -> {after/1024:.0f} KB  ({1 - after/before:.0%} smaller)")
```

> **A caveat on converting `Age` to `int32`:** `Age` has missing values (`NaN`), and standard NumPy integers cannot hold `NaN`. It also has fractional ages for infants (e.g. 0.42). So `astype("int32")` on the raw column fails. Either fill missing values first and decide whether rounding is acceptable, use a nullable type (`"Int32"`, only safe if values are whole numbers), or simply use `float32`.

### Let pandas pick small types for you

```python
df["Fare"] = pd.to_numeric(df["Fare"], downcast="float")
df["PassengerId"] = pd.to_numeric(df["PassengerId"], downcast="integer")
```

### Set types when loading

```python
df = pd.read_csv(
    "train.csv",
    dtype={"Survived": "int8", "Pclass": "int8", "Sex": "category", "Embarked": "category"},
)
```

### More ways to look at it

```python
df.isnull().sum().sum()                 # total missing cells
df.isnull().any(axis=1).sum()           # rows with at least one missing value
df.dropna().shape                       # rows left if you drop every incomplete row

```

Notice that `df.dropna()` on Titanic would throw away most of the data, because `Cabin` is almost always missing. That single number often settles the question of whether to drop rows.

### Visualise missing data

```python
import seaborn as sns

plt.show()
```

### Hidden missing values

`isnull()` only finds real `NaN`. Placeholders slip through:

```python
df.replace(["?", "-", "N/A", "unknown", ""], np.nan, inplace=True)

# Or declare them when loading
df = pd.read_csv("train.csv", na_values=["?", "-", "N/A", "unknown"])

# Suspicious zeros: a Fare of 0, or an Age of 0
(df["Fare"] == 0).sum()
```

### Why it matters: deciding what to do

|Situation|Typical decision|
|---|---|
|Column is mostly empty (`Cabin`, 77%)|Drop it, or keep a "has value" flag|
|A few missing in an important column (`Embarked`, 2)|Fill with the most frequent value, or drop those rows|
|A moderate share missing (`Age`, 20%)|Impute with mean, median, or a group-based median|
|Missingness itself carries meaning|Add an indicator column|

A preview of these options (full treatment comes in the data-cleaning notes):

```python
# Few missing, categorical -> mode
df["Embarked"] = df["Embarked"].fillna(df["Embarked"].mode()[0])

# Moderate missing, numeric -> median within groups
df["Age"] = df["Age"].fillna(df.groupby(["Pclass", "Sex"])["Age"].transform("median"))

# Mostly missing -> keep only the signal
df["HasCabin"] = df["Cabin"].notna().astype(int)
df = df.drop(columns="Cabin")
```

Always ask **why** values are missing. Many first-class passengers have a recorded cabin and most third-class ones do not, so `HasCabin` is a hint about class and survival, not random noise.

### How to read each row

|Statistic|Meaning|
|---|---|
|`count`|Non-missing values (compare with total rows to spot gaps; `Age` shows 714, not 891)|
|`mean`|Average|
|`std`|Spread around the mean|
|`min` / `max`|Extremes|
|`25%` / `50%` / `75%`|Quartiles; 50% is the **median**|

### What the Titanic numbers tell us

- **Age:** mean around 29.7 and median 28, so the distribution is fairly balanced. The minimum of 0.42 is an infant (about five months), and the maximum is 80.
- **Fare:** mean 32.2 but median 14.45, with a maximum of 512.33. Mean far above median means the distribution is **right-skewed** with some very expensive tickets (outliers). The median describes a typical passenger better here.
- **Survived:** the mean of a 0/1 column is the survival rate, about 38%. Handy shortcut.
- **Fare minimum of 0:** possibly free tickets or crew, or missing data recorded as zero. Worth investigating.
- **Pclass, Survived, SibSp, Parch:** stats on these are less meaningful because they are categories or small counts; `describe()` treats every numeric column the same way.

### Useful options

```python
df.describe().T                              # transposed, easier to read on wide data
df.describe(include="object")                # text columns: count, unique, top, freq
df.describe(include="all")                   # everything together
df.describe(percentiles=[0.01, 0.05, 0.95, 0.99])    # custom percentiles for outliers
df["Fare"].describe()                        # a single column
```

## Question 6: Are there duplicate rows?

```python
df.duplicated().sum()
# 0
```

The Titanic file has no duplicates, which is itself a useful finding. Real datasets often do.

### Detect and handle duplicates

```python
df.duplicated()                         # True for each repeated row (after the first)
df[df.duplicated(keep=False)]           # show ALL copies, including the first
df = df.drop_duplicates()               # drop exact duplicates, keep the first
df = df.drop_duplicates(keep="last")    # keep the last copy instead
```

### Duplicates on a key, not the whole row

Whole-row matching misses duplicates that differ in a minor column such as a timestamp.

```python
df.duplicated(subset=["Name", "Ticket"]).sum()
df = df.drop_duplicates(subset=["Name", "Ticket"], keep="first")
```

On Titanic, `PassengerId` is unique per row, so whole-row duplicates are impossible unless you exclude it:

```python
df.drop(columns="PassengerId").duplicated().sum()
```

### Demo with messy data

```python
orders = pd.DataFrame({
    "order_id": [101, 102, 102, 103, 104, 104],
    "customer": ["Asha", "Ben", "Ben", "Chen", "Dina", "Dina"],
    "amount":   [250, 400, 400, 150, 90, 95],
})

orders.duplicated().sum()                          # 1  (rows 1 and 2 are identical)
orders.duplicated(subset="order_id").sum()         # 2  (order 104 appears twice with different amounts)
orders[orders.duplicated(subset="order_id", keep=False)]
```

The two kinds of duplicate need different handling: identical rows are safe to drop, but conflicting rows (order 104: 90 vs 95) need a business decision about which one is correct.

### Why it matters

- Duplicates **inflate counts and sums** (revenue counted twice).
- In machine learning, the same record in both the training and test set causes **data leakage**, making accuracy look better than it is.
- They overweight some observations and bias the model.

Check the shape before and after so you know exactly what you removed:

```python
before = len(df)
df = df.drop_duplicates()
print(f"Removed {before - len(df)} duplicate rows")
```

## Question 7: Is there any correlation between columns?

```python
df.corr(numeric_only=True)
```

In pandas 2.0 and later you must pass `numeric_only=True`, otherwise text columns such as `Name` raise an error.

### Correlation with the target

```python
df.corr(numeric_only=True)["Survived"].sort_values(ascending=False)
```

|Feature|Correlation with `Survived`|
|---|---|
|Survived|1.000|
|Fare|+0.257|
|Parch|+0.082|
|SibSp|-0.035|
|PassengerId|-0.005|
|Age|-0.077|
|Pclass|-0.338|

### Reading the coefficient (Pearson's r, from -1 to +1)

|Value of r|Meaning|
|---|---|
|+1|Perfect positive: both rise together|
|+0.5 to +1|Strong positive|
|0.1 to 0.5|Weak to moderate|
|about 0|No linear relationship|
|-0.5 to -1|Strong negative: one rises, the other falls|
|-1|Perfect negative|

### Interpreting the Titanic results

- **Positive: `Fare` (about +0.26).** Higher ticket prices went with a higher chance of survival.
- **Negative: `Pclass` (about -0.34).** This looks odd until you remember class 1 is the _best_ class. A lower class number meant better survival odds, so as the number rises, survival falls.
- **Near zero: `PassengerId` (about -0.005).** It is just a row label, so it has no predictive value and can be dropped when selecting features.

Check these against the raw data:

```python
df.groupby("Pclass")["Survived"].mean().round(3)
# 1: 0.630   2: 0.473   3: 0.242

df.groupby("Sex")["Survived"].mean().round(3)
# female: 0.742   male: 0.189
```

### Sex is missing from the correlation table. Why?

`corr()` only uses numeric columns. `Sex` is text, so it is skipped, even though it is one of the strongest predictors. Encode it to include it:

```python
tmp = df.copy()
tmp["Sex_num"] = tmp["Sex"].map({"male": 0, "female": 1})
tmp[["Sex_num", "Survived"]].corr().iloc[0, 1]      # about +0.54
```

### Correlation matrix as a heatmap

```python
import seaborn as sns
import matplotlib.pyplot as plt

corr = df.corr(numeric_only=True)

plt.figure(figsize=(8, 6))
sns.heatmap(corr, annot=True, fmt=".2f", cmap="coolwarm", vmin=-1, vmax=1, square=True)
plt.title("Titanic correlation matrix")
plt.show()
```

### Find highly correlated feature pairs

Pairs of inputs that are very strongly correlated carry redundant information (multicollinearity).

```python
corr = df.corr(numeric_only=True).abs()
upper = corr.where(np.triu(np.ones(corr.shape), k=1).astype(bool))
pairs = upper.stack().sort_values(ascending=False)
print(pairs.head(5))

to_drop = [c for c in upper.columns if (upper[c] > 0.9).any()]
```

### Other correlation methods

```python
df.corr(numeric_only=True, method="spearman")    # rank-based, handles monotonic non-linear trends
df.corr(numeric_only=True, method="kendall")     # rank-based, good for small samples
df["Age"].corr(df["Fare"])                       # between two specific columns
```

### Limits of correlation

- **Correlation is not causation.** Fare correlates with survival, but cabin location and class policies are likely the real drivers.
- **Pearson captures only linear relationships.** A U-shaped relationship can have r near 0 and still be very strong.
- **Sensitive to outliers.** A few very large fares can shift `Fare`'s correlation.
- **Numeric only.** For categories, compare group means (`groupby`), cross-tabs, or chi-square tests.
- **Encoded categories mislead.** Correlating an arbitrary label code (`Embarked` as 0/1/2) is meaningless because the numbers have no order.

```python
pd.crosstab(df["Sex"], df["Survived"], normalize="index").round(3)      # survival rate by group
pd.crosstab(df["Pclass"], df["Survived"], margins=True)
```

## Putting it together: a reusable audit function

```python
def quick_audit(df, target=None, corr_threshold=0.9):
    """Run the 7 basic questions on any DataFrame."""
    print(f"1. SIZE        : {df.shape[0]} rows x {df.shape[1]} columns, "
          f"{df.memory_usage(deep=True).sum() / 1024**2:.2f} MB")

    print("\n2. SAMPLE")
    print(df.sample(min(5, len(df)), random_state=0).to_string())

    summary = pd.DataFrame({
        "dtype": df.dtypes,
        "non_null": df.notna().sum(),
        "missing": df.isna().sum(),
        "missing_%": (df.isna().mean() * 100).round(1),
        "unique": df.nunique(),
    })
    print("\n3-4. TYPES & MISSING")
    print(summary.to_string())

    print("\n5. NUMERIC SUMMARY")
    print(df.describe().T.to_string())

    dup = df.duplicated().sum()
    print(f"\n6. DUPLICATES  : {dup} exact duplicate rows ({dup / len(df):.1%})")

    num = df.select_dtypes("number")
    if num.shape[1] > 1:
        corr = num.corr()
        print("\n7. CORRELATION")
        if target in corr.columns:
            print(corr[target].drop(target).sort_values(ascending=False).round(3).to_string())
        pairs = corr.abs().where(np.triu(np.ones(corr.shape), 1).astype(bool)).stack()
        high = pairs[pairs > corr_threshold]
        print(f"Highly correlated pairs (> {corr_threshold}):", high.to_dict() or "none")

    return summary

summary = quick_audit(df, target="Survived")
```

Run this the moment you receive any new file. It takes seconds and prevents hours of debugging later.

## Use cases: the same questions on different data

|Scenario|Question 1: size|Question 4: missing|Question 6: duplicates|Question 7: correlation|
|---|---|---|---|---|
|**Sales / orders table**|Millions of rows? Plan for chunking|Missing `customer_id` breaks joins|Same order inserted twice inflates revenue|Quantity vs price, discount vs sales|
|**Customer churn data**|Few columns, many rows|Blank contract fields mean "no contract" or "unknown"?|Duplicate customer records split history|Tenure vs churn, support calls vs churn|
|**Sensor / IoT readings**|Huge, time-ordered; `sample()` beats `head()`|Gaps mean sensor outages|Repeated timestamps from retries|Temperature vs pressure, redundant sensors|
|**Survey responses**|Small; avoid complex models|"Prefer not to say" coded as `-99`|Double submissions|Satisfaction vs loyalty questions|
|**Scraped data** (see [[04.Web Scraping]])|Compare with the number of pages|Selector failures show as sudden nulls|Same item on several pages|Price vs rating|

### Mini case: audit a sales extract

```python
sales = pd.DataFrame({
    "order_id":   [1, 2, 3, 3, 4, 5, 6],
    "date":       ["2024-01-03", "2024-01-04", "2024-01-04", "2024-01-04", "2024-01-05", "N/A", "2024-01-07"],
    "customer":   ["A12", "B07", None, None, "C33", "A12", "D01"],
    "qty":        [2, 1, 5, 5, 1, 3, 40],
    "unit_price": [10.0, 99.0, 5.5, 5.5, 99.0, 10.0, 10.0],
})

print(sales.shape)                          # (7, 5)
sales.info()                                # date is object, not datetime
print(sales.isnull().sum())                 # customer: 2 missing
print(sales.duplicated().sum())             # 1 duplicate (order 3)
print(sales["qty"].describe())              # max 40 vs median 2 -> outlier / data-entry error?

sales["date"] = pd.to_datetime(sales["date"], errors="coerce")   # "N/A" becomes NaT
sales = sales.drop_duplicates()
sales["revenue"] = sales["qty"] * sales["unit_price"]
print(sales[["qty", "unit_price", "revenue"]].corr())
```

Five quick checks flagged a wrong date type, a placeholder (`"N/A"`), missing customer IDs, a duplicate order, and a suspicious quantity of 40.

## Common mistakes

- **Trusting `head()` alone.** Use `sample()` too, especially on sorted files.
- **Ignoring `info()` dtypes.** A numeric column stored as `object` silently disappears from `describe()` and `corr()`.
- **Believing `isnull()` found everything.** Placeholders like `?` and `-999` are not `NaN`.
- **Reading `mean` without `median`.** Skewed columns like `Fare` mislead on the mean.
- **Dropping duplicates blindly.** Check whether they are true duplicates or legitimate repeats (two customers who bought the same item at the same price).
- **Over-reading correlation.** It is a clue, not a conclusion. Check with group statistics and plots.
- **Modifying the original.** Work on `df.copy()` when experimenting so you can always return to the raw data.
- **Forgetting `numeric_only=True`.** `corr()` errors on text columns in pandas 2.x.

## Checklist to copy into any project

- [ ] Shape checked, memory acceptable
- [ ] `sample()` reviewed; formats and placeholders noted
- [ ] Dtypes correct (numbers, dates, categories)
- [ ] Missing values counted (and hidden placeholders replaced)
- [ ] `describe()` reviewed for impossible values and outliers
- [ ] Duplicates counted and a strategy chosen
- [ ] Correlation with the target reviewed; useless columns (IDs) flagged
- [ ] Findings written down before any cleaning starts

## Key takeaways

- Ask the same 7 questions of every new dataset: **size, look, types, missing, statistics, duplicates, correlation**.
