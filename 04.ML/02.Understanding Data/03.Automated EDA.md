# 1. What automated EDA is

In [[05.Asking Basic Questions to a Dataset]], [[06.Univariate Analysis]] and [[07.Bivariate and Multivariate Analysis]] you did EDA by hand: `shape`, `info`, `describe`, histograms, box plots, correlation matrices, crosstabs. That is the right way to **learn**, but for each new dataset the routine is repetitive.

**Automated EDA tools generate that whole first pass from one line of code.** `ydata-profiling` is like `df.describe()` taken much further: it analyses every column and produces an interactive HTML report.

```python
ProfileReport(df).to_file("report.html")
```

### What you get

|Area|Contents|
|---|---|
|**Overview**|rows, columns, missing cells, duplicate rows, memory, variable types|
|**Alerts**|automatic warnings: missing, skewed, zeros, high cardinality, constant, correlated...|
|**Variables**|per-column statistics, histogram, common values, extreme values|
|**Interactions**|scatter plots for pairs of numeric columns|
|**Correlations**|heatmaps (Pearson, Spearman, Kendall, Phi-K, Cramér's V)|
|**Missing values**|counts, matrix, heatmap, dendrogram|
|**Sample**|first and last rows|
|**Duplicate rows**|the repeated records|

### Where it fits in the workflow

```
Load data -> [ automated profile ] -> read alerts -> targeted manual EDA -> clean -> engineer features -> model
                 (minutes)                            (hours)
```

Use it to **start** EDA faster and to make sure you did not miss something obvious. It does not replace judgement: it can tell you _what_ is odd, not _why_, nor what to do about it.

### How the report relates to your manual steps

|Report section|Equivalent manual work|Note|
|---|---|---|
|Overview|`df.shape`, `df.info()`, `df.duplicated().sum()`|[[05.Asking Basic Questions to a Dataset]]|
|Variables|`describe()`, `value_counts()`, histograms, box plots|[[06.Univariate Analysis]]|
|Interactions|scatter plots, `pairplot`|[[07.Bivariate and Multivariate Analysis]]|
|Correlations|`df.corr()`, heatmaps, Cramér's V|[[07.Bivariate and Multivariate Analysis]]|
|Missing values|`df.isnull().sum()`, missing heatmap|[[05.Asking Basic Questions to a Dataset]]|
|Alerts|the checklist in your head|all of the above|

# 2. Installation and quick start

## Install

```bash
pip install -U ydata-profiling

# Optional extras
pip install -U "ydata-profiling[notebook]"        # Jupyter widgets support
conda install -c conda-forge ydata-profiling       # conda alternative (pip is often more reliable inside conda)
```

Remove the old package first if it is installed:

```bash
pip uninstall pandas-profiling
```

Use a virtual environment; profiling pulls in many dependencies (pandas, numpy, scipy, matplotlib, seaborn, pydantic and others), and version conflicts are the most common installation problem. If an import fails after installing, check that your pandas/numpy versions are supported by the release you installed.

## Quick start

```python
import pandas as pd
from ydata_profiling import ProfileReport

df = pd.read_csv("train.csv")                       # Titanic

profile = ProfileReport(df, title="Titanic Profiling Report")
profile.to_file("titanic_report.html")              # open this file in a browser
```

Inside **Jupyter**:

```python
profile.to_notebook_iframe()      # embed the report in the notebook (most reliable)
profile.to_widgets()              # interactive widgets (needs the notebook extra)
profile                           # in many setups a bare ProfileReport object renders itself
```

Typical run time: a few seconds for Titanic (891 rows); minutes for hundreds of thousands of rows with all features on. See section 9 for speed tips.

# 3. The report, section by section

## 3.1 Overview

Three tabs: **Overview**, **Alerts**, **Reproduction**.

**Dataset statistics (Titanic):**

|Item|Typical value|
|---|---|
|Number of variables|12|
|Number of observations|891|
|Missing cells|866 (about 8.1%)|
|Duplicate rows|0|
|Total size in memory|about 84 KB|
|Variable types|Numeric 5-7, Categorical 4-5, text and others|

> The variable types are _inferred_ by the tool and may disagree with yours. For example `Pclass` and `Survived` may be flagged numeric even though they are categorical. You can override this (section 5.4).

**Reproduction tab:** the analysis start and end time, the package version, and the configuration, which helps you reproduce a report later.

## 3.2 Variables (the heart of the report)

One panel per column. Each shows a **header** (name, type, alerts), **summary statistics**, and a mini histogram or bar chart, with a **"More details"** toggle for the following tabs.

### For a numerical column (e.g. `Age`)

|Tab|Content|You already know it from|
|---|---|---|
|**Statistics: Quantile**|min, 5th percentile, Q1, median, Q3, 95th percentile, max, range, IQR|box plot, `describe()`|
|**Statistics: Descriptive**|mean, standard deviation, coefficient of variation, kurtosis, MAD, skewness, sum, variance|[[06.Univariate Analysis]] section A5|
|**Histogram**|distribution with adjustable bins|`sns.histplot`|
|**Common values**|most frequent values and shares|`value_counts()`|
|**Extreme values**|minimum 5 and maximum 5 values|`nsmallest`, `nlargest`|

Headline figures at the top: distinct count, distinct %, missing count and %, infinite count, mean, min, max, zeros count and %, memory size.

### For a categorical column (e.g. `Sex`, `Embarked`)

|Tab|Content|
|---|---|
|**Overview**|length statistics, unique values, sample|
|**Categories**|bar chart of frequencies (like `countplot`), with an "other values" bucket|
|**Words / Characters / Scripts**|text-level statistics: most common words, character blocks and categories|

### For text, date, boolean, URL, path, image, and file columns

Specialised summaries exist for each type, such as date ranges and string length distributions.

### Practical reading tip

Scan every variable header for **alert badges** (red/orange tags: "Missing", "Skewed", "Zeros", "High cardinality", "Unique"). They tell you where to look first.

## 3.3 Interactions

Pick any two numeric variables from drop-downs to see a **scatter plot**. This is a point-and-click `sns.scatterplot` for every numeric pair, without writing a loop. Good for spotting linear trends, clusters, or odd patterns. With many columns it is expensive, so it is often switched off (section 5).

## 3.4 Correlations

Heatmaps for several methods, plus a table view.

|Method|Variable types|Captures|
|---|---|---|
|**Pearson**|numeric|linear association|
|**Spearman**|numeric / ordinal|monotonic association|
|**Kendall**|numeric / ordinal|rank agreement|
|**Phi-K (phik)**|**mixed** numeric and categorical|any association, including non-linear|
|**Cramér's V**|categorical|association strength (0 to 1)|

Phi-K is especially helpful because it puts numeric and categorical columns in **one** matrix, something a plain `df.corr()` cannot do. Correlations above a threshold (0.9 by default) generate "highly overall correlated" alerts.

## 3.5 Missing values

Four visualisations:

|Plot|Shows|
|---|---|
|**Count**|missing cells per column (bar chart)|
|**Matrix**|each row as a line, white where missing; reveals patterns by row position|
|**Heatmap**|**nullity correlation**: do two columns tend to be missing together?|
|**Dendrogram**|clusters of columns with similar missingness|

On Titanic you see `Cabin` almost empty, `Age` about 20% missing, `Embarked` with 2 gaps. Use the heatmap to ask: "are the same rows missing both A and B?", a hint of how the data was collected (MAR/MNAR; see [[06.Univariate Analysis]] E2).

## 3.6 Sample

First and last rows of the data (default 10 each). Equivalent to `head()` and `tail()`. Remember from [[05.Asking Basic Questions to a Dataset]] that **random** rows are more informative; check `df.sample()` yourself if the file is sorted.

## 3.7 Duplicate rows

Lists exact duplicate records and how many times they occur. Titanic has none; real files often do.

# 4. Alerts: what they mean and what to do

Alerts are automatic data quality warnings. They are **hypotheses to check**, not verdicts.

|Alert|Triggered when|Example (Titanic)|What to do|
|---|---|---|---|
|**Missing**|a column has missing values|`Age` (19.9%), `Cabin` (77.1%), `Embarked` (0.2%)|impute, drop, or add a "missing" indicator; see [[05.Asking Basic Questions to a Dataset]] Q4|
|**Zeros**|many values are exactly 0|`SibSp`, `Parch`, `Fare` (15 zero fares)|decide whether 0 is real, a placeholder, or missing|
|**Skewed**|high absolute skewness|`Fare` (about 4.8), `SibSp`, `Parch`|`log1p` / Yeo-Johnson; see [[06.Univariate Analysis]] D3|
|**High cardinality**|too many distinct categories|`Name`, `Ticket`, `Cabin`|extract features or drop|
|**Unique**|every value is different|`PassengerId`|identifier; exclude from modelling|
|**Constant**|one value in the entire column|(not on Titanic)|drop the column|
|**Constant length**|all strings have equal length|e.g. fixed-format codes|usually harmless; may reveal an ID|
|**Imbalance**|one category dominates (default threshold 0.5)|a rare class in a target|resampling, class weights, stratification|
|**High correlation**|two columns are strongly correlated|`Pclass` and `Fare`|drop or combine; multicollinearity|
|**Duplicates**|repeated rows|(none)|decide whether to drop|
|**Infinite**|values of inf or -inf|(none)|replace with `NaN` or fix the cause|
|**Uniform**|values are uniformly distributed|random-looking IDs or numbers|check if it carries information|
|**Unsupported**|type not understood|mixed or complex types|clean or convert|
|**Date / Sequence / Non-stationary**|time-based checks|time series|see section 9|

### Using alerts wisely

- **Severity differs:** a constant column is an easy decision; "high correlation" needs context.
- **Thresholds are tunable:** the default skew threshold, missing limits and others can be changed in the config.
- **Absence of an alert is not a clean bill of health.** Business rules (an age over 120, an order before the customer existed) are invisible to a generic tool.
- Each alert should lead to an **action**: fix, drop, transform, or accept with a note.

# 5. Configuration

## 5.1 Three modes

```python
# 1) Default: full report
ProfileReport(df, title="Full")

# 2) Minimal: fast, skips expensive parts (interactions, correlations, duplicates and more)
ProfileReport(df, title="Minimal", minimal=True)

# 3) Explorative: switches on extra analyses (text, unicode, rich correlations)
ProfileReport(df, title="Explorative", explorative=True)
```

|Mode|Speed|Detail|When|
|---|---|---|---|
|`minimal=True`|fastest|basic per-column stats and alerts|wide or large datasets, quick checks|
|default|medium|balanced|most work|
|`explorative=True`|slowest|richest|smaller datasets and deep dives|

## 5.2 Common options

```python
profile = ProfileReport(
    df,
    title="Titanic profile",
    dark_mode=True,                       # theme (also orange_mode=True)
    progress_bar=False,                   # cleaner notebooks
    pool_size=0,                          # worker processes (0 = use all CPUs); set 1 to debug
    samples={"head": 5, "tail": 5},       # sample rows shown
    correlations={
        "pearson":  {"calculate": True},
        "spearman": {"calculate": True},
        "kendall":  {"calculate": False},   # slow on big data
        "phi_k":    {"calculate": True},
        "cramers":  {"calculate": True},
    },
    missing_diagrams={"heatmap": False, "dendrogram": False},      # drop the slow ones
    duplicates={"head": 10},
    interactions={"targets": ["Survived"]},   # only scatter plots against the target
    vars={"num": {"low_categorical_threshold": 5}},   # numeric columns with <= 5 distinct values are treated as categorical
)
```

> Option names and defaults evolve between releases. If a setting is rejected, check the documentation for your installed version (`pip show ydata-profiling`).

## 5.3 Turn off what you do not need

```python
# Fast "overview only" report for a wide table
quick = ProfileReport(df, minimal=True, progress_bar=False)

# Everything except the costly interactions
no_inter = ProfileReport(df, interactions=None)
```

## 5.4 Overriding inferred types

The tool guesses types. Fix wrong guesses so statistics and plots make sense.

```python
profile = ProfileReport(
    df,
    type_schema={
        "Pclass":   "categorical",
        "Survived": "categorical",
        "Age":      "numeric",
    },
)
```

Alternatively, convert in pandas first (often the cleanest option):

```python
df["Pclass"] = df["Pclass"].astype("category")
df["Survived"] = df["Survived"].astype("category")
```

## 5.5 Document the dataset inside the report

```python
profile = ProfileReport(
    df,
    title="Titanic",
    dataset={
        "description": "Passenger records from the RMS Titanic (Kaggle training file).",
        "author": "Data team",
        "url": "https://www.kaggle.com/c/titanic",
    },
    variables={
        "descriptions": {
            "Pclass": "Ticket class: 1 = upper, 2 = middle, 3 = lower",
            "SibSp": "Siblings or spouses aboard",
            "Parch": "Parents or children aboard",
            "Embarked": "Port: C = Cherbourg, Q = Queenstown, S = Southampton",

```

The descriptions appear next to each variable, turning the report into shareable documentation.

## 5.6 Settings from a file

```python

```

Keep one config per project so reports are reproducible and consistent across teammates.

# 7. Working programmatically

## 7.1 Read the results as data

```python
import json

report = json.loads(profile.to_json())
print(report.keys())                  # table, variables, correlations, missing, alerts, ...

print(report["table"]["n"], "rows,", report["table"]["n_var"], "variables")
print("missing cells %:", round(report["table"]["p_cells_missing"] * 100, 1))

for alert in report["alerts"]:
    print(" -", alert)                # e.g. "Age has 177 (19.9%) missing values"

age = report["variables"]["Age"]
print(age["mean"], age["skewness"], age["p_missing"])
```

The exact keys can differ slightly between versions; print the dictionary's keys first. This opens the door to **automation**: act on alerts in code.

## 7.2 A data quality gate (CI-style check)

Fail a pipeline when the data is unacceptable.

```python
def quality_gate(df, max_missing=0.4, max_dup=0.01):
    problems = []
    miss = df.isna().mean()
    for col in miss[miss > max_missing].index:
        problems.append(f"{col}: {miss[col]:.0%} missing")
    dup = df.duplicated().mean()
    if dup > max_dup:
        problems.append(f"{dup:.1%} duplicate rows")
    for col in df.columns:
        if df[col].nunique(dropna=True) <= 1:
            problems.append(f"{col}: constant column")
    return problems

issues = quality_gate(df)
if issues:
    print("Data quality problems:\n -", "\n - ".join(issues))
    ProfileReport(df, minimal=True).to_file("failed_report.html")      # attach the evidence
    # raise ValueError("Data quality gate failed")
```

Run it on every new data delivery. Keep the generated HTML next to the run so you can see what changed.

## 7.3 Turn alerts into a cleaning to-do list

```python
todo = {
    "drop":      [c for c in df.columns if df[c].nunique() <= 1 or df[c].nunique() == len(df)],
    "impute":    df.columns[df.isna().mean().between(0.001, 0.4)].tolist(),
    "heavy_na":  df.columns[df.isna().mean() > 0.4].tolist(),
    "skewed":    df.select_dtypes("number").columns[df.select_dtypes("number").skew().abs() > 1].tolist(),
}
todo
```

For Titanic this yields: drop `PassengerId` (unique) and `Name` (unique); impute `Age` and `Embarked`; treat `Cabin` as heavily missing; transform `Fare`, `SibSp`, `Parch`.

# 8. Comparing datasets

## 8.1 Compare two reports

```python
from ydata_profiling import ProfileReport, compare

train_report = ProfileReport(train_df, title="Train")
test_report  = ProfileReport(test_df,  title="Test")

comparison = compare([train_report, test_report])
comparison.to_file("train_vs_test.html")
```

The comparison report shows each statistic side by side, so a difference in distribution jumps out. Another shortcut is `train_report.compare(test_report)`.

### Typical comparisons

|Compare|Why|
|---|---|
|**Train vs test**|catch distribution shift (different ranges, new categories) before it hurts a model|
|**Before vs after cleaning**|prove the cleaning did what you intended|
|**This month vs last month**|detect data drift in production|
|**Raw vs a sample**|check that a sample represents the full data|

Columns must be compatible; the reports are matched by column name.

## 8.2 Splitting by a condition

```python
ProfileReport(df[df["Sex"] == "female"], title="Female").to_file("f.html")
ProfileReport(df[df["Sex"] == "male"],   title="Male").to_file("m.html")
compare([ProfileReport(df[df["Sex"] == "female"], title="Female"),
         ProfileReport(df[df["Sex"] == "male"],   title="Male")]).to_file("f_vs_m.html")
```

A quick way to scan for group differences across every column at once.

# 9. Time series and large datasets

## 9.1 Time-series mode

```python
ts = ProfileReport(
    df_time,
    title="Sensor data",
    tsmode=True,                 # enable time-series analysis
    sortby="timestamp",          # the time column
)
ts.to_file("ts_report.html")
```

Adds time-series-specific alerts and plots such as seasonality, stationarity, and autocorrelation views.

## 9.2 Speed and memory for big data

|Problem|Remedy|
|---|---|
|Report takes too long|`minimal=True`; switch off correlations (`kendall`, `phi_k`), interactions, missing heatmap and dendrogram|
|Too many columns|profile in column subsets, or only the most important columns|
|Too many rows|profile a **random sample** (`df.sample(100_000, random_state=0)`)|
|Out of memory|read only needed columns and dtypes (`usecols`, `dtype`; see [[01.Working with CSV Files]]), or use chunks and profile the pieces|
|Huge HTML file|disable heavy plots; reduce `samples`|
|Slow in a notebook|`progress_bar=False`; run as a script|
|Data in a cluster|use the Spark DataFrame support (profiling a Spark DataFrame directly)|

```python
sample = df.sample(n=min(len(df), 100_000), random_state=0)
ProfileReport(sample, minimal=True, title="Sampled profile").to_file("sample_profile.html")
```

A sample is fine for shapes and alerts but will miss rare values, so state clearly that you profiled a sample.

# 10. Worked example: reading the Titanic report

```python
import pandas as pd
from ydata_profiling import ProfileReport

df = pd.read_csv("train.csv")
df["Survived"] = df["Survived"].astype("category")        # help the tool: these are categories
df["Pclass"]   = df["Pclass"].astype("category")

profile = ProfileReport(
    df, title="Titanic", explorative=True,
    interactions={"targets": ["Age", "Fare"]},
)
profile.to_file("titanic_report.html")
```

### What a typical reading looks like

|Where|Observation|Interpretation|Action|
|---|---|---|---|
|Overview|891 rows, 12 columns, about 8% missing cells, 0 duplicates|small, mostly complete table|proceed|
|Alerts|`Age` 19.9% missing|moderate, probably related to class|impute by group median|
|Alerts|`Cabin` 77.1% missing, high cardinality (147 values)|mostly empty text|`HasCabin` flag, `Deck` letter|
|Alerts|`Embarked` 2 missing|negligible|fill with the mode (S)|
|Alerts|`PassengerId`, `Name` unique|identifiers|drop `PassengerId`; extract `Title` from `Name`|
|Alerts|`Ticket` high cardinality|shared tickets mean groups|`TicketGroupSize`|
|Alerts|`Fare` skewed, 15 zeros|right-skewed, free tickets?|`log1p`; investigate zeros|
|Alerts|`SibSp`, `Parch` many zeros and skewed|mostly travelling alone|`FamilySize`, `IsAlone`|
|Variables: `Age`|roughly bell-shaped, min 0.42, max 80|plausible range|ok|
|Variables: `Sex`|64.8% male|imbalance in a feature (not an error)|note|
|Correlations|`Pclass` vs `Fare` strongly related|class and price overlap|consider keeping one or log-fare + class|
|Correlations (Phi-K)|`Survived` strongest with `Sex`, then `Pclass`, `Fare`|matches your manual finding|prioritise these|
|Missing heatmap|`Age` and `Cabin` gaps partly co-occur (lower classes)|missingness is informative|add indicator columns|

Compare with your manual results: survival 61.6%/38.4%, 3rd class 55%, `Fare` skew 4.8. The report should reproduce them. If it does not, you have found a bug somewhere (in your code or in how the tool inferred types).

### After the report: targeted manual EDA

The report tells you **where to dig**. Follow up with the focused plots you learned earlier:

```python
import seaborn as sns
sns.kdeplot(data=df, x="Age", hue="Survived", common_norm=False, fill=True)       # report cannot split by target this way
df.pivot_table(values="Survived", index="Sex", columns="Pclass", aggfunc=lambda s: (s == 1).mean())   # interaction
```

Automated tools are weaker at **group comparisons against a target and multi-way interactions**. That is where manual bivariate and multivariate analysis ([[07.Bivariate and Multivariate Analysis]]) adds value.

# 11. Alternatives

|Tool|Strength|Quick use|
|---|---|---|
|**ydata-profiling**|most complete single-dataset report; alerts; JSON output|`ProfileReport(df).to_file("r.html")`|

|**D-Tale**|interactive, spreadsheet-like exploration in the browser|`import dtale; dtale.show(df)`|

### Sweetviz example (target-aware)

```python
# pip install sweetviz
import sweetviz as sv

report = sv.analyze(df, target_feat="Survived")       # every feature vs the target
report.show_html("sweetviz_report.html")

compare = sv.compare([train_df, "Train"], [test_df, "Test"])
compare.show_html("sweetviz_compare.html")
```

Sweetviz shows how the target varies with every feature on the same page, which `ydata-profiling` does not emphasise.

### Choosing

|Need|Pick|
|---|---|
|Thorough first-look report with alerts|ydata-profiling|
|Target-centred view, train vs test|Sweetviz|
|Poking at data interactively|D-Tale|
|Quick terminal summary|skimpy|
|Maintained dependency footprint and speed on huge data|minimal-mode profiling or your own functions|

Package maintenance, supported Python/pandas versions, and features change over time; check each project's page before committing to one for production.

# 12. Build your own mini-profiler

Understanding what these tools do is easier when you build a small version. This combines the functions from earlier notes.

```python
import numpy as np
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt
from scipy import stats

def mini_profile(df, target=None, cat_max=12, top_n=5):
    """A text-and-plot first pass: overview, alerts, per-column summary, relationship with the target."""
    n, k = df.shape
    print(f"OVERVIEW: {n} rows x {k} columns | {df.memory_usage(deep=True).sum()/1024:.0f} KB | "
          f"missing cells {df.isna().sum().sum() / df.size:.1%} | duplicate rows {df.duplicated().sum()}")

    alerts = []
    for col in df.columns:
        s = df[col]
        miss = s.isna().mean()
        if miss > 0:                 alerts.append(f"{col}: {miss:.1%} missing")
        if s.nunique() <= 1:         alerts.append(f"{col}: constant")
        elif s.nunique() == n:       alerts.append(f"{col}: unique (identifier?)")
        if pd.api.types.is_numeric_dtype(s) and s.nunique() > cat_max:
            sk = s.skew()
            if abs(sk) > 1:          alerts.append(f"{col}: skewed (skew={sk:.2f})")
            if (s == 0).mean() > 0.1: alerts.append(f"{col}: {(s == 0).mean():.0%} zeros")
        elif not pd.api.types.is_numeric_dtype(s) and s.nunique() > 50:
            alerts.append(f"{col}: high cardinality ({s.nunique()} values)")

    num = df.select_dtypes("number")
    if num.shape[1] > 1:
        c = num.corr().abs().where(np.triu(np.ones((num.shape[1],) * 2), 1).astype(bool)).stack()
        for (a, b), v in c[c > 0.8].items():
            alerts.append(f"{a} ~ {b}: high correlation ({v:.2f})")

    print("\nALERTS")
    print("\n".join(f" - {a}" for a in alerts) or " none")

    print("\nNUMERIC SUMMARY")
    print(num.describe().T.assign(skew=num.skew(), missing=num.isna().sum()).round(2).to_string())

    cat = df.select_dtypes(exclude="number")
    print("\nCATEGORICAL SUMMARY (top values)")
    for col in cat.columns:
        vc = cat[col].value_counts(normalize=True).head(top_n).round(3)
        print(f" {col} ({cat[col].nunique()} unique): " + ", ".join(f"{i}={v:.0%}" for i, v in vc.items()))

    if target is not None and target in df:
        print(f"\nRELATIONSHIP WITH TARGET '{target}'")
        y = df[target]
        for col in df.columns.drop(target):
            sub = df[[col, target]].dropna()
            if sub[col].nunique() < 2 or len(sub) < 20:
                continue
            if pd.api.types.is_numeric_dtype(sub[col]) and sub[col].nunique() > cat_max:
                if sub[target].nunique() <= 2:
                    groups = [g[col].values for _, g in sub.groupby(target)]
                    print(f" {col:12s} Kruskal p = {stats.kruskal(*groups).pvalue:.2e}")
                else:
                    print(f" {col:12s} Spearman = {stats.spearmanr(sub[col], sub[target]).correlation:.2f}")
            else:
                ct = pd.crosstab(sub[col], sub[target])
                chi2, p, *_ = stats.chi2_contingency(ct)
                v = np.sqrt(chi2 / (ct.values.sum() * (min(ct.shape) - 1)))
                print(f" {col:12s} chi2 p = {p:.2e}, Cramer's V = {v:.2f}")

mini_profile(df.drop(columns=["PassengerId"]), target="Survived")
```

# 13. Limitations, pitfalls, privacy

## Limitations

|Limitation|Consequence|
|---|---|
|**No business context**|will not know an age of 150 is impossible or that `-1` means "unknown"|
|**Generic thresholds**|alerts can be noisy or miss domain-specific issues|
|**Weak on target-centred analysis**|does not show how each feature relates to the target as clearly as manual bivariate plots (Sweetviz does better)|
|**Weak on interactions among 3+ variables**|no facets, no pivot heatmaps|
|**Type inference mistakes**|numeric codes treated as numbers, dates read as text|
|**Heavy on big data**|long runs, large HTML files, memory use|
|**Version sensitivity**|breaking changes between releases; dependency conflicts|
|**A report is not an analysis**|someone still has to interpret it and write conclusions|

## Pitfalls

- **Profiling raw data once and never again.** Re-profile after cleaning to confirm fixes.
- **Reading the alerts as instructions.** Drop a "high correlation" column only after thinking.
- **Profiling the full dataset including the test set.** Decisions made from test-set statistics leak information. Profile **training data** for decisions; use comparison reports to check the test set.
- **Ignoring type inference.** A wrong type yields misleading histograms.
- **Profiling a sample and presenting it as the whole.**
- **Treating the correlations tab as causation.**
- **Not saving the configuration** (so nobody can reproduce the report).

## Privacy and security

A report is a **data export**. It can contain sample rows, the most frequent values, extreme values, and category lists.

- Do not share reports built on personal or confidential data without approval.
- Check the options for hiding samples and value counts (a "sensitive" setting exists in recent versions; check your version) or drop columns before profiling:

```python
safe = df.drop(columns=["Name", "Ticket"])            # remove identifying text
ProfileReport(safe, samples=None, title="Shareable profile").to_file("shareable.html")
```

- Store HTML files with the same access controls as the dataset.

## Key takeaways

- `pandas-profiling` is now **`ydata-profiling`**; use `from ydata_profiling import ProfileReport`.
- One line produces a full report: overview, alerts, per-variable statistics, interactions, correlations, missing values, samples, and duplicates.
- **Alerts** (missing, zeros, skewed, high cardinality, unique, constant, imbalance, high correlation) are prompts for you to investigate, then act.
- Tune with `minimal=True`, `explorative=True`, `type_schema`, and the correlation, interaction and missing-diagram options; document the dataset inside the report.
- Export to HTML to share and JSON to automate quality gates; use `compare` for train vs test, before vs after cleaning, or period vs period.
- Automated EDA gives speed and coverage, while manual EDA gives depth and understanding. Use the tool for the first pass, then investigate the flagged problems and the target relationships yourself.
- Treat reports as data exports: mind privacy, profile training data for decisions, and always re-check the key findings by hand.
