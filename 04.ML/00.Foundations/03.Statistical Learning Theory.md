You've trained a model. It performs well on training data. But will it perform well on data it has never seen?

This note answers that question **mathematically**. Not with intuition alone — with proofs. By the end, you will understand:
- How much data is "enough"
- What makes a model class "too complex"
- Why the training error and test error differ, and by how much
- Why regularisation and simplicity are not just good habits — they are mathematically provable necessitie
## What Are We Even Trying to Do?
### The Data-Generating Distribution
Assume all your data — training set and future test data — is drawn from a single fixed distribution $P_{XY}$ over inputs $\mathcal{X}$ and labels $\mathcal{Y}$.

Every example $(x_i, y_i)$ is drawn **i.i.d.**:
- **Identically distributed** — every example comes from the same $P_{XY}$
- **Independently** — knowing example $i$ tells you nothing about example $i+1$
This is a strong assumption. In real life, it is violated constantly:
- Time-series data has temporal correlations
- Hospital data has selection bias
- User behaviour data shifts over months
But knowing the assumption exists lets you reason about _when_ it matters and when the theory still approximately holds.

### The Loss Function
A **loss function** $\ell(\hat{y}, y)$ tells you: how bad is it to predict $\hat{y}$ when the true answer is $y$?

It always returns a non-negative number. Zero means perfect prediction.

| Loss          | Formula                                               | Used When                 |
| ------------- | ----------------------------------------------------- | ------------------------- |
| Squared loss  | $(\hat{y} - y)^2$                                     | Regression                |
| Absolute loss | $                                                     | \hat{y} - y               |
| 0-1 loss      | $\mathbf{1}[\hat{y} \neq y]$ (1 if wrong, 0 if right) | Classification            |
| Log loss      | $-y \log \hat{p} - (1-y)\log(1-\hat{p})$              | Probabilistic classifiers |
| Hinge loss    | $\max(0, 1 - y\hat{y})$                               | Support Vector Machines   |

The loss function is a **design choice**. It encodes what you care about. Squared loss punishes large errors heavily. Absolute loss treats all errors more equally. Your choice of loss shapes the entire learning problem.

##  Risk: The Central Object

### Population Risk (What We Actually Want)
The **population risk** (also called true risk or expected risk) of a hypothesis $h$ is:
$$R(h) = \mathbb{E}_{(x,y) \sim P_{XY}}\left[\ell(h(x), y)\right]$$
- if you picked a random example from the entire data-generating distribution and measured the loss, what would the average loss be?

This is the number we actually want to minimise. A model with low $R(h)$ will do well on real, unseen data.

**The problem:** $P_{XY}$ is unknown. We can never compute $R(h)$ directly. We only have a finite training set.

### The Bayes-Optimal Predictor

The best any model could ever do is:

$$h^* = \underset{h}{\arg\min} \ R(h)$$

For squared loss, this turns out to be $h^*(x) = \mathbb{E}[y \mid x]$ — just predict the average label given input $x$.

The **Bayes risk** $R(h^*)$ is the irreducible floor — the minimum error any model can achieve. It comes from genuine noise in the data itself. No amount of data or model complexity can get below it.

### Empirical Risk (What We Can Actually Measure)

Since we can't compute $R(h)$, we approximate it using our training set $\mathcal{D} = {(x_i, y_i)}_{i=1}^n$:

$$\hat{R}(h) = \frac{1}{n} \sum_{i=1}^n \ell(h(x_i), y_i)$$

This is just the average training loss — the number your training loop prints.

| |Symbol|What it is|Can we compute it?|
|---|---|---|---|
|True risk|$R(h)$|Average loss over all possible data|❌ No ($P_{XY}$ unknown)|
|Empirical risk|$\hat{R}(h)$|Average loss over training data|✅ Yes|

The gap between these two is the central problem of machine learning theory.

## 3. Empirical Risk Minimisation (ERM)

**ERM** is the simplest reasonable learning principle: just pick the hypothesis in your class $\mathcal{H}$ that minimises training loss.

$$\hat{h} = \underset{h \in \mathcal{H}}{\arg\min} \ \hat{R}(h)$$

Almost every supervised learning algorithm is ERM in disguise:

- **Linear regression** → ERM with squared loss, linear functions
- **Logistic regression** → ERM with log loss, sigmoid-linear functions
- **SVM** → regularised ERM with hinge loss
- **Decision tree** → approximate ERM with 0-1 loss (exact minimisation is NP-hard, so it uses greedy splits)

### When ERM Goes Wrong: Overfitting

ERM has one critical failure mode. If your hypothesis class $\mathcal{H}$ is very rich (e.g., a degree-1000 polynomial, or a huge neural network), ERM can find a hypothesis that memorises the training data perfectly — zero training error — while failing completely on test data.

This is overfitting. The model learned the noise in the training set, not the underlying signal.

The theory below tells us _precisely_ when ERM is safe.

## 4. The Generalisation Gap

Define the **generalisation gap** as:

$$\text{gen gap} = R(\hat{h}) - \hat{R}(\hat{h})$$

This is: how much worse does my model do on real data compared to training data?

It is almost always positive — training error is optimistically biased because we chose $\hat{h}$ specifically to minimise it on the training data.

**Two things control the generalisation gap:**

1. **Complexity of $\mathcal{H}$** — richer classes can overfit more, creating bigger gaps
2. **Number of training examples $n$** — more data shrinks the gap

The rest of this note formalises these two points.

## 5. PAC Learning: When Is Learning Guaranteed to Work?

**PAC = Probably Approximately Correct** (Valiant, 1984)

PAC learning asks: can we _prove_, before seeing test data, that our learned model will generalise?

### 5.1 The PAC Definition

A hypothesis class $\mathcal{H}$ is **PAC-learnable** if there exists a learning algorithm $\mathcal{A}$ such that: for any desired accuracy $\epsilon > 0$ and any desired confidence $1 - \delta$, when given enough training examples, $\mathcal{A}$ outputs $\hat{h}$ satisfying:

$$P!\left(R(\hat{h}) - R(h^*) \leq \epsilon\right) \geq 1 - \delta$$

Breaking this down word by word:

- **Probably** ($1 - \delta$): with high probability over the random draw of your training set…
- **Approximately** ($\epsilon$): you get a model whose true risk is within $\epsilon$ of the best possible…
- **Correct** ($R(h^*)$): measured against the best hypothesis in the class

So PAC says: with enough data, you can probably get approximately the best possible model. It's a guarantee.

### Sample Complexity: How Much Data Is Enough?
The **sample complexity** $n_{\mathcal{H}}(\epsilon, \delta)$ is the minimum number of training examples needed for PAC learning.

For a **finite hypothesis class** $|\mathcal{H}| < \infty$, with probability at least $1 - \delta$, for _all_ $h \in \mathcal{H}$ simultaneously:

$$R(h) \leq \hat{R}(h) + \sqrt{\frac{\log|\mathcal{H}| + \log(1/\delta)}{2n}}$$

Read this as: **true error ≤ training error + complexity penalty**.

The complexity penalty depends on:

- $|\mathcal{H}|$: more hypotheses → bigger penalty (richer classes need more data)
- $n$: more data → smaller penalty (shrinks at rate $O(1/\sqrt{n})$)
- $\delta$: higher confidence required → very slightly bigger penalty (only logarithmic)

This gives sample complexity:

$$n_{\mathcal{H}}(\epsilon, \delta) = O!\left(\frac{\log|\mathcal{H}| + \log(1/\delta)}{\epsilon^2}\right)$$

**Key insight:** $\log|\mathcal{H}|$ appears, not $|\mathcal{H}|$. So even if $\mathcal{H}$ has a billion hypotheses, you only need $\log(\text{billion}) \approx 30$ extra training examples to account for that complexity. The logarithm saves us.

### Proof

The proof uses two tools you need to know:

**Tool 1: Hoeffding's Inequality** If you average $n$ independent bounded random variables, the average is unlikely to deviate much from the true mean:

$$P!\left(\bar{Z} - \mu \geq t\right) \leq \exp!\left(-2nt^2\right)$$

Applied here: for a single hypothesis $h$, each training loss $\ell(h(x_i), y_i)$ is a random variable with mean $R(h)$. Hoeffding tells us:

$$P!\left(R(h) - \hat{R}(h) \geq \epsilon\right) \leq e^{-2n\epsilon^2}$$

**Tool 2: Union Bound** The probability that _at least one_ of $k$ bad events happens is at most the sum of their individual probabilities.

For all $|\mathcal{H}|$ hypotheses:

$$P!\left(\exists h \in \mathcal{H}: R(h) - \hat{R}(h) \geq \epsilon\right) \leq |\mathcal{H}| \cdot e^{-2n\epsilon^2}$$

Set this equal to $\delta$, solve for $\epsilon$, and you get the bound in Section 5.2. $\square$

### The Problem: Infinite Hypothesis Classes

The bound above requires $|\mathcal{H}| < \infty$. But linear classifiers in $\mathbb{R}^d$? There are infinitely many. Neural networks? Infinitely many parameter settings.

We need a different way to measure complexity for infinite classes. Enter VC dimension.

## 6. VC Dimension: Measuring Complexity Without Counting

The **Vapnik-Chervonenkis (VC) dimension** (1971) gives us a way to measure the complexity of an infinite hypothesis class. Instead of counting hypotheses, it measures: **how many points can the class classify in all possible ways?**

### 6.1 Shattering: The Core Concept

A hypothesis class $\mathcal{H}$ **shatters** a set of points ${x_1, \ldots, x_m}$ if, for every possible binary labelling of those points, some $h \in \mathcal{H}$ achieves it.

In plain English: $\mathcal{H}$ shatters $m$ points if it can produce all $2^m$ possible label patterns on those points.

**Example:** Can a line in 2D shatter 3 points?

Place 3 non-collinear points. There are $2^3 = 8$ possible label patterns (which ones are "+" and which are "−"). A line can separate any 7 of them... but not the XOR pattern (alternating labels around a triangle). So a line cannot shatter any 4 points (there's always a labelling it can't achieve), but it can shatter 3.

### 6.2 VC Dimension Defined

$$\text{VC-dim}(\mathcal{H}) = \max{m : \exists {x_1,\ldots,x_m} \text{ that } \mathcal{H} \text{ can shatter}}$$

The VC dimension is the size of the **largest set that $\mathcal{H}$ can shatter**.

### 6.3 VC Dimension Examples

**Linear classifiers (hyperplanes) in $\mathbb{R}^d$:** $$\text{VC-dim} = d + 1$$

Why? In $\mathbb{R}^2$, a line has 2 parameters + 1 bias = 3 degrees of freedom, and can shatter any 3 non-collinear points. In $\mathbb{R}^d$, a hyperplane has $d$ weights + 1 bias, and can shatter any $d+1$ points in general position.

**Useful rule of thumb:** For linear models, VC dimension ≈ number of parameters. (This is a rough guide, not a theorem.)

**Intervals on $\mathbb{R}$** (classify $x$ as "+" iff $x \in [a, b]$): $$\text{VC-dim} = 2$$

Two points can be shattered: you can choose intervals to get any of the 4 patterns ${+,+}, {+,-}, {-,+}, {-,-}$. But 3 points $x_1 < x_2 < x_3$ cannot be shattered — the pattern ${+, -, +}$ requires two separate intervals, which a single interval $[a,b]$ cannot achieve.

**Convex polygons in $\mathbb{R}^2$:** $$\text{VC-dim} = \infty$$

For any $n$ points placed on a circle, a convex polygon can separate any subset from the rest (take the convex hull of the "+" points). Since this works for any $n$, VC dimension is infinite. This class can overfit arbitrarily.

### 6.4 The Fundamental Theorem of Statistical Learning

This is one of the most important theorems in all of ML theory.

For binary classification with 0-1 loss, **all three of these are equivalent:**

1. $\mathcal{H}$ is PAC-learnable (learning provably generalises)
2. $\text{VC-dim}(\mathcal{H}) < \infty$ (finite VC dimension)
3. $\mathcal{H}$ has the uniform convergence property (empirical risk converges to true risk uniformly)

This means VC dimension **completely characterises** whether a hypothesis class can be learned. A class with infinite VC dimension cannot be PAC-learned. Period.

### 6.5 VC Generalisation Bound

For any $\mathcal{H}$ with $\text{VC-dim}(\mathcal{H}) = d < \infty$, with probability at least $1 - \delta$:

$$R(\hat{h}) \leq \hat{R}(\hat{h}) + O!\left(\sqrt{\frac{d \log(n/d) + \log(1/\delta)}{n}}\right)$$

And the sample complexity becomes:

$$n_{\mathcal{H}}(\epsilon, \delta) = O!\left(\frac{d \log(d/\epsilon) + \log(1/\delta)}{\epsilon^2}\right)$$

Key takeaways:

- Still converges at rate $O(1/\sqrt{n})$ in samples
- Now the complexity penalty scales with $d = \text{VC-dim}(\mathcal{H})$ instead of $\log|\mathcal{H}|$
- For linear classifiers in $\mathbb{R}^d$: you need roughly $O(d/\epsilon^2)$ samples — linear in the number of features

## 7. The Bias-Variance Decomposition

The VC bound tells us _when_ learning is possible. The bias-variance decomposition tells us _what kind_ of error we're making.

Think of it this way: you can make two types of mistakes.

- **Systematic mistakes** — your model is fundamentally too simple to capture the truth, even with infinite data
- **Random mistakes** — your model is too sensitive to the particular training set you happened to get

These two error types are called **bias** and **variance**.

### 7.1 Setup

Fix a point $x$ in your input space. Imagine drawing many different training sets of size $n$ from $P_{XY}$, training a fresh model $\hat{h}_\mathcal{D}$ on each one, and measuring its prediction $\hat{h}_\mathcal{D}(x)$ at $x$.

Define:

- **Average prediction across training sets:** $\bar{h}(x) = \mathbb{E}_\mathcal{D}[\hat{h}_\mathcal{D}(x)]$
- **True underlying function:** $f^*(x)$
- **Label noise:** $\epsilon \sim (0, \sigma^2)$, so $y = f^*(x) + \epsilon$

### 7.2 The Decomposition Formula

For squared loss:

$$\boxed{\mathbb{E}\left[(\hat{h}(x) - y)^2\right] = \underbrace{(\bar{h}(x) - f^*(x))^2}_{\text{Bias}^2} + \underbrace{\mathbb{E}\left[(\hat{h}(x) - \bar{h}(x))^2\right]}_{\text{Variance}} + \underbrace{\sigma^2}_{\text{Irreducible Noise}}}$$

**Total expected error = Bias² + Variance + Irreducible Noise**

### 7.3 Full Derivation (Step by Step)

Let $\hat{h} = \hat{h}_\mathcal{D}(x)$, $\bar{h} = \bar{h}(x)$, $f = f^*(x)$, and $y = f + \epsilon$.

**Step 1:** Expand the squared error. $$\mathbb{E}[(\hat{h} - y)^2] = \mathbb{E}[(\hat{h} - f - \epsilon)^2]$$

**Step 2:** Expand the square. The cross-term $\mathbb{E}[(\hat{h} - f)\epsilon] = 0$ because $\hat{h}$ depends only on training data, and $\epsilon$ is test-time noise — they are independent. $$= \mathbb{E}[(\hat{h} - f)^2] + \sigma^2$$

**Step 3:** Add and subtract $\bar{h}$ inside the first term: $$\mathbb{E}[(\hat{h} - f)^2] = \mathbb{E}[(\hat{h} - \bar{h} + \bar{h} - f)^2]$$

**Step 4:** Expand the square of the sum $(A + B)^2 = A^2 + 2AB + B^2$ where $A = \hat{h} - \bar{h}$ and $B = \bar{h} - f$: $$= \mathbb{E}[(\hat{h} - \bar{h})^2] + 2\mathbb{E}[\hat{h} - \bar{h}](\bar{h} - f) + (\bar{h} - f)^2$$

**Step 5:** The cross-term vanishes: $\mathbb{E}[\hat{h} - \bar{h}] = \mathbb{E}[\hat{h}] - \bar{h} = 0$ by definition of $\bar{h}$.

**Final result:** $$\mathbb{E}[(\hat{h} - y)^2] = \underbrace{(\bar{h} - f)^2}_{\text{Bias}^2} + \underbrace{\mathbb{E}[(\hat{h} - \bar{h})^2]}_{\text{Variance}} + \underbrace{\sigma^2}_{\text{Irreducible}} \quad \square$$

### 7.4 What Each Term Means in Practice

**Bias²** — Systematic, persistent error. $$\text{Bias}^2 = (\bar{h}(x) - f^*(x))^2$$

Even if you trained on infinite data, the _average_ prediction of your model is still wrong. This is because your hypothesis class $\mathcal{H}$ is too restricted — it can't represent the truth.

_Concrete example:_ Trying to fit a sine wave with a linear model. No matter how much data you give it, the best-fit line cannot capture the curvature. The bias is baked into the model family choice.

**High bias is caused by:** too simple a model, wrong inductive bias (wrong model family), too much regularisation.

---

**Variance** — Sensitivity to the particular training set. $$\text{Variance} = \mathbb{E}_\mathcal{D}[(\hat{h}_\mathcal{D}(x) - \bar{h}(x))^2]$$

Swap out your training set for a different random draw from the same distribution — how much does your prediction change? High variance means the model is very sensitive to which training examples it happened to see.

_Concrete example:_ A depth-50 decision tree trained on 100 examples. Swap 5 training examples and the whole tree changes drastically. The tree memorises noise.

**High variance is caused by:** too complex a model, too little training data, too little regularisation.

---

**Irreducible Noise σ²** — The floor you cannot beat.

This is the variance of the label noise itself. No model, regardless of complexity or data quantity, can get below this. It's genuine randomness in $P_{XY}$ — even the Bayes-optimal predictor pays this cost.

### 7.5 The Bias-Variance Tradeoff

Total error = $\text{Bias}^2 + \text{Variance} + \sigma^2$. Since $\sigma^2$ is fixed, we want to minimise $\text{Bias}^2 + \text{Variance}$.

These two pull in opposite directions:

```
Error
  |
  |  \                                  Total Error
  |   \                   ____________/
  |    \                 /
  |     \               /   Variance (grows with complexity)
  |      \             /
  |       \___________/
  |                        ←Bias² (shrinks with complexity)
  |
  +----------------------------------------> Model Complexity
                      ↑
              Sweet spot (minimises total error)
```

As model complexity increases:

- **Bias decreases** — richer $\mathcal{H}$ can approximate $f^*$ more closely
- **Variance increases** — richer $\mathcal{H}$ is more sensitive to the specific training set

The optimal complexity sits at the bottom of the total error curve.

### 7.6 Important Caveat: Double Descent

The classical U-curve above is incomplete for modern deep learning.

For very large models (like large neural networks), empirically the test error can **decrease again** after the classical overfitting peak. This is called **double descent**. It occurs when the model is large enough to perfectly memorise the training data _and still generalise_.

The bias-variance framework remains valid, but the relationship between model size and variance is more subtle than the classical picture — SGD and overparameterisation interact in ways the classical theory doesn't fully capture. This is an active research area.

### 7.7 Implications: Why Regularisation Works

The bias-variance decomposition directly explains every regularisation technique:

|Technique|What It Does|Bias-Variance View|
|---|---|---|
|L2 (Ridge)|Penalises $\lambda\|w\|_2^2$|Shrinks weights → reduces variance at cost of slight bias|
|L1 (Lasso)|Penalises $\lambda\|w\|_1$|Drives some weights to exactly zero (sparse) → reduces effective model size|
|Early stopping|Stop gradient descent before convergence|Prevents memorising training noise → equivalent to L2 regularisation|
|Dropout|Randomly zero activations during training|Effectively trains an ensemble of smaller networks → reduces variance|

**All regularisation is variance reduction at the cost of some bias.** The hyperparameter ($\lambda$, dropout rate, number of epochs) controls where you sit on the bias-variance curve.

## 8. Rademacher Complexity: A More General Complexity Measure

VC dimension is powerful but limited — it only applies to binary classification. **Rademacher complexity** generalises the idea to regression, multi-class, and any real-valued function class.

### 8.1 The Idea

Rademacher complexity asks: **how well can functions in $\mathcal{F}$ fit pure random noise?**

This is a clever test. A very expressive function class can always find some $f$ that correlates well with any random labels — it can fit noise. A simple class cannot.

### 8.2 Definition

Let $\sigma_1, \ldots, \sigma_n$ be independent random $\pm 1$ labels (called **Rademacher variables** — think of them as completely random coin flips). The **empirical Rademacher complexity** is:

$$\hat{\mathcal{R}}_n(\mathcal{F}) = \mathbb{E}_\sigma!\left[\sup_{f \in \mathcal{F}} \frac{1}{n} \sum_{i=1}^n \sigma_i f(x_i)\right]$$

In plain English: on your training inputs $x_1, \ldots, x_n$, assign random $\pm 1$ labels. How well can the best function in $\mathcal{F}$ correlate with these random labels? A rich class can correlate well (high Rademacher complexity). A simple class cannot (low complexity).

The **Rademacher complexity** $\mathcal{R}_n(\mathcal{F})$ is the expectation of the above over random training sets.

### 8.3 Rademacher Generalisation Bound

With probability at least $1 - \delta$ over a training sample of size $n$:

$$R(\hat{h}) \leq \hat{R}(\hat{h}) + 2\mathcal{R}_n(\mathcal{H}_\ell) + \sqrt{\frac{\log(1/\delta)}{2n}}$$

where $\mathcal{H}_\ell$ is the loss class induced by $\mathcal{H}$.

This is tighter than VC bounds in many practical cases and works beyond binary classification.

## 9. Decomposing Excess Risk

We can split the gap between our learned model and the Bayes-optimal into two interpretable pieces:

$$\underbrace{R(\hat{h}) - R(h^_)}_{\text{Excess Risk}} = \underbrace{R(h^__\mathcal{H}) - R(h^*)}_{\text{Approximation Error}} + \underbrace{R(\hat{h}) - R(h^*_\mathcal{H})}_{\text{Estimation Error}}$$

where $h^*_\mathcal{H} = \arg\min_{h \in \mathcal{H}} R(h)$ is the best possible model in your hypothesis class.

|Error Type|What It Is|How to Reduce It|What Affects It|
|---|---|---|---|
|**Approximation Error**|Gap between best-in-class and Bayes-optimal|Use a richer hypothesis class|Only class richness, not data|
|**Estimation Error**|Gap between what you learned and best-in-class|Get more training data|Data size $n$|

This connects directly to bias-variance:

- Approximation error = bias (the class isn't expressive enough)
- Estimation error = variance (you didn't estimate the best-in-class model accurately)

The tension: as you enrich $\mathcal{H}$, approximation error decreases but estimation error increases.

## 10. Occam's Razor as a Mathematical Theorem

"Prefer simpler explanations." Occam's Razor sounds like philosophy. But it follows directly from the PAC bound.

Assign a **complexity cost** $c(h) > 0$ to every hypothesis such that $\sum_{h \in \mathcal{H}} e^{-c(h)} \leq 1$ (think of this as a probability distribution over models, where simpler models get lower cost). Then with probability at least $1 - \delta$:

$$R(h) \leq \hat{R}(h) + \sqrt{\frac{c(h) + \log(1/\delta)}{2n}}$$

The simpler the hypothesis (smaller $c(h)$), the tighter the generalisation guarantee.

**The theorem says:** If two models achieve the same training error, the mathematically provable bound on their true error is _tighter_ for the simpler model.

Simplicity is not aesthetic preference — it is a statistical guarantee. This is why we regularise.

## 11. Structural Risk Minimisation (SRM)

SRM is the practical algorithm that applies the theory above.

**Setup:** You have a nested sequence of increasingly rich hypothesis classes:

$$\mathcal{H}_1 \subset \mathcal{H}_2 \subset \cdots \subset \mathcal{H}_k$$

For example:

- $\mathcal{H}_1$ = linear functions
- $\mathcal{H}_2$ = quadratic functions
- $\mathcal{H}_3$ = cubic functions
- ...

Each class has increasing VC complexity $d_1 \leq d_2 \leq \cdots \leq d_k$.

**SRM selects the model and the class simultaneously:**

$$\hat{k}, \hat{h} = \underset{k,\ h \in \mathcal{H}_k}{\arg\min} \left[\hat{R}(h) + \text{complexity penalty}(n, d_k, \delta)\right]$$

The complexity penalty comes from the VC bound. You're choosing the model that minimises the **total bound on true risk**, not just training error.

**In practice, SRM motivates:**

- **Cross-validation** — empirically approximating the theoretical bound by holding out validation data
- **Regularisation paths** — in Lasso/Ridge, varying $\lambda$ traces the family of models $\hat{h}$ as complexity is controlled
- **Bayesian model selection** — choosing the model with highest marginal likelihood (which implicitly penalises complexity)

## 12. What This Theory Says and What It Doesn't

### ✅ What PAC/VC Theory Says

- If $\text{VC-dim}(\mathcal{H}) < \infty$ and you have enough data, ERM will generalise
- The generalisation gap shrinks at rate $O(1/\sqrt{n})$ as you add data
- Model complexity must be matched to sample size — you can't use a complex model with very little data
- All else equal, simpler models that fit the data well are provably preferable

### ❌ What It Does Not Say

|Limitation|Reality|
|---|---|
|**Bounds are very loose**|A VC bound may say you need $10^6$ samples; in practice $10^3$ suffice. The bounds tell you the right _rates_ and _dependencies_, but constants are often uninformative.|
|**Assumes i.i.d. data**|Distribution shift, covariate shift, temporal dependence — all violate the assumptions. The theory is still directionally useful but not directly applicable.|
|**Doesn't explain deep learning**|Neural networks with millions of parameters trained to zero training error still generalise. The VC dimension of large NNs is enormous, yet bounds massively overestimate the required data.|
|**Double descent is unaccounted for**|The classical theory predicts a U-curve. In reality, very large models enter a second descent phase after interpolation. SGD's implicit regularisation and the geometry of overparameterised loss landscapes are partial explanations.|

For neural networks specifically: the VC dimension is proportional to the number of parameters × number of layers — yet practical generalisation is far better than the bound predicts. The theory is _necessary_ for understanding learning, but _not sufficient_ for understanding deep learning. This is one of the most active areas in ML theory today.

```
VC dimension:    the right notion of "complexity" for binary classification

Bias:            error from underfitting (class too simple)
Variance:        error from overfitting (class too rich, not enough data)

```
