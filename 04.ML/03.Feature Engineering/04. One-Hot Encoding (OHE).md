# 1. Context: why nominal data needs One-Hot Encoding

## 1.1 The motivation

Machine learning algorithms work with **mathematical operations** (distances, dot products, gradients), so they cannot consume raw strings. Categorical features must be converted to numbers before training.

## 1.2 Recap of categorical types

|Type|Meaning|Examples|Encoding|
|---|---|---|---|
|**Ordinal**|categories with an intrinsic order or ranking|review: Poor < Average < Good; education: School < UG < PG|`OrdinalEncoder` ([[11.Ordinal and Label Encoding]])|
|**Nominal**|categories with **no natural ordering or hierarchy**|colour: Yellow, Blue, Red; gender: Male, Female; fuel: Petrol, Diesel, CNG; brand; city|**One-Hot Encoding** (this note)|
|**Target**|the label we predict|purchased Yes/No|`LabelEncoder`|

## 1.3 Why not just number the categories?

Giving Yellow = 0, Blue = 1, Red = 2 tells the model that Red is "twice" Blue and that Blue sits "between" Yellow and Red. For nominal data this order is invented (derivation in [[11.Ordinal and Label Encoding]], section 2). One-Hot Encoding represents each category as its own **independent** direction, so the model assumes no order and no preferred distances.

# 2. How One-Hot Encoding works

## 2.1 The mechanism

For a nominal feature with **$K$ unique categories**, OHE creates **$K$ new binary columns** (one per category). In each row, exactly **one** column is 1 (the row's category) and the rest are 0.

### Example: a `Color` column with Yellow, Blue, Red

|Color (original)|Color_Yellow|Color_Blue|Color_Red|
|---|---|---|---|
|Yellow|**1**|0|0|
|Blue|0|**1**|0|
|Red|0|0|**1**|
|Blue|0|**1**|0|

Each category becomes a **binary vector**: $$\text{Yellow} \to \begin{bmatrix}1\0\0\end{bmatrix},\qquad \text{Blue} \to \begin{bmatrix}0\1\0\end{bmatrix},\qquad \text{Red} \to \begin{bmatrix}0\0\1\end{bmatrix}$$ The name comes from digital electronics: of $K$ wires, exactly one is "hot" (on).

```python
import pandas as pd

colors = pd.DataFrame({"Color": ["Yellow", "Blue", "Red", "Blue"]})
print(pd.get_dummies(colors, dtype=int))
#    Color_Blue  Color_Red  Color_Yellow
# 0           0          0             1
# 1           1          0             0
# 2           0          1             0
# 3           1          0             0
```

(`pd.get_dummies` and scikit-learn order the new columns **alphabetically**, not by appearance.)

## 2.2 Geometry: why it creates no fake order

The one-hot vectors are the **standard basis vectors** $e_1, e_2, \dots, e_K$. For any two different categories $i \neq j$: $$\lVert e_i - e_j\rVert^2 = 1^2 + 1^2 = 2 \quad\Rightarrow\quad d(e_i, e_j) = \sqrt{2}$$ and their dot product $e_i \cdot e_j = 0$ (they are **orthogonal**, with cosine similarity 0).

So **every pair of categories is exactly the same distance apart**. No category is "closer" to another. Compare with integer codes, where distance(0, 2) = 2 but distance(0, 1) = 1.

```python
import numpy as np
E = np.eye(3)                                                         # the three one-hot vectors
print([np.linalg.norm(E[i] - E[j]).round(3) for i, j in [(0, 1), (0, 2), (1, 2)]])      # [1.414, 1.414, 1.414]
```

## 2.3 The matrix is sparse

Each row has exactly one 1 among $K$ entries, so for large $K$ the matrix is almost all zeros. Libraries store it as a **sparse matrix** to save memory (section 9.3).

## 2.4 Dimension grows

One column becomes $K$ columns. For a feature with 4 fuel types that is trivial; for a feature with 3,000 cities it is a serious problem (section 4).

# 3. The dummy variable trap and multicollinearity

## 3.1 The trap

With $K$ dummy columns $C_1, \dots, C_K$, every row satisfies $$C_1 + C_2 + \dots + C_K = 1$$ because exactly one category is active. This is an **exact linear relationship** among the input columns. The last column is fully predictable from the others: $C_K = 1 - C_1 - \dots - C_{K-1}$.

In a model that also has an **intercept** (a column of ones), this means $$\mathbf{1} = C_1 + C_2 + \dots + C_K$$ so the design matrix has **perfectly collinear columns**.

## 3.2 Why linear models care: derivation

Ordinary least squares (OLS) with design matrix $X$ solves the normal equations $$X^\top X,\hat{w} = X^\top y \quad\Rightarrow\quad \hat{w} = (X^\top X)^{-1} X^\top y$$ If the columns of $X$ are linearly dependent, $X$ has **rank less than its number of columns**, so $X^\top X$ is **singular** (determinant 0) and **cannot be inverted**.

Intuitively, the model $\hat{y} = b + \sum_k w_k C_k$ has **infinitely many equivalent solutions**. For any constant $t$, replacing $$b \to b + t, \qquad w_k \to w_k - t ;;\text{for all } k$$ changes nothing, because $t\cdot 1 - t,(C_1 + \dots + C_K) = 0$ for every row. The data cannot decide which $(b, w)$ is "right", so the estimates are **non-unique, unstable, and may blow up** in size. This is **multicollinearity** (here its extreme form, _perfect_ multicollinearity).

Models affected: **Linear Regression, Logistic Regression** (without regularisation), and anything using $X^\top X$ or a Hessian that must be invertible. Linear models assume the input features are not perfectly dependent on one another.

```python
import numpy as np, pandas as pd

s = pd.Series(["Yellow", "Blue", "Red", "Blue", "Yellow", "Red"])
D = pd.get_dummies(s, dtype=int)                             # columns: Blue, Red, Yellow  (K = 3)

X_full = np.c_[np.ones(len(D)), D.values]                    # intercept + all K dummies = 4 columns
print("columns:", X_full.shape[1], "| rank:", np.linalg.matrix_rank(X_full))        # 4 vs 3: rank deficient
print("det(X'X):", np.linalg.det(X_full.T @ X_full).round(6))                       # about 0 -> singular

X_drop = np.c_[np.ones(len(D)), D[["Red", "Yellow"]].values] # intercept + (K-1) dummies = 3 columns
print("columns:", X_drop.shape[1], "| rank:", np.linalg.matrix_rank(X_drop))        # 3 vs 3: full rank
```

## 3.3 The solution: $K-1$ encoding

**Drop one dummy column.** For $K$ categories keep only $K-1$ columns; the dropped category becomes the **reference (baseline) category**, represented implicitly by "all dummies are 0".

|Color|Color_Blue|Color_Red|(Color_Yellow dropped)|
|---|---|---|---|
|Yellow|0|0|implied|
|Blue|1|0||
|Red|0|1||

If `Color_Blue = 0` and `Color_Red = 0`, the row must be Yellow. No information is lost, and the linear dependence is gone (the remaining columns plus the intercept are independent).

> **Which column is "first"?** The lecture drops Yellow (first in its listing). scikit-learn and pandas sort categories **alphabetically**, so `drop="first"` drops **Blue** here. The choice does not change predictions, only which category serves as the baseline.

## 3.4 What the coefficients mean after dropping

With the reference category's dummies all zero, the model is $\hat{y} = b + w_{\text{Blue}},\text{Blue} + w_{\text{Red}},\text{Red}$ (Yellow as the reference):

- For Yellow: $\hat{y} = b$, so **$b$ = the mean outcome of the reference category** (in OLS).
- For Blue: $\hat{y} = b + w_{\text{Blue}}$, so **$w_{\text{Blue}}$ = mean(Blue) - mean(Yellow)**.
- For Red: **$w_{\text{Red}}$ = mean(Red) - mean(Yellow)**.

Each coefficient is the **difference from the reference**. This makes the choice of reference important for interpretation (pick a meaningful baseline, for example the most common category or an "unspecified" one).

```python
from sklearn.linear_model import LinearRegression

y = np.array([10, 30, 20, 32, 11, 19], dtype=float)
ref = "Yellow"
X_ref = pd.get_dummies(s, dtype=int).drop(columns=ref)       # keep Blue and Red; Yellow is the reference
lr = LinearRegression().fit(X_ref, y)

means = pd.Series(y).groupby(s.values).mean()
print("intercept          :", lr.intercept_.round(2), "= mean(Yellow) =", means["Yellow"])
print(dict(zip(X_ref.columns, lr.coef_.round(2))))
print("mean(Blue)-mean(Yellow):", (means["Blue"] - means["Yellow"]).round(2),
      "| mean(Red)-mean(Yellow):", (means["Red"] - means["Yellow"]).round(2))
```

The printed coefficients match the differences in group means exactly.

## 3.5 Subtlety: dropping changes the geometry for distance models

After dropping, the reference category is the **zero vector**. Distances become:

- reference to any other category: $\lVert 0 - e_i\rVert = 1$
- between two non-reference categories: $\lVert e_i - e_j\rVert = \sqrt{2}$

So the reference now looks **closer** to everything than the others are to each other, an artifact. For **KNN, K-Means, and RBF-SVM**, keep all $K$ columns (no drop). Dropping is for linear models.

## 3.6 When you do and do not need to drop

|Model|Drop one dummy?|Why|
|---|---|---|
|Linear / Logistic regression **without** regularisation|**Yes**|avoid singular $X^\top X$|
|Ridge, Lasso, Elastic Net, and `LogisticRegression` (L2 by default)|Optional|the penalty makes the solution unique, but coefficients are still easier to read with a reference|
|statsmodels OLS / GLM|**Yes**|will raise or warn about singular matrices|
|Decision trees, random forests, gradient boosting|No|not affected by collinearity|
|KNN, K-Means, SVM (RBF)|**No**|dropping distorts distances|
|Neural networks|No|not affected; extra column is harmless|

## 3.7 Binary features

For a feature with $K = 2$ (gender: Male / Female), dropping one dummy leaves a **single 0/1 column**. This is the natural encoding for a two-category variable. In scikit-learn use `drop="if_binary"` to do this automatically for binary features while keeping all dummies for features with more than two categories.

# 4. High cardinality: the top-frequent-categories strategy

## 4.1 The problem

**Cardinality** is the number of unique categories. If a `brand` column has 32 distinct car brands, standard OHE creates **32+ new columns**:

- **Dimensionality inflates** (more features than useful information),
- **Memory use grows** and **training slows**,
- Most columns are **rare** (few ones), so the model sees too little data for each,
- Risk of **overfitting** and the curse of dimensionality (especially for KNN, linear models without regularisation),
- Test data may contain **unseen** categories.

## 4.2 Top frequent categories strategy

1. Count how often each category occurs (`value_counts()`).
2. Choose a **frequency threshold** (for example, brands with at least 100 cars: Maruti, Hyundai, Honda, ...).
3. Keep the **frequent** categories as they are.
4. Group **all infrequent (rare)** categories (luxury brands with few listings, such as Jaguar and Volvo) into a single category named `Uncommon` (or `Other`).
5. Apply OHE to the reduced set.

Result: a feature with 32+ levels shrinks to about 10 to 11 columns (10 frequent brands plus `Uncommon`).

|Brand|Count|After grouping|
|---|---|---|
|Maruti|1,200|Maruti|
|Hyundai|800|Hyundai|
|... (frequent ones)|100+|unchanged|
|Jaguar|8|**Uncommon**|
|Volvo|5|**Uncommon**|

## 4.3 Code (pandas)

```python
counts = df["brand"].value_counts()
threshold = 100
frequent = counts[counts >= threshold].index                      # brands to keep
df["brand_grouped"] = df["brand"].where(df["brand"].isin(frequent), "Uncommon")

print(df["brand"].nunique(), "->", df["brand_grouped"].nunique())  # e.g. 32 -> 11
df["brand_grouped"].value_counts()
```

Equivalent with `np.where` or a replace loop:

```python
df["brand_grouped"] = np.where(df["brand"].isin(frequent), df["brand"], "Uncommon")
```

## 4.4 Do it without leakage: learn the frequent set on training data only

The counts decide which categories are kept, so they are **learned from data**. Compute them on the **training set** and apply the same rule to test and production data (where unseen brands also become `Uncommon`).

```python
keep = X_train["brand"].value_counts()
keep = keep[keep >= 100].index

X_train["brand_grouped"] = X_train["brand"].where(X_train["brand"].isin(keep), "Uncommon")
X_test["brand_grouped"] = X_test["brand"].where(X_test["brand"].isin(keep), "Uncommon")     # unseen brands -> Uncommon too
```

## 4.5 A reusable, pipeline-safe grouping transformer

```python
from sklearn.base import BaseEstimator, TransformerMixin

class RareCategoryGrouper(BaseEstimator, TransformerMixin):
    """Replace categories with fewer than `min_count` training rows by `label`."""
    def __init__(self, min_count=100, label="Uncommon"):
        self.min_count = min_count
        self.label = label
    def fit(self, X, y=None):
        X = pd.DataFrame(X)
        self.cols_ = list(X.columns)
        self.keep_ = {c: set(X[c].value_counts()[lambda v: v >= self.min_count].index) for c in self.cols_}
        return self
    def transform(self, X):
        X = pd.DataFrame(X, columns=self.cols_).copy()
        for c in self.cols_:
            X[c] = X[c].where(X[c].isin(self.keep_[c]), self.label)
        return X
    def get_feature_names_out(self, input_features=None):
        return np.array(self.cols_)
```

Chain it in front of the encoder: `Pipeline([("group", RareCategoryGrouper(100)), ("ohe", OneHotEncoder(...))])`.

## 4.6 Built-in scikit-learn alternative (1.1+)

`OneHotEncoder` can group rare categories itself:

```python
from sklearn.preprocessing import OneHotEncoder

ohe = OneHotEncoder(min_frequency=100,                      # categories with fewer than 100 rows are "infrequent"
                    handle_unknown="infrequent_if_exist",   # unseen categories join the infrequent group
                    sparse_output=False)
ohe.fit(X_train[["brand"]])
print(ohe.infrequent_categories_)                           # which categories were merged
print(ohe.get_feature_names_out())                          # includes 'brand_infrequent_sklearn'
```

`max_categories=10` instead keeps only the 10 most frequent (including the merged infrequent group).

## 4.7 Choosing the threshold

|Rule of thumb|Note|
|---|---|
|a fixed count (100)|simple, as in the lecture|
|a share of rows (1% to 5%)|scales with dataset size|
|cumulative coverage (top categories covering 80% to 95% of rows)|keeps most data detailed|
|tune it with cross-validation|treat the threshold as a hyperparameter|

```python
share = X_train["brand"].value_counts(normalize=True)
print("top 10 brands cover", share.head(10).sum().round(3), "of rows")
```

# 5. Method A: `pd.get_dummies()`

## 5.1 Usage

```python
import pandas as pd

pd.get_dummies(df, columns=["fuel", "owner"])                               # only these columns are expanded
pd.get_dummies(df, columns=["fuel", "owner"], drop_first=True)              # K-1 columns per feature
pd.get_dummies(df, columns=["fuel"], dtype=int)                             # 0/1 integers (default is bool in pandas 2.x)
pd.get_dummies(df, columns=["fuel"], prefix="f", prefix_sep="_")            # control the new column names
pd.get_dummies(df, columns=["fuel"], dummy_na=True)                         # extra column for missing values
```

|Argument|Effect|
|---|---|
|`columns=[...]`|which columns to encode (the rest pass through unchanged)|
|`drop_first=True`|remove the first dummy per feature to avoid the dummy variable trap ($K-1$ columns)|
|`dtype=int`|integer 0/1 (in pandas 2.x the default is `bool`; older versions used `uint8`)|
|`dummy_na=True`|add a column for `NaN`|
|`sparse=True`|return sparse columns|

The original columns are removed and replaced by the dummies.

## 5.2 Strengths

- One line, readable output with proper column names, keeps the DataFrame index.
- Excellent for **quick exploration**, EDA, and one-off analysis.

## 5.3 The limitation: it does not remember anything

`pd.get_dummies()` works on **whatever data you hand it**. It stores no mapping of categories to columns, so it **cannot reproduce the same transformation on unseen test or production data**.

```python
train = pd.DataFrame({"fuel": ["Diesel", "Petrol", "CNG", "Petrol"]})
test = pd.DataFrame({"fuel": ["Petrol", "LPG"]})                 # LPG never appeared in train

print(pd.get_dummies(train, dtype=int).columns.tolist())         # ['fuel_CNG', 'fuel_Diesel', 'fuel_Petrol']
print(pd.get_dummies(test, dtype=int).columns.tolist())          # ['fuel_LPG', 'fuel_Petrol']  -> different columns!
```

The test set has a different set and order of columns, so a model trained on the training columns **breaks or silently misaligns** features. A manual patch exists:

```python
train_cols = pd.get_dummies(train, dtype=int).columns
test_enc = pd.get_dummies(test, dtype=int).reindex(columns=train_cols, fill_value=0)     # unseen LPG is dropped, missing columns become 0
```

...but this is fragile (you must carry `train_cols` around yourself, and `drop_first` complicates it). Therefore `get_dummies` is **generally avoided in production ML pipelines**.

# 6. Method B: scikit-learn `OneHotEncoder`

## 6.1 Why it is the production standard

`OneHotEncoder` is a proper scikit-learn **transformer**. During `fit()` it **saves the category-to-column mapping**, so `transform()` produces identical columns for training data, test data, and new data at deployment. It plugs directly into `Pipeline` and `ColumnTransformer`.

## 6.2 Constructor

```python
from sklearn.preprocessing import OneHotEncoder
import numpy as np

OneHotEncoder(
    categories="auto",             # or a list of lists to fix categories and their order
    drop=None,                     # None | "first" | "if_binary" | list of categories per feature
    sparse_output=True,            # False -> dense NumPy array (use sparse=False in scikit-learn < 1.2)
    dtype=np.float64,              # np.int32 -> integer 0/1 output
    handle_unknown="error",        # "ignore" | "infrequent_if_exist"
    min_frequency=None,            # group rare categories (scikit-learn 1.1+)
    max_categories=None,           # cap number of output categories per feature (1.1+)
)
```

|Parameter|Purpose|
|---|---|
|`drop="first"`|removes the first category of each feature to avoid multicollinearity (the dummy variable trap)|
|`drop="if_binary"`|drops one column only for features with exactly 2 categories|
|`drop=["Petrol", "First Owner"]`|choose the reference category per feature (one entry per feature)|
|`sparse_output=False` (older: `sparse=False`)|returns a **dense** NumPy array rather than a sparse matrix|
|`dtype=np.int32`|outputs integer 0/1 instead of floats|
|`handle_unknown="ignore"`|unseen categories become all zeros instead of raising an error|
|`min_frequency`, `max_categories`|group rare categories (section 4.6)|
|`categories=[[...], [...]]`|fix the allowed categories and their column order explicitly|

## 6.3 Attributes and methods

|Member|Purpose|
|---|---|
|`fit(X_train)`|learns the categories of each feature from **training data**|
|`transform(X)`|applies the saved mapping to train, test, or new data|
|`fit_transform(X_train)`|both, for training data only|
|`inverse_transform(Z)`|back to the original categories (with `drop`, an all-zero row maps to the dropped category)|
|`categories_`|list of arrays, the categories found per feature|
|`drop_idx_`|index of the dropped category per feature|
|`get_feature_names_out()`|names of the output columns (`fuel_Diesel`, ...)|
|`infrequent_categories_`|the grouped rare categories (if `min_frequency` or `max_categories` is used)|
|`feature_names_in_`|the input column names|

## 6.4 The standard workflow

1. **Split** the data into training and test sets **before encoding** (prevents data leakage).
2. Create the encoder with the chosen options.
3. `fit_transform` on the training columns; `transform` on the test columns.
4. Recombine with the numerical features.
5. Train the model.

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)

ohe = OneHotEncoder(drop="first", sparse_output=False, dtype=np.int32)

train_cat = ohe.fit_transform(X_train[["fuel", "owner"]])     # learn on TRAIN, transform TRAIN
test_cat = ohe.transform(X_test[["fuel", "owner"]])           # transform TEST with the saved mapping

print(ohe.categories_)
print(ohe.get_feature_names_out())
print(train_cat.shape, test_cat.shape)
```

Rules (same as scalers and other encoders): **fit on train only, transform both, never fit on test**.

## 6.5 Putting numerical and encoded columns back together

The encoder returns a NumPy array, so the lecture recombines manually with `np.hstack()`:

```python
num_cols = ["km_driven"]

X_train_final = np.hstack([X_train[num_cols].to_numpy(), train_cat])
X_test_final = np.hstack([X_test[num_cols].to_numpy(), test_cat])
print(X_train_final.shape)
```

A DataFrame version that keeps column names (recommended):

```python
cat_names = ohe.get_feature_names_out()
X_train_df = pd.concat([X_train[num_cols].reset_index(drop=True),
                        pd.DataFrame(train_cat, columns=cat_names)], axis=1)
```

Or let scikit-learn do it (scikit-learn 1.2+):

```python
ohe = OneHotEncoder(drop="first", sparse_output=False).set_output(transform="pandas")
train_cat_df = ohe.fit_transform(X_train[["fuel", "owner"]])      # DataFrame with named columns and the original index
X_train_df = pd.concat([X_train[num_cols], train_cat_df], axis=1) # indexes align, no reset needed
```

This manual slicing, encoding, and re-stacking is **verbose and error-prone**; the next lesson (`ColumnTransformer`) replaces it.

## 6.6 `inverse_transform`

```python
ohe.inverse_transform(test_cat[:3])          # back to the original category labels
```

## 6.7 Comparing the two methods

||`pd.get_dummies()`|`OneHotEncoder`|
|---|---|---|
|Convenience|very high, one line|needs a few lines|
|Remembers the categories (fit/transform)|**no**|**yes**|
|Same columns for train, test, production|no (needs manual alignment)|**yes**|
|Handles unseen categories|no|yes (`handle_unknown`)|
|Works in `Pipeline` / `ColumnTransformer`|no|**yes**|
|Returns|DataFrame with names|NumPy / sparse (DataFrame with `set_output`)|
|Rare-category grouping|manual|built in (`min_frequency`)|
|Best for|exploration, EDA, notebooks|**modelling and production**|

# 7. Worked example: the second-hand car dataset

The lecture uses a **second-hand car** dataset with columns `brand`, `km_driven`, `fuel` (Diesel, Petrol, CNG, LPG), `owner` (First Owner, Second Owner, and so on), and the target `selling_price`.

## 7.1 Build a stand-in dataset

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)

top = {"Maruti": 1200, "Hyundai": 800, "Mahindra": 350, "Tata": 300, "Honda": 250,
       "Ford": 200, "Toyota": 180, "Chevrolet": 150, "Renault": 140, "Volkswagen": 110}
rare = ["Skoda", "Nissan", "Datsun", "Fiat", "BMW", "Mercedes-Benz", "Audi", "Jaguar", "Volvo", "Land",
        "Mitsubishi", "Jeep", "Mini", "Lexus", "Porsche", "Isuzu", "Ashok", "Force", "Ambassador",
        "Opel", "Kia", "MG"]
weights = np.array(list(top.values()) + list(rng.integers(3, 40, len(rare))), dtype=float)
brands = list(top) + rare
n = 4000
brand = rng.choice(brands, n, p=weights / weights.sum())

luxury = {"BMW", "Mercedes-Benz", "Audi", "Jaguar", "Volvo", "Land", "Porsche", "Lexus", "Mini"}
brand_effect = {b: rng.normal(0, 0.15) + (0.9 if b in luxury else 0) for b in brands}
fuel = rng.choice(["Diesel", "Petrol", "CNG", "LPG"], n, p=[0.5, 0.43, 0.05, 0.02])
owner = rng.choice(["First Owner", "Second Owner", "Third Owner", "Fourth & Above Owner", "Test Drive Car"],
                   n, p=[0.65, 0.25, 0.07, 0.025, 0.005])
km = rng.gamma(4, 15_000, n).round(-2)

log_price = (12.8 + np.array([brand_effect[b] for b in brand])
             + pd.Series(fuel).map({"Diesel": 0.15, "Petrol": 0.0, "CNG": -0.1, "LPG": -0.2}).to_numpy()
             + pd.Series(owner).map({"First Owner": 0, "Second Owner": -0.12, "Third Owner": -0.25,
                                     "Fourth & Above Owner": -0.35, "Test Drive Car": 0.3}).to_numpy()
             - km * 3e-6 + rng.normal(0, 0.15, n))

df = pd.DataFrame({"brand": brand, "km_driven": km, "fuel": fuel, "owner": owner,
                   "selling_price": np.exp(log_price).round(-3)})
print(df.head())
print(df["brand"].nunique(), "brands;", df["fuel"].nunique(), "fuel types;", df["owner"].nunique(), "owner types")
```

(Use your own `cars.csv` via `pd.read_csv` if you have it.)

## 7.2 Look at the categorical columns

```python
for col in ["fuel", "owner", "brand"]:
    print(df[col].value_counts().head(12), "\n")
```

- `fuel` (4 values) and `owner` (5 values) are **low cardinality**: plain OHE is fine.
- `brand` (32 values) is **high cardinality** with a long tail: group the rare ones.

## 7.3 Step 1: split first

```python
from sklearn.model_selection import train_test_split

X = df.drop(columns="selling_price")
y = df["selling_price"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=2)
```

## 7.4 Step 2: One-Hot Encode `fuel` and `owner` (Method B)

```python
from sklearn.preprocessing import OneHotEncoder

ohe = OneHotEncoder(drop="first", sparse_output=False, dtype=np.int32)

X_train_cat = ohe.fit_transform(X_train[["fuel", "owner"]])
X_test_cat = ohe.transform(X_test[["fuel", "owner"]])

print(ohe.categories_)
print(ohe.get_feature_names_out())
# fuel (4 categories)  -> 3 columns after drop="first"
# owner (5 categories) -> 4 columns after drop="first"     => 7 new columns in total

X_train_final = np.hstack([X_train[["km_driven"]].to_numpy(), X_train_cat])
X_test_final = np.hstack([X_test[["km_driven"]].to_numpy(), X_test_cat])
print(X_train_final.shape)                               # (3200, 8): km_driven + 7 dummies
```

Spot check one row: if every dummy for `fuel` is 0, that row is the dropped (reference) fuel type, here **CNG** (alphabetically first).

## 7.5 Step 3: the high-cardinality `brand` column

```python
counts = X_train["brand"].value_counts()
print(counts.head(12))
print("brands with at least 100 cars:", (counts >= 100).sum(), "of", len(counts))

frequent = counts[counts >= 100].index
X_train["brand"] = X_train["brand"].where(X_train["brand"].isin(frequent), "Uncommon")
X_test["brand"] = X_test["brand"].where(X_test["brand"].isin(frequent), "Uncommon")      # same rule, from TRAIN counts

print(X_train["brand"].nunique(), "categories after grouping")    # about 8 to 11 instead of 32
print(X_train["brand"].value_counts())
```

(Work on a copy such as `X_train = X_train.copy()` to avoid pandas' `SettingWithCopyWarning`.) The luxury brands (Jaguar, Volvo, and so on) now fall under `Uncommon`.

## 7.6 Step 4: encode everything and train a model

```python

ohe = OneHotEncoder(drop="first", sparse_output=False, dtype=np.int32, handle_unknown="ignore")

from sklearn.metrics import r2_score

model = Ridge(alpha=1.0).fit(Xtr, np.log(y_train))

```

(Modelling the log of a skewed target such as price is common; see [[06.Univariate Analysis]].)

## 7.7 Step 5: the one-step version (preview of the next lesson)

```python
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X_raw_train, X_raw_test, y_raw_train, y_raw_test = train_test_split(X, y, test_size=0.2, random_state=2)   # fresh, ungrouped copies

pre = ColumnTransformer([
    ("cat", Pipeline([("group", RareCategoryGrouper(min_count=100)),
                      ("ohe", OneHotEncoder(drop="first", handle_unknown="ignore"))]), ["brand", "fuel", "owner"]),
    ("num", StandardScaler(), ["km_driven"]),
])
pipe = Pipeline([("prep", pre), ("model", Ridge(alpha=1.0))])
pipe.fit(X_raw_train, np.log(y_raw_train))
print("R2:", r2_score(np.log(y_raw_test), pipe.predict(X_raw_test)).round(3))
```

Everything (grouping, encoding, scaling) is fitted on the training data only and applied identically to new data, with no manual `hstack`. `ColumnTransformer` is the subject of the next lesson.

## 7.8 Does grouping hurt accuracy? Measure it

```python
from sklearn.model_selection import cross_val_score

def pipe_for(group):
    cat_steps = [("group", RareCategoryGrouper(100))] if group else []
    cat = Pipeline(cat_steps + [("ohe", OneHotEncoder(drop="first", handle_unknown="ignore"))])
    pre = ColumnTransformer([("cat", cat, ["brand", "fuel", "owner"]), ("num", StandardScaler(), ["km_driven"])])
    return Pipeline([("prep", pre), ("model", Ridge(alpha=1.0))])

for g in (False, True):
    p = pipe_for(g)
    p.fit(X_raw_train, np.log(y_raw_train))
    n_cols = p[:-1].transform(X_raw_train).shape[1]
    score = cross_val_score(p, X_raw_train, np.log(y_raw_train), cv=5).mean()
    print(f"group rare brands = {g!s:5}  columns = {n_cols:3d}  CV R2 = {score:.3f}")
```

Typical pattern: grouping cuts the number of columns sharply with little or no loss in accuracy (and can help when rare categories add noise). Here the cost is that the distinct luxury premium of rare brands is partly lost, because they are lumped together, so tune the threshold rather than assuming 100 is perfect.

# 8. Which models need which version of OHE

|Model family|Encoding advice|
|---|---|
|**Linear / logistic regression**|OHE with `drop="first"` (or regularise); choose a meaningful reference; scale numerics separately|
|**Ridge / Lasso / Elastic Net**|OHE; dropping optional; Lasso may zero out dummies|
|**KNN, K-Means, SVM**|OHE with **all $K$ columns**; consider scaling consistency (dummies are already 0/1)|
|**Neural networks**|OHE, or **embeddings** for high-cardinality features|
|**Tree-based (random forest, GBM, XGBoost)**|OHE works for low cardinality; for high cardinality it tends to be wasteful (trees must find one-column splits), so prefer grouping, frequency/target encoding, or native categorical support (LightGBM, CatBoost, `HistGradientBoosting(categorical_features=...)`)|
|**Naive Bayes (categorical)**|usually expects integer-coded categories, not one-hot|

### Feature importance after OHE

```python
names = pipe[:-1].get_feature_names_out()

coefs.head(), coefs.tail()                    # largest negative and positive effects per category (vs. the reference)
```

# 9. Edge cases

## 9.1 Unknown categories at prediction time

```python
ohe = OneHotEncoder(drop="first", sparse_output=False)
ohe.fit(pd.DataFrame({"fuel": ["Diesel", "Petrol", "CNG"]}))
try:
    ohe.transform(pd.DataFrame({"fuel": ["Hydrogen"]}))
except ValueError as e:
    print(str(e)[:70])                         # Found unknown categories ['Hydrogen'] in column 0 during transform

ohe = OneHotEncoder(drop="first", sparse_output=False, handle_unknown="ignore")
ohe.fit(pd.DataFrame({"fuel": ["Diesel", "Petrol", "CNG"]}))
print(ohe.transform(pd.DataFrame({"fuel": ["Hydrogen"]})))        # [[0. 0.]]  all zeros
```

With `handle_unknown="ignore"` the unknown category becomes an **all-zeros row**. Be aware that with `drop="first"` this is **indistinguishable from the dropped (reference) category**, so the model will treat "Hydrogen" as "CNG". Alternatives: group rare and unseen categories explicitly (`handle_unknown="infrequent_if_exist"` with `min_frequency`), keep all $K$ columns (no drop) so that all-zeros is a distinct "unknown" pattern, or retrain with the new category.

## 9.2 Missing values

`OneHotEncoder` treats `NaN` as its own category (so you get a `fuel_nan` column) in scikit-learn 0.24+. Choices:

- **Impute first** with the most frequent value (`SimpleImputer(strategy="most_frequent")`), or
- Keep a "Missing" category if missingness is informative (`SimpleImputer(strategy="constant", fill_value="Missing")`),
- With `pd.get_dummies`, use `dummy_na=True` to get an explicit NaN column.

```python
cat_pipe = Pipeline([("impute", SimpleImputer(strategy="constant", fill_value="Missing")),
                     ("ohe", OneHotEncoder(handle_unknown="ignore"))])
```

## 9.3 Sparse output and memory

By default `OneHotEncoder` returns a **sparse matrix** that stores only the 1s. With `sparse_output=False` you get a dense array. For many categories the difference is enormous:

```python
rng = np.random.default_rng(0)
big = pd.DataFrame({"city": rng.choice([f"city_{i}" for i in range(2000)], 100_000)})

sp = OneHotEncoder().fit_transform(big)                                         # sparse CSR matrix
sparse_bytes = sp.data.nbytes + sp.indices.nbytes + sp.indptr.nbytes
dense_bytes = 100_000 * 2000 * 8                                                # float64 dense equivalent
print(f"sparse: {sparse_bytes/1e6:.1f} MB | dense would be: {dense_bytes/1e9:.1f} GB")      # about 1.2 MB vs 1.6 GB
```

Keep it sparse for high cardinality and use models that accept sparse input (linear models, SVM, naive Bayes, random forests, gradient boosting, KNN). Convert with `.toarray()` only if the matrix is small. Combine sparse and dense blocks with `scipy.sparse.hstack` (or let `ColumnTransformer` handle it).

## 9.4 Binary features

```python
OneHotEncoder(drop="if_binary")          # binary features -> one 0/1 column; multi-category features keep all dummies
```

## 9.5 Dummy columns for numbers that are really categories

`pincode`, `zip`, `area_code`, `store_id`, and `day_of_week` stored as integers are categories, so encode them (convert to string first, or tell the encoder explicitly).

```python
df["pincode"] = df["pincode"].astype(str)
```

## 9.6 Order of columns and names

Columns appear in the order of `categories_` (alphabetical by default). Fix the order for reproducibility with `categories=[[...], [...]]`. Use `get_feature_names_out()` and `set_output(transform="pandas")` to keep names.

## 9.7 Interactions and many-to-many

- **Multi-label / multi-select columns** ("tags": `["sports", "tech"]`) are not one-hot; use `MultiLabelBinarizer` (section 11).
- **Interaction features** (brand x fuel) can be created by concatenating strings before encoding, but they multiply the cardinality.

# 10. When OHE is not enough: alternatives for high cardinality

|Method|Idea|Output size|Notes|
|---|---|---|---|
|**Top-N + "Other" grouping** (this note)|keep frequent, merge rare|N + 1|simple, robust, loses rare-category detail|
|**Frequency / count encoding**|replace a category by its frequency|1|no extra columns; categories with equal counts collide|
|**Target (mean) encoding**|replace a category by the mean target|1|powerful, but **must be cross-fitted** to avoid leakage (`sklearn.preprocessing.TargetEncoder`, scikit-learn 1.3+)|
|**Binary encoding**|store the category index in binary|$\log_2 K$|compact, introduces arbitrary shared bits|
|**Hashing** (`FeatureHasher`)|hash categories into a fixed number of buckets|fixed|handles unseen categories; collisions|
|**Embeddings**|learn a dense vector per category in a neural net|small|best for very high cardinality; needs more data|
|**Native categorical support**|the model handles categories (LightGBM, CatBoost, HistGradientBoosting)|none|no encoding needed|

These are covered in later notes. For now, remember: **OHE for low and moderate cardinality; group rare levels for moderate-to-high cardinality; use other encoders beyond that.**

## Use case 4: survey with multi-select answers

A respondent can pick several hobbies. A normal OHE assumes one category per row; use `MultiLabelBinarizer`:

```python

```

## Use case 5: time features

Day of week or hour of day can be one-hot encoded when the pattern is **irregular** (weekend spikes, lunch rush).

```python
dow = pd.Series(["Mon", "Tue", "Sat", "Sun", "Sat"], name="dow")

```

If the pattern is smooth and cyclical (temperature through the year), prefer sine and cosine features ([[11.Ordinal and Label Encoding]], section 8.6). One-hot treats Sunday and Monday as unrelated, losing adjacency, but gains flexibility.

## Use case 6: text as one-hot (bag of words)

# 12. Reference and practice

## 12.1 OHE vs the other encoders

||**One-Hot**|**Ordinal**|**Label**|
|---|---|---|---|
|For|nominal features|ordinal features|the target $y$|
|Output|$K$ (or $K-1$) binary columns|1 integer column|1 integer column|
|Implies order?|no|yes (intended)|irrelevant|
|Equal distances between categories?|yes ($\sqrt{2}$)|no (by rank)|n/a|
|Dimensionality|grows with $K$|unchanged|unchanged|
|Class|`OneHotEncoder` / `pd.get_dummies`|`OrdinalEncoder`|`LabelEncoder`|

## 12.2 Common mistakes

|Mistake|Consequence|Fix|
|---|---|---|
|Using integer codes for nominal features|invented order and distances|One-Hot|
|Keeping all $K$ dummies (plus intercept) in unregularised linear regression|dummy variable trap, singular matrix|`drop="first"`|
|Dropping a column for KNN / K-Means / SVM|distorts distances (reference at the origin)|keep all $K$|
|One-hot encoding a feature with thousands of categories|huge, sparse, overfit-prone matrix|group rare levels, or use another encoder|
|`pd.get_dummies` on train and test separately|mismatched columns|`OneHotEncoder` fitted on train|
|Encoding before splitting|leakage (category sets, frequent-group counts)|split first, fit on train|
|Computing top-frequent categories on all data|leakage|compute counts on the training set only|
|`handle_unknown="error"` in production|crash on a new category|`"ignore"` or `"infrequent_if_exist"`|
|`handle_unknown="ignore"` together with `drop="first"` without thinking|unknown category looks like the reference|group unseen categories or keep all columns|
|Forgetting that the dropped category is the **baseline**|misread coefficients|state the reference, choose it deliberately|
|Dense output for huge cardinality|memory error|keep the matrix sparse|
|Treating ID-like numbers (`pincode`) as numeric|meaningless order|convert to string and encode|
|Leaving `NaN` unhandled|stray `nan` column or errors|impute or mark as "Missing"|
|Losing column names|cannot interpret the model|`get_feature_names_out()` / `set_output("pandas")`|
|Not saving the fitted encoder|cannot reproduce at deployment|`joblib.dump` the whole pipeline|

## 12.4 Self-test

1. What problem does One-Hot Encoding solve, and for which type of data?
2. How many columns does OHE create for a feature with $K$ categories?
3. Why are one-hot vectors all equally distant from each other?
4. What is the dummy variable trap, and what linear relationship causes it?
5. Why does perfect multicollinearity break linear regression?
6. How does `drop="first"` fix it, and what does the dropped category become?
7. How do you interpret a dummy's coefficient in a model with a reference category?
8. Why should you not drop a column for KNN?
9. What is high cardinality, and why is it a problem for OHE?
10. Describe the top-frequent-categories strategy.
11. Why must the frequent-category counts come from the training data?
12. Why is `pd.get_dummies` avoided in production?
13. What do `drop`, `sparse_output`, `dtype`, and `handle_unknown` do in `OneHotEncoder`?
14. Why split the data before encoding?
15. What is `ColumnTransformer` for?

### Short answers

1. Converting **nominal** categories (no order) into numbers without inventing order.
2. $K$ columns ($K-1$ with `drop`).
3. They are orthonormal basis vectors: distance $\sqrt{2}$, dot product 0 for every pair.
4. With all $K$ dummies, $C_1 + \dots + C_K = 1$ in every row (equal to the intercept column), so the columns are linearly dependent.
5. $X^\top X$ becomes singular, so the coefficients are not uniquely determined (infinitely many solutions).
6. It removes one dummy; the dropped category is the **reference**, represented by all zeros.
7. As the difference in the expected outcome compared with the reference category (holding other features fixed).
8. Dropping puts the reference at the origin, making it appear closer (distance 1) than other categories are to each other (sqrt 2).
9. Many unique values (for example 32+ car brands); OHE creates many sparse columns, increasing memory and training time, and risking overfitting.
10. Keep categories above a frequency threshold, group the rest into `Uncommon`/`Other`, then one-hot encode.
11. Test information must not influence preprocessing (leakage), and the same rule must be applied to new data.
12. It remembers no mapping, so train, test, and production data can yield different columns.
13. Remove a dummy (avoid collinearity); return a dense array instead of sparse; output integer 0/1 instead of floats; handle categories unseen at fit time (ignore instead of error).
14. The encoder learns categories from data; fitting on all data leaks test information.
15. Applying different transformations (ordinal, one-hot, scaling) to different columns in a single, leakage-safe step (next lesson).

## 12.6 Glossary

|Term|Meaning|
|---|---|
|**One-Hot Encoding**|representing each category as a binary vector with a single 1|
|**Dummy variable**|one of the binary columns produced by OHE|
|**Dummy variable trap**|perfect collinearity when all $K$ dummies and an intercept are used|
|**Multicollinearity**|input features that are linearly dependent or strongly correlated|
|**Reference (baseline) category**|the dropped category, represented by all zeros|
|**Cardinality**|the number of distinct categories in a feature|
|**High cardinality**|very many categories (dozens to thousands)|
|**Infrequent / rare category**|a category with few observations, often grouped as `Uncommon` / `Other`|
|**Sparse matrix**|storage that records only non-zero entries|
|**Orthogonal**|at right angles; dot product 0 (one-hot vectors are mutually orthogonal)|
|**Unknown category**|a category not seen when the encoder was fitted|
|**Data leakage**|test information influencing training or preprocessing|
|**ColumnTransformer**|applies different preprocessing steps to different columns in one object|

- [ ] Checked cardinality (`nunique`, `value_counts`) and cleaned strings and typos

- [ ] **Split first**; fitted encoders and frequency thresholds on training data only
- [ ] High cardinality: grouped rare categories (or chose another encoder) and tuned the threshold
- [ ] Decided `drop` by model type (drop for unregularised linear models; keep all for KNN, K-Means, SVM)
- [ ] Chose the reference category deliberately when coefficients matter

- [ ] Put everything in a `Pipeline` / `ColumnTransformer` and saved the fitted pipeline

## Key takeaways

- **Nominal** categories (colour, gender, fuel, brand) have no order, so they need **One-Hot Encoding**: $K$ categories become $K$ binary columns, with a single 1 per row. The vectors are orthonormal, so every pair of categories is equally far apart ($\sqrt{2}$).
- **Dummy variable trap:** the $K$ dummies sum to 1 in every row, an exact linear relationship (equal to the intercept) that makes $X^\top X$ singular and linear-model estimates unstable. **Drop one column ($K-1$ encoding)**; the dropped category becomes the reference, and each coefficient measures the difference from it. No information is lost.
- Drop for **unregularised linear models**; **do not drop** for KNN, K-Means, or SVM (it distorts distances) and it is unnecessary for trees and neural networks.
- **High cardinality** (for example 32+ car brands) inflates dimensionality, memory, and training time. Use the **top-frequent-categories strategy**: keep categories above a threshold (such as 100 rows), group the rest as `Uncommon`, then encode. Learn the threshold counts from the **training** data only. `OneHotEncoder(min_frequency=...)` does this natively.
- **`pd.get_dummies`** is convenient for exploration (`columns=`, `drop_first=True`) but **remembers nothing**, so train and test columns can mismatch. **`OneHotEncoder`** stores category mappings at `fit()` and is the **production standard** (`drop`, `sparse_output`, `dtype`, `handle_unknown`).
- Workflow: **split first**, `fit_transform` on training columns, `transform` on test columns, then recombine with numerical features (`np.hstack` or, better, a `ColumnTransformer`). Manual slicing and re-stacking is verbose, which is why the next lesson introduces **`ColumnTransformer`**.
- Handle unknown categories, missing values, and sparse output deliberately, and consider target, frequency, hashing, or native-categorical approaches when cardinality gets very large.
