# 1. The problem: heterogeneous data needs different preprocessing

Real datasets mix **column types**, and each type needs its own treatment:

|Column type|Typical preprocessing|Tool|
|---|---|---|
|Numerical with missing values|impute (mean, median)|`SimpleImputer`|
|Numerical, features on different scales|scale|`StandardScaler`, `MinMaxScaler`|
|Numerical, already fine|leave as is|`passthrough`|
|Nominal categorical (gender, city)|one-hot encode|`OneHotEncoder` ([[12.One-Hot Encoding]])|
|Ordinal categorical (cough: mild < strong)|ordinal encode|`OrdinalEncoder` ([[11.Ordinal and Label Encoding]])|
|Text|vectorize|`TfidfVectorizer`|

A scikit-learn transformer such as `OneHotEncoder` or `StandardScaler` applies **one** operation to **whatever columns you give it**. If you give it the whole DataFrame, it tries to treat every column the same way (and fails on mixed types). So you must apply different transformers to different subsets of columns, and then **combine the results** into a single feature matrix for the model.

Doing this by hand is possible but **tedious, error-prone, and hard to maintain**. `ColumnTransformer` (from `sklearn.compose`) does the whole job in one object.

# 2. The demonstration dataset (COVID-19 patients)

The lecture uses a custom dataset with **100 rows** and **5 input features** (plus a target):

|Feature|Type|Needs|
|---|---|---|
|`age`|continuous numerical|nothing (pass through as is)|
|`gender`|nominal (Male / Female)|One-Hot Encoding|
|`fever`|continuous numerical, **10 missing values**|missing value imputation (`SimpleImputer`)|
|`cough`|ordinal (mild < strong)|Ordinal Encoding (`OrdinalEncoder`)|
|`city`|nominal (Kolkata, Bangalore, Delhi, Mumbai)|One-Hot Encoding|
|`has_covid`|target (Yes / No)|label encoding (not part of `X`)|

## Build a stand-in dataset

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
n = 100
df = pd.DataFrame({
    "age": rng.integers(5, 81, n),
    "gender": rng.choice(["Male", "Female"], n),
    "fever": rng.normal(100, 1.8, n).round(1),
    "cough": rng.choice(["mild", "strong"], n, p=[0.6, 0.4]),
    "city": rng.choice(["Kolkata", "Bangalore", "Delhi", "Mumbai"], n),
})
risk = (0.9 * (df["fever"] - 100) + 1.2 * (df["cough"] == "strong")
        + 0.02 * (df["age"] - 40) + rng.normal(0, 0.8, n))
df["has_covid"] = np.where(risk > 0.8, "Yes", "No")
df.loc[rng.choice(n, 10, replace=False), "fever"] = np.nan          # 10 missing fever readings

print(df.head())
print(df.isna().sum())                                               # fever: 10
```

(Use your own `covid_data.csv` through `pd.read_csv` if you have it.)

## Split first

```python
from sklearn.model_selection import train_test_split

X = df.drop(columns="has_covid")
y = df["has_covid"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)
print(X_train.shape, X_test.shape)                                   # (80, 5) (20, 5)
```

Transformers must be **fitted on training data only** and applied to the test data (data leakage rule, as with scalers and encoders).

# 3. The manual approach (without `ColumnTransformer`)

## 3.1 Five steps, and then all of it again for the test set

```python
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OrdinalEncoder, OneHotEncoder

# 1) Impute missing values in 'fever' with the mean
si = SimpleImputer(strategy="mean")
fever_train = si.fit_transform(X_train[["fever"]])
fever_test = si.transform(X_test[["fever"]])

# 2) Ordinal-encode 'cough' (mild -> 0, strong -> 1)
oe = OrdinalEncoder(categories=[["mild", "strong"]])
cough_train = oe.fit_transform(X_train[["cough"]])
cough_test = oe.transform(X_test[["cough"]])

# 3) One-hot-encode the nominal columns 'gender' and 'city' (drop first to avoid the dummy variable trap)
ohe = OneHotEncoder(drop="first", sparse_output=False)
gc_train = ohe.fit_transform(X_train[["gender", "city"]])
gc_test = ohe.transform(X_test[["gender", "city"]])

# 4) Extract the column that needs no change ('age')
age_train = X_train[["age"]].to_numpy()
age_test = X_test[["age"]].to_numpy()

# 5) Concatenate all pieces horizontally
X_train_manual = np.concatenate([age_train, fever_train, cough_train, gc_train], axis=1)
X_test_manual = np.concatenate([age_test, fever_test, cough_test, gc_test], axis=1)
print(X_train_manual.shape)          # (80, 7): age + fever + cough + gender(1) + city(3)
```

> **Version note:** the lecture's `OneHotEncoder(sparse=False)` was renamed `sparse_output=False` in scikit-learn 1.2, and the old `sparse` argument was removed in 1.4. Use `sparse_output=False` on current versions.

## 3.2 What goes wrong with the manual way

|Problem|Detail|
|---|---|
|**Many arrays**|each transformer returns its own NumPy array, losing column names|
|**Manual stacking**|`np.concatenate` order must be remembered by you|
|**Repetition**|every step is written twice (train and test)|
|**Easy to leak data**|one `fit_transform` on the test set (or on the full data) goes unnoticed|
|**Column order bugs**|if the order of columns in `X_test` differs, results are silently wrong|
|**Hard to scale**|with 30 columns and 8 transformers the code explodes|
|**Hard to deploy**|you must save and reload five separate fitted objects and replay the same stacking code|
|**Hard to cross-validate**|the preprocessing is outside the model, so `cross_val_score` cannot refit it per fold|

Notice also that the model never sees column names, so you cannot later say which array column was `city_Delhi`.

# 4. `ColumnTransformer`: the one-step approach

## 4.1 The idea

`ColumnTransformer` takes a **list of (name, transformer, columns)** triples. It applies **each transformer only to its own columns**, then **concatenates all outputs horizontally** into one feature matrix. It behaves like any scikit-learn transformer, with `fit`, `transform`, and `fit_transform`.

```
                   X (DataFrame with mixed columns)
                              |
        ---------------------------------------------------
        |               |                |                |
  ['fever']         ['cough']     ['gender','city']    remainder
  SimpleImputer   OrdinalEncoder   OneHotEncoder      ['age']
        |               |                |             passthrough
        v               v                v                v
   (n x 1)         (n x 1)          (n x 4)           (n x 1)
        \_______________\______________/_________________/
                              |
                     horizontal concatenation
                              |
                        X_transformed (n x 7)
```

## 4.2 The lecture example

```python
from sklearn.compose import ColumnTransformer

ct = ColumnTransformer(
    transformers=[
        ("trf1", SimpleImputer(), ["fever"]),
        ("trf2", OrdinalEncoder(categories=[["mild", "strong"]]), ["cough"]),
        ("trf3", OneHotEncoder(sparse_output=False, drop="first"), ["gender", "city"]),
    ],
    remainder="passthrough",
)

X_train_transformed = ct.fit_transform(X_train)      # learns on TRAIN and transforms TRAIN in one call
X_test_transformed = ct.transform(X_test)            # applies what was learned to TEST

print(X_train_transformed.shape, X_test_transformed.shape)       # (80, 7) (20, 7)
```

One object replaces about twenty lines of manual code.

### Verify it equals the manual result

`ColumnTransformer` orders the output as **each transformer in list order, then the remainder last**:

```python
X_train_manual_ordered = np.concatenate([fever_train, cough_train, gc_train, age_train], axis=1)
print(np.allclose(X_train_transformed, X_train_manual_ordered))          # True
```

(The earlier manual stack had `age` first; the content is the same, only the column order differs.)

## 4.3 The `transformers` list in detail

Each tuple has three parts:

|Part|Meaning|Example|
|---|---|---|
|**name**|a unique label (used for lookup, feature names, and hyperparameter tuning)|`"trf1"`, `"num"`, `"ohe"`|
|**transformer**|any scikit-learn transformer, a `Pipeline`, `"passthrough"`, or `"drop"`|`SimpleImputer()`|
|**columns**|which columns it receives: names, positions, slice, boolean mask, or selector|`["fever"]`, `[0, 2]`, `slice(1, 4)`|

The lecture's three transformers:

|Name|Transformer|Columns|Output columns|
|---|---|---|---|
|`trf1`|`SimpleImputer()` (mean by default)|`["fever"]`|1|
|`trf2`|`OrdinalEncoder(categories=[["mild", "strong"]])`|`["cough"]`|1|
|`trf3`|`OneHotEncoder(drop="first", sparse_output=False)`|`["gender", "city"]`|1 (gender) + 3 (city) = 4|

## 4.4 How it works internally

For each tuple in `transformers`:

1. **Select** the listed columns from `X` (by name, so the order of the columns in `X` does not matter when you use names).
2. **`fit`** the transformer on that sub-DataFrame (training data only).
3. **`transform`** it to get an array (or sparse matrix).

Then it **hstacks** all arrays in the order of the list, and appends the **remainder** columns last. On `transform` (test or new data) it repeats steps 1 and 3 using the already fitted transformers.

Because each transformer sees **only its own columns**, an encoder can never accidentally touch a numeric column, and a scaler can never touch a text column.

## 4.5 The `remainder` parameter (what happens to unlisted columns)

|Value|Behaviour|
|---|---|
|`"drop"` (**default**)|columns not mentioned are **silently discarded**|
|`"passthrough"`|unlisted columns are kept unchanged and **appended at the end**|
|a transformer|unlisted columns are processed with that transformer (for example `remainder=StandardScaler()`)|

The lecture sets `remainder="passthrough"` so that `age`, which needs no transformation, is not dropped.

```python
ct_drop = ColumnTransformer([("trf1", SimpleImputer(), ["fever"])])                      # default remainder="drop"
print(ct_drop.fit_transform(X_train).shape)                                              # (80, 1): everything else vanished!

ct_pass = ColumnTransformer([("trf1", SimpleImputer(), ["fever"])], remainder="passthrough")
print(ct_pass.fit_transform(X_train).shape)                                              # (80, 5)
```

> **Warning:** forgetting `remainder="passthrough"` is the classic source of "where did my columns go?" Always check the output shape.

## 4.6 Fitted attributes

```python
ct.transformers_                       # list of fitted (name, transformer, columns), including 'remainder'
ct.named_transformers_["trf3"].categories_      # access an individual fitted transformer by name
ct.named_transformers_["trf1"].statistics_      # the learned fever mean
ct.get_feature_names_out()             # names of every output column
ct.output_indices_                     # slices telling you which output columns belong to which transformer
ct.feature_names_in_                   # the input columns the transformer was fitted on
ct.n_features_in_
```

```python
print(ct.get_feature_names_out())
# ['trf1__fever' 'trf2__cough' 'trf3__gender_Male' 'trf3__city_Delhi' 'trf3__city_Kolkata'
#  'trf3__city_Mumbai' 'remainder__age']
```

Notes: `drop="first"` drops alphabetically-first categories (Female for gender; Bangalore for city), which become the reference categories ([[12.One-Hot Encoding]], section 3).

## 4.7 The shortcut: `make_column_transformer`

It names the transformers automatically (lowercased class names):

```python
from sklearn.compose import make_column_transformer

ct = make_column_transformer(
    (SimpleImputer(), ["fever"]),
    (OrdinalEncoder(categories=[["mild", "strong"]]), ["cough"]),
    (OneHotEncoder(sparse_output=False, drop="first"), ["gender", "city"]),
    remainder="passthrough",
)
```

Use the explicit `ColumnTransformer` when you need meaningful names, for example for hyperparameter search.

## 4.8 Apply the same fitted object everywhere

```python
new_patient = pd.DataFrame({"age": [34], "gender": ["Female"], "fever": [101.2], "cough": ["strong"], "city": ["Delhi"]})
ct.transform(new_patient)           # same columns, same encodings, same learned mean, no re-fitting
```

This is the point of `fit` once, `transform` many times: training, test, and production all go through the identical transformation.

# 5. Several steps per column group (sub-pipelines)

A single transformer is often not enough: you want to **impute and then scale** the numeric columns, or **impute and then one-hot encode** the categorical ones. Put a `Pipeline` inside the `ColumnTransformer`:

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

numeric_fever = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler()),
])

nominal = Pipeline([
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("ohe", OneHotEncoder(drop="first", handle_unknown="ignore", sparse_output=False)),
])

ct = ColumnTransformer([
    ("fever", numeric_fever, ["fever"]),
    ("age", StandardScaler(), ["age"]),
    ("cough", OrdinalEncoder(categories=[["mild", "strong"]]), ["cough"]),
    ("nominal", nominal, ["gender", "city"]),
])
```

Here every column is listed, so no remainder is needed (the default `drop` removes nothing).

**Order matters inside a sub-pipeline:** impute first, then scale (scaling statistics must not be computed with missing values), as established in the scaling notes.

# 6. Adding a model: `Pipeline` + `ColumnTransformer`

## 6.1 Preprocessing and model in one object

```python
from sklearn.linear_model import LogisticRegression

clf = Pipeline([
    ("prep", ct),
    ("model", LogisticRegression()),
])

y_train_bin = (y_train == "Yes").astype(int)
y_test_bin = (y_test == "Yes").astype(int)

clf.fit(X_train, y_train_bin)            # ct.fit_transform(X_train) happens inside, then the model is fitted
print("test accuracy:", clf.score(X_test, y_test_bin).round(3))

clf.predict(X_test)[:5]                  # raw, untransformed X_test goes in
clf.predict_proba(new_patient)
```

The `Pipeline` guarantees that **every preprocessing step is learned from the training data only** and applied identically at prediction time. (The target is encoded separately, here with a fixed mapping so that "Yes" is class 1; see [[11.Ordinal and Label Encoding]].)

## 6.2 Leakage-safe cross-validation

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(clf, X, (y == "Yes").astype(int), cv=5)
print(scores.mean().round(3), scores.std().round(3))
```

In every fold, the imputer mean, the encoder categories, and the scaler statistics are re-learned from that fold's training part only. That is impossible with the manual approach unless you rewrite the preprocessing inside your own loop.

## 6.3 Tuning preprocessing and model together

Hyperparameters are addressed with double underscores: `step__transformer__substep__parameter`.

```python
from sklearn.model_selection import GridSearchCV

param_grid = {
    "prep__fever__imputer__strategy": ["mean", "median"],
    "prep__nominal__ohe__drop": ["first", None],
    "model__C": [0.1, 1, 10],
}
grid = GridSearchCV(clf, param_grid, cv=5)
grid.fit(X_train, y_train_bin)
print(grid.best_params_, grid.best_score_.round(3))
print(clf.get_params().keys())                  # list every tunable name
```

Meaningful transformer names (`fever`, `nominal`) make these paths readable, which is why you should name them yourself.

## 6.4 Inspect the pipeline visually

```python
from sklearn import set_config
set_config(display="diagram")
clf                                    # in a notebook, shows a clickable diagram of the whole pipeline
```

## 6.5 Save and deploy the whole thing

```python
import joblib
joblib.dump(clf, "covid_model.joblib")          # imputer, encoders, scaler, and model together
loaded = joblib.load("covid_model.joblib")
loaded.predict(new_patient)
```

# 7. Selecting columns smartly

## 7.1 Ways to specify columns

|Specification|Example|Notes|
|---|---|---|
|list of names|`["fever", "age"]`|most readable; independent of column order|
|single string|`"review_text"`|passes a **1D** Series (needed for text vectorizers)|
|list of integers|`[0, 2]`|depends on position; fragile|
|slice|`slice(0, 3)`|positional|
|boolean mask|`[True, False, True, ...]`|rarely used directly|
|**callable / selector**|`make_column_selector(...)`|choose by dtype or name pattern|

## 7.2 `make_column_selector`

Select columns automatically by **dtype** or by a **regex on names**:

```python
from sklearn.compose import make_column_selector as selector

num_cols = selector(dtype_include=np.number)               # all numeric columns
cat_cols = selector(dtype_include=object)                  # all text columns (also "category", "string")
fever_like = selector(pattern="^fe")                       # names starting with 'fe'
all_but_age = selector(dtype_exclude=np.number)

ct = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")), ("sc", StandardScaler())]), num_cols),
    ("cat", OneHotEncoder(handle_unknown="ignore", sparse_output=False), cat_cols),
])
```

This is convenient on **wide datasets** with dozens of columns. The selectors are evaluated at `fit` time on the data you pass.

### Caution: one column, one transformer

A column selected by **two** transformers is processed twice and appears twice in the output. With selectors it is easy to overlap by accident (for example, a numeric-coded categorical column picked by both). Check with `get_feature_names_out()`, and when a column needs special treatment (like `cough`), list it explicitly and exclude it from the selectors.

```python
ordinal_cols = ["cough"]
nominal_cols = ["gender", "city"]
numeric_cols = ["age", "fever"]               # explicit lists are safest for smaller datasets
```

## 7.3 Whole-column operations with `FunctionTransformer`

Apply any function to selected columns (log transform, date parts, ratios):

```python
from sklearn.preprocessing import FunctionTransformer

log_tf = FunctionTransformer(np.log1p, feature_names_out="one-to-one")      # fix skewed columns

def date_parts(X):
    s = pd.to_datetime(pd.DataFrame(X).squeeze())
    return np.c_[s.dt.month, s.dt.dayofweek]

ct = ColumnTransformer([
    ("skew", Pipeline([("log", log_tf), ("sc", StandardScaler())]), ["income"]),
    ("date", FunctionTransformer(date_parts), ["signup_date"]),
])
```

Use a named function (not a lambda) so the pipeline can be saved with `joblib`.

# 8. The `remainder` parameter in depth

## 8.1 Three choices revisited

```python
ColumnTransformer([...], remainder="drop")           # default: unlisted columns vanish
ColumnTransformer([...], remainder="passthrough")    # unlisted columns appended unchanged, last
ColumnTransformer([...], remainder=StandardScaler()) # unlisted columns scaled
```

## 8.2 Where the remainder ends up

Always **after** every listed transformer, regardless of where the columns sat in the original DataFrame. In the lecture example `age` (the first column of the DataFrame) becomes the **last** column of the output. This matters when you later interpret model coefficients or feature importances: use `get_feature_names_out()` rather than assuming the original order.

## 8.3 Using remainder for a clean design

When most columns need the same treatment, list only the exceptions and let the remainder handle the rest:

```python
ct = ColumnTransformer(
    [("ord", OrdinalEncoder(categories=[["mild", "strong"]]), ["cough"]),
     ("nom", OneHotEncoder(drop="first", handle_unknown="ignore"), ["gender", "city"])],
    remainder=StandardScaler(),         # age and fever (anything left) get scaled
)
```

Risk: a new numeric column added later silently gets scaled and a new text column crashes. Be explicit for production pipelines.

## 8.4 Dropping on purpose

```python
ColumnTransformer([("keep", "passthrough", ["age"]), ("gone", "drop", ["patient_id"])])
```

`"drop"` as the transformer makes the intent explicit and documented.

# 9. Output format: names, DataFrames, sparse vs dense

## 9.1 Names with `verbose_feature_names_out`

By default each output name is prefixed by the transformer name (`trf3__city_Delhi`). To get clean names:

```python
ct = ColumnTransformer([...], remainder="passthrough", verbose_feature_names_out=False)
ct.fit(X_train)
print(ct.get_feature_names_out())      # ['fever' 'cough' 'gender_Male' 'city_Delhi' ...  'age']
```

Names must remain unique, so if two transformers would produce the same name, keep the prefixes.

## 9.2 Output as a DataFrame (scikit-learn 1.2+)

```python
ct = ColumnTransformer([...], remainder="passthrough", verbose_feature_names_out=False).set_output(transform="pandas")
X_train_df = ct.fit_transform(X_train)
X_train_df.head()                       # a DataFrame with named columns and the original index
```

Or set it globally: `sklearn.set_config(transform_output="pandas")`.

## 9.3 Sparse versus dense output

`ColumnTransformer` stacks the blocks and decides the format using `sparse_threshold` (default **0.3**): if the **overall density** of the result is **below 0.3**, it returns a **sparse matrix**; otherwise a dense array.

```python
ColumnTransformer([...], sparse_threshold=0)       # always dense
ColumnTransformer([...], sparse_threshold=1)       # sparse whenever any block is sparse
```

This is why the lecture sets `sparse=False` on the `OneHotEncoder` (to be sure of dense output), but a transformer with a high-cardinality one-hot block may still return sparse output depending on the final density. If a downstream step needs a dense array, set `sparse_threshold=0` or `sparse_output=False`.

## 9.4 Parallel and weighted

```python
ColumnTransformer([...], n_jobs=-1)                                 # fit the branches in parallel (helps with slow transformers)
ColumnTransformer([...], transformer_weights={"nom": 0.5})          # multiply a block's output by a weight (rarely used)
ColumnTransformer([...], verbose=True)                              # print timing per transformer
```

# 10. Debugging and common errors

|Symptom|Cause|Fix|
|---|---|---|
|Output has fewer columns than expected|default `remainder="drop"`|`remainder="passthrough"` or list the columns|
|`ValueError: A given column is not a column of the dataframe`|misspelled or missing column|check `X.columns`; names are case-sensitive|
|`ValueError: Found unknown categories` at `transform`|new category at prediction time|`handle_unknown="ignore"` on `OneHotEncoder` or fixed `categories`|
|`TypeError: __init__() got an unexpected keyword argument 'sparse'`|old `sparse=` removed in scikit-learn 1.4|use `sparse_output=False`|
|Column appears twice in the output|selected by two transformers|make the column lists disjoint|
|`ValueError: Expected 2D array, got 1D array`|passed a single string where the transformer wants 2D|use a list: `["fever"]`|
|A text vectorizer fails with a list|`TfidfVectorizer` needs 1D input|pass a **string**: `"review_text"`|
|NaN errors in the model|missing values left after the transformer|add a `SimpleImputer` in the numeric branch|
|Wrong feature names / order|assumed original order|use `get_feature_names_out()`|
|`LabelEncoder` inside `ColumnTransformer` fails|it is for the target only|use `OrdinalEncoder` or `OneHotEncoder` for features|
|Different results on train and test|accidentally called `fit_transform` on test|use `transform` only (or use a `Pipeline`)|
|Model breaks in production|input has different columns or dtypes|validate the schema; `ct.feature_names_in_` lists the expected names|

### Useful checks

```python
Xt = ct.fit_transform(X_train)
print(Xt.shape)                                         # expected number of columns?
print(pd.DataFrame(Xt, columns=ct.get_feature_names_out()).head())
print(pd.DataFrame(Xt, columns=ct.get_feature_names_out()).isna().sum().sum())      # 0 missing values after imputation?
```

A good habit: after building any `ColumnTransformer`, print the shape and the feature names and compare them with what you intended.

# 11. Use cases with code

## Use case 1: the Titanic dataset

```python
import seaborn as sns
from sklearn.ensemble import RandomForestClassifier

titanic = sns.load_dataset("titanic")
X = titanic[["age", "fare", "sibsp", "parch", "sex", "embarked", "pclass"]]
y = titanic["survived"]

pre = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")), ("sc", StandardScaler())]), ["age", "fare", "sibsp", "parch"]),
    ("cat", Pipeline([("imp", SimpleImputer(strategy="most_frequent")),
                      ("ohe", OneHotEncoder(handle_unknown="ignore"))]), ["sex", "embarked", "pclass"]),
])
model = Pipeline([("prep", pre), ("clf", RandomForestClassifier(random_state=0))])
print(cross_val_score(model, X, y, cv=5).mean().round(3))
```

(`pclass` is ordinal in meaning but one-hot encoding is fine for a tree; with a linear model compare it against the ordinal treatment.)

## Use case 2: house prices (numeric, nominal, ordinal, skewed)

```python
quality_order = ["Poor", "Fair", "Average", "Good", "Excellent"]

pre = ColumnTransformer([
    ("skewed", Pipeline([("imp", SimpleImputer(strategy="median")),
                         ("log", FunctionTransformer(np.log1p, feature_names_out="one-to-one")),
                         ("sc", StandardScaler())]), ["lot_area", "gr_liv_area"]),
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")), ("sc", StandardScaler())]), ["year_built", "bedrooms"]),
    ("quality", OrdinalEncoder(categories=[quality_order, quality_order],
                               handle_unknown="use_encoded_value", unknown_value=-1), ["kitchen_quality", "exterior_quality"]),
    ("nominal", OneHotEncoder(handle_unknown="infrequent_if_exist", min_frequency=20, drop="first"), ["neighborhood", "house_style"]),
])
```

One object handles skew (log), scale, order (ordinal), and cardinality (rare neighbourhoods grouped).

# 12. Comparisons: `ColumnTransformer` vs `Pipeline` vs `FeatureUnion`

```
Pipeline (series):         step 1  ->  step 2  ->  step 3  ->  model        (the whole data flows through each step)

ColumnTransformer (parallel branches by column):
                              +-- cols A -- transformer 1 --+
                    X  -------+-- cols B -- transformer 2 --+--> concatenate --> next step
                              +-- cols C -- transformer 3 --+
```

|Tool|What it does|Typical use|
|---|---|---|
|`Pipeline`|chains steps **in sequence**; each step's output is the next step's input|preprocessing then model|
|`ColumnTransformer`|applies **different transformers to different column subsets** and concatenates the results|heterogeneous tabular data|
|`FeatureUnion`|applies **several transformers to the same input** and concatenates|combining different feature extractions of the same columns (for example, PCA + selected features)|
|`pd.get_dummies` + manual concatenation|quick one-off|exploration only|

The three compose: the usual production structure is `Pipeline([("prep", ColumnTransformer([... sub-Pipelines ...])), ("model", estimator)])`, which is the topic of the next lesson.

## Manual vs `ColumnTransformer` summary

||Manual|`ColumnTransformer`|
|---|---|---|
|Lines of code|many, repeated for train and test|one object, `fit_transform` then `transform`|
|Column order|you manage it|defined and documented (transformers then remainder)|
|Feature names|lost|`get_feature_names_out()`|
|Leakage risk|high|low, especially inside a `Pipeline`|
|Cross-validation and grid search|cannot include preprocessing|preprocessing is tuned and validated with the model|
|Deployment|save many objects|save one object|
|Maintenance|brittle|change one line|

# 13. Reference and practice

## 13.1 Common mistakes

|Mistake|Consequence|Fix|
|---|---|---|
|Forgetting `remainder="passthrough"`|unlisted columns silently dropped|set it or list every column|
|Fitting on the full data before splitting|leakage|split first, or use a `Pipeline`|
|`fit_transform` on the test set|different statistics per split|`transform` only|
|Assuming the remainder keeps its original position|columns shuffled in interpretation|use `get_feature_names_out()`|
|Overlapping column lists or selectors|duplicated columns|make the lists disjoint|
|Passing `"col"` instead of `["col"]` to an encoder|1D vs 2D shape error|use a list for normal transformers; use a string only for text vectorizers|
|Using the old `sparse=False`|`TypeError` in scikit-learn 1.4+|`sparse_output=False`|
|Forgetting `handle_unknown` for production|crash on a new category|`handle_unknown="ignore"` (or group rare levels)|
|Imputing after scaling (order inside the sub-pipeline)|statistics computed with NaN or imputed values distorting them|impute, then scale|
|Using `LabelEncoder` on features|wrong tool|`OrdinalEncoder` / `OneHotEncoder`|
|Using positional indices that change when columns change|silent misalignment|use column names|
|Forgetting to save the fitted pipeline|cannot reproduce preprocessing|`joblib.dump` the full pipeline|
|Assuming the output is dense|errors in code expecting arrays|`sparse_threshold=0` or `sparse_output=False`|
|Tuning hyperparameters without naming the transformers meaningfully|unreadable parameter paths|name them (`"num"`, `"cat"`)|

### Short answers

1. Each transformer applies one operation to all the columns it receives, but columns of different types need different operations.
2. A name, a transformer (or `"passthrough"`/`"drop"`), and the columns it receives.
3. It concatenates them horizontally into a single feature matrix.
4. `"drop"` (unlisted columns are discarded); `"passthrough"` keeps them unchanged and appends them at the end.
5. Transformers in the order of the list, then the remainder columns.
6. Otherwise information from the test set leaks into preprocessing (means, categories, scaling statistics).
7. With the parameter path, for example `prep__fever__imputer__strategy` for a sub-pipeline step named `imputer` inside the transformer `fever` of the pipeline step `prep`.
8. `get_feature_names_out()`, optionally with `verbose_feature_names_out=False` or `set_output(transform="pandas")`.
9. For text vectorizers such as `TfidfVectorizer`, which expect 1D input.
10. `Pipeline` chains steps in sequence on all data; `ColumnTransformer` applies different transformers in parallel to different columns and joins the results.
11. The column is processed twice and appears twice in the output.
12. To return a dense array instead of a sparse matrix; `sparse_output=False` in scikit-learn 1.2+.
13. The preprocessing is re-fitted on each training fold, so there is no leakage, and preprocessing choices can be tuned together with the model.
14. `remainder="passthrough"` or an explicit `("keep", "passthrough", ["col"])` entry.

## 13.4 Cheat sheet

```python
from sklearn.compose import ColumnTransformer, make_column_selector as selector
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, OrdinalEncoder, StandardScaler

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)      # split first

ct = ColumnTransformer(
    transformers=[
        ("trf1", SimpleImputer(), ["fever"]),                                                  # (name, transformer, columns)
        ("trf2", OrdinalEncoder(categories=[["mild", "strong"]]), ["cough"]),
        ("trf3", OneHotEncoder(drop="first", sparse_output=False), ["gender", "city"]),
    ],
    remainder="passthrough",                    # keep 'age'; default is "drop"
    verbose_feature_names_out=False,
).set_output(transform="pandas")                # DataFrame output (scikit-learn 1.2+)

Xt_train = ct.fit_transform(X_train)            # fit on TRAIN
Xt_test = ct.transform(X_test)                  # transform only
ct.get_feature_names_out(); ct.named_transformers_["trf3"].categories_

model = Pipeline([("prep", ct), ("model", LogisticRegression())])
model.fit(X_train, y_train); cross_val_score(model, X, y, cv=5)
GridSearchCV(model, {"prep__trf1__strategy": ["mean", "median"], "model__C": [0.1, 1, 10]})
```

|Remember||
|---|---|
|Output order|transformers (in list order), then remainder|
|Unlisted columns|dropped unless `remainder="passthrough"`|
|Names in tuples|unique; use them for tuning|
|Text columns|pass as a string, not a list|
|Sparse|`sparse_threshold=0` forces dense|
|Always|split first, fit on train, check shape and names|

## 13.5 Glossary

|Term|Meaning|
|---|---|
|**ColumnTransformer**|applies different transformers to different column subsets and concatenates the results|
|**Transformer**|an object with `fit` and `transform` (imputer, scaler, encoder, custom class)|
|**Remainder**|columns not named in `transformers`|
|**Passthrough**|keep a column unchanged|
|**Pipeline**|a chain of steps applied in sequence, ending optionally in a model|
|**Heterogeneous data**|a dataset with columns of different types|
|**Data leakage**|test information influencing training or preprocessing|
|**Sparse matrix**|storage that records only the non-zero entries|
|**FunctionTransformer**|wraps an arbitrary function as a transformer|
|**Column selector**|a callable that picks columns by dtype or name pattern|
|**Hyperparameter path**|`step__substep__parameter` naming used in grid search|

## Key takeaways

- Real datasets mix column types that need different preprocessing (imputation, ordinal encoding, one-hot encoding, passing through). Applying transformers one by one produces **separate NumPy arrays** that you must stack by hand, which is tedious, error-prone, and repeated for the test set.
- **`ColumnTransformer`** (from `sklearn.compose`) takes a list of **(name, transformer, columns)** tuples, applies each transformer **only to its own columns**, and **concatenates the results horizontally**, all in one `fit_transform` (train) and one `transform` (test).
- Lecture example: `SimpleImputer` for `fever` (trf1), `OrdinalEncoder(categories=[['mild', 'strong']])` for `cough` (trf2), `OneHotEncoder(drop='first')` for `gender` and `city` (trf3), and `remainder='passthrough'` to keep `age`.
- **`remainder`** defaults to `"drop"`; `"passthrough"` appends untouched columns **at the end**. Check the output shape and use `get_feature_names_out()`.
- Use **sub-pipelines** for multi-step columns (impute, then scale or encode), `make_column_selector` for dtype-based selection, and `FunctionTransformer` for custom functions.
- Wrapping the transformer and the model in a **`Pipeline`** makes preprocessing **leakage-safe**, lets you **cross-validate and tune everything together** (`prep__trf1__strategy`), and lets you **save and deploy a single object**.
- On current scikit-learn use `sparse_output=False` (the lecture's `sparse=False` was removed in 1.4), and remember that `sparse_threshold` controls sparse versus dense output.
- Next up: **Pipelines**, which chain preprocessing and models into a single estimator.
