# Part A: Foundations

## A1. Where feature engineering sits in the ML lifecycle

```
Problem framing -> Data gathering -> Pre-processing & cleaning -> EDA -> [ FEATURE ENGINEERING ] -> Model training -> Evaluation -> Deployment & monitoring
 (this note's place)                                                         ^^^^^^^^^^^^^^^^^^^
```

It happens **after** you have collected, cleaned, and explored the data ([[05.Asking Basic Questions to a Dataset]], [[06.Univariate Analysis]], [[07.Bivariate and Multivariate Analysis]], [[08.Automated EDA]]) and **just before** you train a model. EDA tells you what is in the data; feature engineering decides what the model will actually see.

Every EDA finding becomes a feature engineering action:

|EDA finding|Feature engineering action|
|---|---|
|`Age` has 20% missing values|impute (plus a missing indicator)|
|`Fare` is strongly right-skewed|`log1p` / power transform|
|`SibSp` and `Parch` mostly zero, both relate to survival|construct `FamilySize`, `IsAlone`|
|`Name` is unique but contains titles|extract `Title`|
|`Sex` is text|one-hot encode|
|`Age` and `Fare` on different scales|scale (for distance and gradient-based models)|
|`PassengerId` is unique|drop|
|`Pclass` and `Fare` strongly correlated|consider selection|

## A2. Definition

**Feature engineering** is the process of using **domain knowledge** to extract or transform features (columns) from raw data so that machine learning algorithms perform better.

A **feature** is one input column the model uses to make predictions; the **target** is what it predicts. A model never sees "the real world", only the table of features you give it.

## A3. Art versus science

Feature engineering follows some rules (do not leak, fit on train only, encode text), but the **creative part** is an art:

- Different practitioners look at the same data and invent different features.
- The best features often come from **domain knowledge**: an insurance analyst knows which ratios matter, a retail analyst knows recency and frequency matter.
- It involves trial, evaluation, and iteration. You propose a feature, test whether it helps (cross-validation), and keep or discard it.

## A4. The golden rule

> A simple model with well-engineered features will often beat a powerful model trained on poorly prepared features.

Why? Garbage in, garbage out: the algorithm can only find patterns that are _expressible_ from its inputs. A good feature turns a hard problem into an easy one.

### Demonstration: area is what matters

```python
import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import cross_val_score

rng = np.random.default_rng(0)
n = 1000
plot = pd.DataFrame({"length": rng.uniform(5, 50, n), "width": rng.uniform(5, 50, n)})
plot["price"] = 100 * plot["length"] * plot["width"] + rng.normal(0, 2000, n)    # price depends on AREA

X_raw = plot[["length", "width"]]
X_eng = plot[["length", "width"]].assign(area=plot["length"] * plot["width"])
y = plot["price"]

def r2(model, X): return cross_val_score(model, X, y, cv=5, scoring="r2").mean().round(3)

print("Linear regression, raw features      :", r2(LinearRegression(), X_raw))      # mediocre
print("Linear regression, + area feature     :", r2(LinearRegression(), X_eng))      # near 1.0
print("Random forest (complex), raw features :", r2(RandomForestRegressor(random_state=0), X_raw))
```

The **simple** linear model with one constructed feature is far better than the same model on raw columns and competes with a far more complex model. A linear model cannot multiply columns by itself; you give it that ability through the feature.

### Nuances (stay honest)

- **Not always:** powerful models (gradient boosting, deep nets) can learn some interactions and non-linearities themselves, so the gap shrinks. Deep learning on images, audio, and text learns its own features ("representation learning").
- **Still true for tabular data:** most production models on tabular data win through data quality and features, not algorithm swaps.
- Model choice and feature engineering interact: trees do not need scaling, linear models and KNN do.

## A5. The four pillars

```
                          FEATURE ENGINEERING
        ┌──────────────┬───────────┴──────────┬─────────────────┐
        ▼              ▼                      ▼                 ▼
 Transformation   Construction            Selection         Extraction
 (change how an   (create new columns    (keep the best,   (project many
  existing column  by hand from domain    drop the rest)    columns into fewer
  is represented)  knowledge)                               new ones by algorithm)
```

|Pillar|Idea|Rows / columns effect|Who decides|Examples|
|---|---|---|---|---|
|**Transformation**|Change the **representation** of existing columns|same number of columns (or more after one-hot)|rules and statistics|impute, encode, scale, log, bin, handle outliers|
|**Construction**|**Create** new columns by hand|more columns|**you**, with domain knowledge|`FamilySize`, `Title`, price per square foot|
|**Selection**|**Choose a subset** of existing columns|fewer columns|statistics or a model|drop blank pixels, drop redundant columns|
|**Extraction**|**Compute new, fewer** columns from many|fewer columns, new meaning|**algorithms**|PCA, LDA|

### Key differences people confuse

|Pair|Difference|
|---|---|
|Construction vs extraction|Construction: you design the feature from domain intuition. Extraction: a mathematical algorithm derives it.|
|Selection vs extraction|Selection keeps original columns unchanged; extraction creates **new** columns that mix the originals.|
|Transformation vs construction|Transformation changes the form of **one** column; construction typically combines **several** or adds new information.|

## A6. The #1 rule: avoid data leakage

**Data leakage** is when information from outside the training data (the test set, or the future, or the target itself) leaks into your features. It produces great validation scores that collapse in production.

|Type|Example|Fix|
|---|---|---|
|**Train-test leakage**|computing the mean for imputation or the scaling parameters on the **whole** dataset|**fit** on the training set only, then **transform** the test set|
|**Target leakage**|a feature derived from the target (for example "refund issued" when predicting churn)|check each feature: would I know this at prediction time?|
|**Temporal leakage**|using future data to predict the past|split by time|
|**Group leakage**|the same customer in train and test|group-aware splitting|

Always wrap fitted steps in a scikit-learn **`Pipeline`** so cross-validation refits them for each fold:

```python
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale",  StandardScaler()),
    ("model",  LogisticRegression(max_iter=1000)),
])
# cross_val_score(pipe, X, y, cv=5) refits imputer and scaler inside every fold: no leakage.
```

**Stateless** operations (such as `a + b`, `log1p`, extracting a title from a name) do not learn anything from the data, so they can run before the split. **Stateful** operations (imputation, scaling, encoding categories, target encoding, PCA) must be fitted on training data only.

# Part B: Feature transformation

**Definition:** modifying an existing feature from its original format into a representation that models can process more effectively.

Five groups of tasks: **(1) missing values, (2) categorical variables and binning, (3) outliers, (4) scaling, (5) mathematical transforms.**

## B1. Missing value imputation

Most scikit-learn estimators cannot train on data with missing values (a few, such as `HistGradientBoosting*`, can). You must **drop** or **impute**.

### Step 1: understand the missingness (from [[05.Asking Basic Questions to a Dataset]])

```python
miss = df.isna().mean().mul(100).round(1)
miss[miss > 0].sort_values(ascending=False)      # Cabin 77.1, Age 19.9, Embarked 0.2
```

### Step 2: choose an approach

|Situation|Choice|
|---|---|
|Column mostly empty (above about 50 to 70%), little signal|drop the column, or keep only a "has value" flag|
|Very few rows affected (below about 5%)|drop those rows, or impute simply|
|Numeric, moderately missing|mean / median / group median / model-based|
|Categorical|most frequent (mode) or a new category "Missing"|
|Missingness itself informative|add a **missing indicator** column|

### Dropping

```python
df.dropna(axis=1, thresh=int(0.5 * len(df)))        # drop columns with more than 50% missing
df.dropna(subset=["Embarked"])                       # drop rows missing a key column
```

Dropping rows with `df.dropna()` on Titanic would throw away most of the data, because `Cabin` is almost always missing.

### Simple imputers (scikit-learn)

```python
from sklearn.impute import SimpleImputer

num_imp = SimpleImputer(strategy="median")              # or "mean"
cat_imp = SimpleImputer(strategy="most_frequent")       # mode, works for text
const_imp = SimpleImputer(strategy="constant", fill_value="Missing")

X_train[["Age"]] = num_imp.fit_transform(X_train[["Age"]])       # FIT on train only...
X_test[["Age"]]  = num_imp.transform(X_test[["Age"]])            # ...then transform test
```

|Strategy|Pros|Cons|
|---|---|---|
|**Mean**|simple; keeps the overall mean|pulled by outliers; shrinks variance|
|**Median**|robust to outliers and skew|still shrinks variance|
|**Mode**|works for categories|can over-represent the most common value|
|**Constant / "Missing"**|keeps the information that it was missing|needs the model to handle the new value|

### Missing indicator: keep the signal

```python
imp = SimpleImputer(strategy="median", add_indicator=True)     # adds a 0/1 column marking imputed rows
imp.fit_transform(X_train[["Age"]])[:5]
```

Useful when "missing" carries meaning (for example, `Cabin` missing mostly for lower-class passengers).

### Group-wise imputation (often better)

```python
# Median age within each class and sex, computed from the training set only
group_median = X_train.groupby(["Pclass", "Sex"])["Age"].median()

def impute_age(frame):
    out = frame.copy()
    fill = out.set_index(["Pclass", "Sex"]).index.map(group_median)
    out["Age"] = out["Age"].fillna(pd.Series(fill, index=out.index))
    return out
```

Imputing with a typical value for a similar group preserves structure better than one global median.

### Model-based imputation

```python
from sklearn.impute import KNNImputer
from sklearn.experimental import enable_iterative_imputer      # required to unlock the next import
from sklearn.impute import IterativeImputer

num = ["Age", "Fare", "SibSp", "Parch", "Pclass"]
KNNImputer(n_neighbors=5).fit_transform(X_train[num])            # uses the most similar rows
IterativeImputer(random_state=0).fit_transform(X_train[num])     # predicts each column from the others
```

Slower and more complex; try them when simple methods leave obvious gaps, and check the gain with cross-validation.

### Check what imputation does to the distribution

Imputation can distort shape (a median fill creates a spike) and shrink variance. Compare histograms before and after ([[06.Univariate Analysis]], section E2).

## B2. Handling categorical variables

Scikit-learn models compute with numbers, so text categories must be converted.

### Know the variable type first

|Type|Examples|Encoding approach|
|---|---|---|
|**Nominal** (no order)|`Sex`, `Embarked`, country|one-hot, frequency, target encoding|
|**Ordinal** (ordered)|`Pclass`, size S/M/L, education|ordinal encoding with explicit order|
|**Binary**|yes/no|0/1|
|**High cardinality**|`Ticket`, zip code, city|frequency, target (with care), hashing, grouping rare labels|

### One-hot encoding

Turns each category into its own 0/1 column.

```python
from sklearn.preprocessing import OneHotEncoder

ohe = OneHotEncoder(sparse_output=False, handle_unknown="ignore")
ohe.fit(X_train[["Sex", "Embarked"]].fillna("Missing"))
encoded = ohe.transform(X_test[["Sex", "Embarked"]].fillna("Missing"))
print(ohe.get_feature_names_out())
# ['Sex_female' 'Sex_male' 'Embarked_C' 'Embarked_Missing' 'Embarked_Q' 'Embarked_S']
```

|Sex|Sex_female|Sex_male|
|---|---|---|
|male|0|1|
|female|1|0|

- `handle_unknown="ignore"` prevents an error if the test set has a category unseen in training.
- `drop="first"` removes one column per feature to avoid the **dummy variable trap** (perfect collinearity), which matters for plain linear regression, but is optional for regularised models and trees.
- In pandas: `pd.get_dummies(df, columns=["Sex", "Embarked"], drop_first=True)`. It is fine for exploration but easy to misuse between train and test; prefer the scikit-learn encoder inside a pipeline.
- Older scikit-learn versions used `sparse=False`; the argument is now `sparse_output=False`.

### Ordinal encoding

```python
from sklearn.preprocessing import OrdinalEncoder

sizes = pd.DataFrame({"size": ["S", "L", "M", "S", "XL"]})
enc = OrdinalEncoder(categories=[["S", "M", "L", "XL"]])      # you define the order
enc.fit_transform(sizes)                                       # S=0, M=1, L=2, XL=3
```

Use it **only** when the order is real. Encoding nominal categories as 0, 1, 2 tells a linear or distance-based model that "Southampton is twice Cherbourg", which is false.

### `LabelEncoder` is for the target

```python
from sklearn.preprocessing import LabelEncoder
LabelEncoder().fit_transform(["cat", "dog", "cat"])           # for y, not for X features
```

### Frequency (count) encoding

```python
freq = X_train["Ticket"].value_counts(normalize=True)
X_train["Ticket_freq"] = X_train["Ticket"].map(freq)
X_test["Ticket_freq"] = X_test["Ticket"].map(freq).fillna(0)       # unseen tickets get 0
```

Compact for high-cardinality columns; assumes frequency is informative.

### Target encoding (powerful and dangerous)

Replaces a category with the average target for that category. Leaks easily if done naively.

```python
from sklearn.preprocessing import TargetEncoder        # scikit-learn 1.3 and later

te = TargetEncoder(random_state=0)                      # internally uses cross-fitting to limit leakage
te.fit_transform(X_train[["Embarked"]].fillna("Missing"), y_train)
```

Always do it inside cross-validation folds (a pipeline does this), and use smoothing for rare categories.

### Choosing quickly

|Cardinality|Preferred|
|---|---|
|2|binary 0/1|
|3 to about 15|one-hot|
|ordered|ordinal with defined order|
|15 to hundreds|group rare labels then one-hot, or frequency / target encoding|
|thousands|target encoding, hashing, embeddings|

Tree-based models can work with ordinal codes for nominal data, but linear and distance-based models cannot.

## B3. Binning (discretisation)

Converting a continuous variable into groups.

```python
df["AgeGroup"] = pd.cut(df["Age"], bins=[0, 12, 18, 60, 120],
                        labels=["Child", "Teen", "Adult", "Senior"])      # custom, meaningful edges
df["FareBand"] = pd.qcut(df["Fare"], q=4, labels=["Low", "Mid", "High", "Top"])   # equal-frequency bands
df["AgeGroup"].value_counts()
```

As a transformer:

```python
from sklearn.preprocessing import KBinsDiscretizer, Binarizer

kb = KBinsDiscretizer(n_bins=5, encode="ordinal", strategy="quantile")      # also "uniform", "kmeans"
kb.fit_transform(X_train[["Fare"]].fillna(0))

Binarizer(threshold=0).fit_transform(X_train[["Fare"]].fillna(0))           # 0/1: zero vs non-zero
```

|Strategy|Meaning|Use|
|---|---|---|
|`uniform`|equal-width bins|evenly spread data|
|`quantile`|equal-count bins|skewed data (robust to outliers)|
|`kmeans`|bins from 1D clustering|natural groupings|
|custom edges|domain thresholds (18 = adult, 65 = senior)|**best** when domain rules exist|

**Why bin?**

- capture non-linear effects in linear models (survival differs sharply for children);
- reduce the impact of outliers and noise;
- make a feature interpretable (age groups for reporting);
- handle messy, rounded measurements.

**Costs:** you lose information inside each bin and add arbitrary cut points. Trees do their own binning, so they rarely need it.

## B4. Outlier detection and handling

An **outlier** is a value far from the rest. Methods in detail: [[06.Univariate Analysis]], section D4.

### Why outliers matter: they distort some models

```python
rng = np.random.default_rng(1)
x = np.arange(50, dtype=float)
y = 2 * x + rng.normal(0, 3, 50)

slope_clean = np.polyfit(x, y, 1)[0]
y_out = y.copy(); y_out[-1] = 400               # one extreme value (like a mark of 98 when others are near 50)
slope_out = np.polyfit(x, y_out, 1)[0]
print(round(slope_clean, 2), "->", round(slope_out, 2))     # one point visibly tilts the line
```

Linear regression minimises squared error, so a single extreme point pulls the whole line toward itself. KNN, k-means, and anything built on distances or means is also sensitive.

|Model family|Sensitivity to outliers|
|---|---|
|Linear / logistic regression, SVM, k-means, KNN, PCA|high|
|Neural networks|moderate (depends on scaling)|
|Decision trees, random forests, gradient boosting|low (they split on order)|

### Detect

```python
def iqr_bounds(s, k=1.5):
    q1, q3 = s.quantile([0.25, 0.75])
    iqr = q3 - q1
    return q1 - k * iqr, q3 + k * iqr

low, high = iqr_bounds(X_train["Fare"])
mask = (X_train["Fare"] < low) | (X_train["Fare"] > high)
print(mask.sum(), "outlier fares")

z = (X_train["Age"] - X_train["Age"].mean()) / X_train["Age"].std()
(z.abs() > 3).sum()
```

### Handle

|Method|How|When|
|---|---|---|
|**Remove**|drop the rows|clear errors; plenty of data; only on the **training** set|
|**Cap (winsorise)**|clip to percentile or IQR bounds|real but extreme values|
|**Transform**|`log1p`, Box-Cox, Yeo-Johnson|skewed data with a long tail|
|**Flag**|add `is_outlier`|the outlier status is informative (VIPs, fraud)|
|**Robust model / scaler**|trees, `RobustScaler`|when you want to keep them|

```python
lo, hi = X_train["Fare"].quantile([0.01, 0.99])
X_train["Fare_capped"] = X_train["Fare"].clip(lo, hi)
X_test["Fare_capped"] = X_test["Fare"].clip(lo, hi)           # use the TRAIN bounds on test data
```

**Important:** the simple rule "remove all outliers before training" is not always right. Outliers can be the most valuable rows (fraud, rare failures, first-class suites). Investigate the cause first (error, different population, genuine extreme), then decide. Never delete test-set rows to improve your score.

## B5. Feature scaling

Features with very different ranges (age in tens, salary in tens of thousands) can dominate models that use distances or gradients.

### Why: KNN example

Distance between two people (age 25, salary 50,000) and (age 60, salary 51,000): the salary gap of 1,000 swamps the age gap of 35, so KNN effectively ignores age.

```python
from sklearn.datasets import load_wine
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler

Xw, yw = load_wine(return_X_y=True)                   # features range from about 0.1 to over 1000
knn = KNeighborsClassifier()
print("unscaled:", cross_val_score(knn, Xw, yw, cv=5).mean().round(3))
print("scaled  :", cross_val_score(Pipeline([("s", StandardScaler()), ("m", knn)]), Xw, yw, cv=5).mean().round(3))
```

Scaling typically produces a large accuracy gain on a dataset like this, where one feature (proline) is orders of magnitude larger than the rest.

### The scalers

|Scaler|Formula|Result|Notes|
|---|---|---|---|
|**StandardScaler** (standardisation, z-score)|`(x - mean) / std`|mean 0, std 1 (no fixed bounds)|the default for most models; assumes nothing about shape but sensitive to outliers|
|**MinMaxScaler** (normalisation)|`(x - min) / (max - min)`|range 0 to 1 (or set `feature_range=(-1, 1)`)|keeps shape; very sensitive to outliers; good for images and bounded inputs|
|**RobustScaler**|`(x - median) / IQR`|centred on the median|**outlier-resistant**|
|**MaxAbsScaler**|`x / max(abs(x))`|range -1 to 1|keeps sparsity; good for sparse data|
|**Normalizer**|scales each **row** to unit length|row norm = 1|text and cosine-similarity work; not column scaling|

```python
from sklearn.preprocessing import StandardScaler, MinMaxScaler, RobustScaler

num = ["Age", "Fare"]
data = X_train[num].fillna(X_train[num].median())

for name, sc in {"standard": StandardScaler(), "minmax": MinMaxScaler(), "robust": RobustScaler()}.items():
    out = pd.DataFrame(sc.fit_transform(data), columns=num)
    print(f"{name:9s}", out.describe().loc[["mean", "std", "min", "max"]].round(2).to_dict("index"))
```

### Which models need scaling?

|Needs scaling|Why|
|---|---|
|KNN, SVM, k-means, PCA|distance or variance based|
|Linear / logistic regression with regularisation|penalty depends on coefficient size|
|Neural networks, gradient descent|faster, stabler convergence|
|**Does not need it:** decision trees, random forest, gradient boosting|split on order, unaffected by monotonic scaling|

### Rules

- **Fit on train, transform test** (pipeline).
- Scaling changes the **scale, not the shape**. A skewed column stays skewed after standardising; use a transform for shape.
- Do not scale one-hot or binary columns unless a model requires it.
- Choose `StandardScaler` by default, `MinMaxScaler` for bounded or neural inputs, `RobustScaler` when outliers remain.

## B6. Mathematical transformations

Reshape distributions, especially skewed ones ([[06.Univariate Analysis]], section D3).

```python
from sklearn.preprocessing import FunctionTransformer, PowerTransformer, QuantileTransformer

fare = X_train["Fare"]
print("skew raw     :", round(fare.skew(), 2))                            # about 4.8
print("skew log1p   :", round(np.log1p(fare).skew(), 2))
print("skew sqrt    :", round(np.sqrt(fare).skew(), 2))

PowerTransformer(method="yeo-johnson").fit_transform(fare.to_frame())      # chooses the best power; handles zeros
PowerTransformer(method="box-cox").fit_transform((fare + 1).to_frame())    # positive values only
QuantileTransformer(output_distribution="normal", random_state=0).fit_transform(fare.to_frame())
log_tf = FunctionTransformer(np.log1p, feature_names_out="one-to-one")     # reusable step in a pipeline
```

|Transform|For|Note|
|---|---|---|
|`log` / `log1p`|right skew, multiplicative data (income, prices)|`log1p` safe for 0|
|`sqrt`|counts, moderate skew|gentler|
|reciprocal `1/x`|very strong skew|reverses order|
|square, cube|left skew|rare|
|**Box-Cox**|positive data; learns the best power|needs x > 0|
|**Yeo-Johnson**|any real values|the safe default|
|**Quantile transform**|forces any shape toward normal or uniform|robust, but distorts distances between values|

Linear models, KNN, and neural nets benefit; trees do not need them. Always compare via cross-validation instead of assuming.

# Part C: Feature construction

**Definition:** manually creating new features from existing columns, using domain knowledge, intuition, or EDA findings. This is where the "art" lives and where the biggest gains usually come from.

## C1. The Titanic example: `Family_Size`

`SibSp` (siblings/spouses) and `Parch` (parents/children) each mean little alone, but together they describe the passenger's **family**.

```python
df["Family_Size"] = df["SibSp"] + df["Parch"]                 # relatives aboard (alone = 0)
# Alternative convention: + 1 to count the passenger too (alone = 1)

df["Family_Type"] = pd.cut(df["Family_Size"], bins=[-1, 0, 4, np.inf],
                           labels=["Alone", "Small_Family", "Large_Family"])
df.groupby("Family_Type", observed=True)["Survived"].agg(["mean", "count"]).round(3)
```

|Family_Type|Meaning|Survival|
|---|---|---|
|Alone|no relatives (size 0)|about 30%|
|Small_Family|1 to 4 relatives|about 50% to 60%|
|Large_Family|more than 4|about 16%|

Check the pattern: survival is **not a straight line** in family size (small families fared best, singles and very large families worse). Binning captured that non-linearity; a model using raw `SibSp` and `Parch` separately would struggle to express it.

```python
df["IsAlone"] = (df["Family_Size"] == 0).astype(int)
```

## C2. More Titanic features

```python
# Title from Name: "Braund, Mr. Owen Harris" -> "Mr"
df["Title"] = df["Name"].str.extract(r",\s*([^\.]+)\.", expand=False).str.strip()
title_map = {"Mlle": "Miss", "Ms": "Miss", "Mme": "Mrs", "Lady": "Rare", "Countess": "Rare", "Sir": "Rare",
             "Don": "Rare", "Dona": "Rare", "Jonkheer": "Rare", "Capt": "Rare", "Col": "Rare",
             "Major": "Rare", "Dr": "Rare", "Rev": "Rare"}
df["Title"] = df["Title"].replace(title_map)           # fixed mapping: stateless, no leakage

df["HasCabin"] = df["Cabin"].notna().astype(int)
df["Deck"] = df["Cabin"].str[0].fillna("U")
df["TicketGroupSize"] = df.groupby("Ticket")["Ticket"].transform("count")      # people sharing a ticket
df["FarePerPerson"] = df["Fare"] / (df["TicketGroupSize"])
df["Age_x_Class"] = df["Age"] * df["Pclass"]                                   # interaction
df["NameLength"] = df["Name"].str.len()
```

`Title` quietly encodes sex, age (Master = boy), and marital status. `FarePerPerson` fixes the fact that group tickets inflate `Fare` (the 512.33 fares).

## C3. Families of construction techniques

|Technique|Example|Code idea|
|---|---|---|
|**Arithmetic combination**|`Family_Size = SibSp + Parch`|`a + b`|
|**Ratios**|price per square foot, debt-to-income, click-through rate|`a / b` (guard against zero)|
|**Differences**|days since last order, age at signup|`a - b`|
|**Interactions**|`age * class`, `bill * party size`|`a * b` or `PolynomialFeatures`|
|**Polynomials**|`x**2` for curved relations|`PolynomialFeatures(degree=2)`|
|**Aggregations**|customer's average order value, orders per month|`groupby(...).transform("mean")`|
|**Counts and flags**|has cabin, is weekend, number of items|`notna()`, comparisons|
|**Text-derived**|title, string length, word counts, contains a keyword|`.str` methods, TF-IDF|
|**Date-derived**|year, month, weekday, hour, is_holiday, days since event|`.dt` accessor|
|**Binning / grouping**|age groups, family types|`pd.cut`, `qcut`|
|**Geographic**|distance to city centre, region|haversine formula|
|**Domain formulas**|BMI = weight / height squared|domain knowledge|
|**Lags and rolling** (time series)|last week's sales, 7-day average|`shift`, `rolling`|

### Interaction and polynomial terms automatically

```python
from sklearn.preprocessing import PolynomialFeatures

PolynomialFeatures(degree=2, include_bias=False).fit_transform(X_train[["Age", "Fare"]].fillna(0))
# columns: Age, Fare, Age^2, Age*Fare, Fare^2
PolynomialFeatures(degree=2, interaction_only=True, include_bias=False)      # only products, no squares
```

The number of features explodes with degree and column count, so use sparingly and follow with selection.

### Date and time features

```python
rng = np.random.default_rng(0)
orders = pd.DataFrame({"ts": pd.Timestamp("2024-01-01") + pd.to_timedelta(rng.integers(0, 365 * 24, 1000), unit="h")})
orders["year"] = orders["ts"].dt.year
orders["month"] = orders["ts"].dt.month
orders["weekday"] = orders["ts"].dt.dayofweek
orders["hour"] = orders["ts"].dt.hour
orders["is_weekend"] = (orders["weekday"] >= 5).astype(int)
orders["days_since_start"] = (orders["ts"] - orders["ts"].min()).dt.days

# Cyclical encoding: hour 23 is close to hour 0
orders["hour_sin"] = np.sin(2 * np.pi * orders["hour"] / 24)
orders["hour_cos"] = np.cos(2 * np.pi * orders["hour"] / 24)
```

Cyclical features (hour, weekday, month) should be encoded with sine and cosine, otherwise the model thinks 23 and 0 are far apart.

### Aggregation features

```python
shop = pd.DataFrame({"customer": ["a", "a", "b", "b", "b", "c"], "amount": [10, 30, 5, 5, 20, 100]})
shop["cust_avg"] = shop.groupby("customer")["amount"].transform("mean")
shop["cust_orders"] = shop.groupby("customer")["amount"].transform("count")
shop["amount_vs_avg"] = shop["amount"] / shop["cust_avg"]
```

Compute aggregates on **training data** (or only past data in time series); aggregates that include the current row's target are leakage.

## C4. Domain-driven examples

|Domain|Raw columns|Constructed features|
|---|---|---|
|**E-commerce**|order dates, amounts|**RFM**: recency (days since last order), frequency (orders per period), monetary (total spent); average order value; discount share|
|**Real estate**|rooms, washrooms, plot size, price|total area, rooms per area, price per square foot, house age|
|**Healthcare**|height, weight|BMI = weight / height squared|
|**Banking**|income, loan, debts|debt-to-income ratio, utilisation rate, payments late in last 6 months|
|**Telecom churn**|usage per month|change in usage vs last quarter, support calls per month|
|**Transport**|pickup/dropoff coordinates, time|trip distance, hour of day, rush-hour flag|
|**Logistics**|order time, delivery time|delivery duration, late flag|
|**Text**|review text|length, number of exclamation marks, sentiment score|
|**Sensors**|readings over time|rolling mean, rolling std, rate of change|

### RFM from a transaction table

```python
tx = pd.DataFrame({
    "customer": ["a", "a", "a", "b", "b", "c"],
    "date": pd.to_datetime(["2024-01-05", "2024-02-10", "2024-03-01", "2024-01-20", "2024-03-15", "2023-12-01"]),
    "amount": [50, 70, 30, 200, 150, 20],
})
snapshot = pd.Timestamp("2024-04-01")
rfm = tx.groupby("customer").agg(
    recency=("date", lambda d: (snapshot - d.max()).days),
    frequency=("date", "count"),
    monetary=("amount", "sum"),
)
rfm["avg_order"] = rfm["monetary"] / rfm["frequency"]
rfm
```

Customer-level features like these are usually far more predictive of churn or lifetime value than the raw transaction rows.

## C5. How to find good features

1. **Start with EDA findings:** skew, non-linear patterns, interactions, group differences ([[07.Bivariate and Multivariate Analysis]]).
2. **Talk to domain experts:** ask what they look at when they judge a case by hand.
3. **Ask "what would a human use?":** ratios, differences, rates, "has/has not".
4. **Look at model errors:** where does the model fail? Which feature would explain those cases?
5. **Test every feature:** keep it only if cross-validated performance improves (or the model becomes simpler at the same score).
6. **Respect availability:** the feature must be known **at prediction time**.

### A caution on "too many ideas"

Each new feature adds noise and risk of overfitting. Test in small batches, keep a log of what helped, and prune with selection (Part D).

# Part D: Feature selection

**Definition:** choosing the most relevant subset of existing features and dropping the uninformative or redundant ones, to improve **speed, accuracy, and interpretability**.

## D1. Why select features?

|Reason|Explanation|
|---|---|
|**Faster training and inference**|fewer columns, less computation|
|**Less overfitting**|irrelevant features give the model more ways to memorise noise|
|**Better accuracy** (sometimes)|removing noise helps, especially for small datasets|
|**Interpretability**|fewer features are easier to explain|
|**Lower cost**|less data to collect, store, and maintain|
|**Curse of dimensionality**|in high dimensions, data becomes sparse and distances lose meaning|

## D2. The MNIST example: blank border pixels

MNIST images are 28 x 28 pixels, giving **784** pixel features. The outer border is almost always blank, so those pixels have no predictive signal. Keeping only informative pixels reduces dimensions and training time.

Scikit-learn's smaller **digits** dataset (8 x 8 = 64 pixels, 1,797 images) shows the same idea quickly:

```python
from sklearn.datasets import load_digits
from sklearn.feature_selection import VarianceThreshold
from sklearn.ensemble import RandomForestClassifier

Xd, yd = load_digits(return_X_y=True)
print(Xd.shape)                                           # (1797, 64)

vt = VarianceThreshold(threshold=0.0)                     # drop columns that never change
Xd_sel = vt.fit_transform(Xd)
print("kept:", Xd_sel.shape[1], "of", Xd.shape[1])        # a few always-blank pixels removed

# Show pixel variance as an image: dark = uninformative
plt.imshow(Xd.var(axis=0).reshape(8, 8), cmap="viridis"); plt.colorbar(label="variance"); plt.title("Pixel variance"); plt.show()

rf = RandomForestClassifier(n_estimators=100, random_state=0)
print("all pixels :", cross_val_score(rf, Xd, yd, cv=5).mean().round(3))
print("selected   :", cross_val_score(rf, Xd_sel, yd, cv=5).mean().round(3))
```

The same technique on full MNIST (`fetch_openml("mnist_784", as_frame=False)`) removes a large share of the 784 columns with little or no accuracy loss. You can also keep only the **top-k pixels by variance or importance**.

```python
top = np.argsort(Xd.var(axis=0))[-40:]                    # 40 most variable pixels
cross_val_score(rf, Xd[:, top], yd, cv=5).mean().round(3)
```

## D3. Three families of selection methods

```
FILTER      score each feature on its own with a statistic, keep the best     (fast, model-agnostic)
WRAPPER     try subsets, train a model each time, keep the best subset         (accurate, slow)
EMBEDDED    selection happens inside model training (L1, tree importance)      (balanced)
```

### 1. Filter methods

|Method|Feature type to target|Idea|
|---|---|---|
|**Variance threshold**|any|drop constant or near-constant features|
|**Correlation filter**|numeric vs numeric|drop features highly correlated with each other (redundant) or uncorrelated with the target|
|**ANOVA F-test** (`f_classif`)|numeric feature, categorical target|do group means differ?|
|**Chi-square** (`chi2`)|non-negative / categorical feature, categorical target|is the feature independent of the target?|
|**Mutual information**|any (captures non-linear)|how much does knowing the feature reduce uncertainty about the target?|
|**Missing-rate filter**|any|drop columns with excessive missing values|

```python
from sklearn.feature_selection import SelectKBest, f_classif, mutual_info_classif, chi2

num_cols = ["Age", "Fare", "SibSp", "Parch", "Pclass"]
Xn = X_train[num_cols].fillna(X_train[num_cols].median())

scores = pd.DataFrame({
    "F-score": f_classif(Xn, y_train)[0],
    "mutual_info": mutual_info_classif(Xn, y_train, random_state=0),
}, index=num_cols).round(3).sort_values("mutual_info", ascending=False)
scores

SelectKBest(score_func=mutual_info_classif, k=3).fit(Xn, y_train).get_support()    # boolean mask of kept columns
```

Remove highly correlated pairs:

```python
def drop_correlated(frame, threshold=0.9):
    corr = frame.corr().abs()
    upper = corr.where(np.triu(np.ones(corr.shape), k=1).astype(bool))
    return [c for c in upper.columns if (upper[c] > threshold).any()]
drop_correlated(Xn, 0.8)
```

**Variance inflation factor (VIF)** is another multicollinearity check (see [[07.Bivariate and Multivariate Analysis]], E7).

Filter weakness: each feature is judged **alone**, so it can discard features that only help in combination.

### 2. Wrapper methods

Use a model to evaluate subsets of features.

|Method|How|
|---|---|
|**Forward selection**|start empty; add the feature that improves the score most; repeat|
|**Backward elimination**|start with all; remove the least useful; repeat|
|**Recursive feature elimination (RFE)**|fit a model, drop the weakest features by coefficient or importance, repeat|

```python
from sklearn.feature_selection import RFE, SequentialFeatureSelector
from sklearn.linear_model import LogisticRegression

lr = LogisticRegression(max_iter=1000)

rfe = RFE(lr, n_features_to_select=3).fit(Xn, y_train)
print(dict(zip(num_cols, rfe.ranking_)))                            # 1 = selected

fwd = SequentialFeatureSelector(lr, n_features_to_select=3, direction="forward", cv=5).fit(Xn, y_train)
bwd = SequentialFeatureSelector(lr, n_features_to_select=3, direction="backward", cv=5).fit(Xn, y_train)
print("forward :", [c for c, k in zip(num_cols, fwd.get_support()) if k])
print("backward:", [c for c, k in zip(num_cols, bwd.get_support()) if k])
```

Wrappers find feature **combinations** but cost many model fits, so they get slow with hundreds of features. Run them inside cross-validation to avoid selection bias.

### 3. Embedded methods

Selection is a by-product of training.

```python
from sklearn.feature_selection import SelectFromModel
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier

# L1 (Lasso-style) regularisation drives useless coefficients to exactly zero
l1 = LogisticRegression(penalty="l1", solver="liblinear", C=0.5).fit(StandardScaler().fit_transform(Xn), y_train)
print(dict(zip(num_cols, l1.coef_[0].round(2))))

# Tree-based importance
rf = RandomForestClassifier(n_estimators=300, random_state=0).fit(Xn, y_train)
imp = pd.Series(rf.feature_importances_, index=num_cols).sort_values(ascending=False)
imp.plot.barh(); plt.title("Random forest importance"); plt.show()

SelectFromModel(rf, threshold="median").fit(Xn, y_train).get_support()
```

**Permutation importance** (shuffle one feature and see how much the score drops) is more reliable than built-in tree importance, which favours high-cardinality features:

```python
from sklearn.inspection import permutation_importance
Xn_val = X_test[num_cols].fillna(X_train[num_cols].median())
pi = permutation_importance(rf, Xn_val, y_test, n_repeats=10, random_state=0)
pd.Series(pi.importances_mean, index=num_cols).sort_values(ascending=False)
```

## D4. Choosing a method

|Situation|Choice|
|---|---|
|Hundreds or thousands of columns, quick cleanup|variance threshold, correlation filter, mutual information|
|Need the best small subset for a given model|wrapper (RFE / sequential)|
|Linear model with many features|L1 / Lasso / ElasticNet|
|Tree model|importance, permutation importance|
|Interpretability and regulation|filter + domain review|

### Selection best practices

- Do selection **inside** cross-validation or on the training set only.
- Remove obviously useless columns first (IDs, constants).
- Do not drop a feature just because it looks weak alone; it may matter in interaction.
- Confirm that removing a feature does not hurt validation performance.
- Document why each feature was kept or dropped.

# Part E: Feature extraction

**Definition:** algorithmically **projecting** existing, often high-dimensional features into a new, smaller set of features that capture most of the information.

## E1. Construction vs extraction

||**Construction**|**Extraction**|
|---|---|---|
|Who creates the feature|**you**, using domain intuition|**a mathematical algorithm**|
|New features are|interpretable (`Family_Size`, BMI)|combinations that are hard to interpret (`PC1`)|
|Number of features|usually grows|**shrinks**|
|Needs labels?|no|PCA no, LDA yes|
|Example|`rooms + washrooms` formula built by hand|PCA compresses 784 pixels to 50 components|

> **About the real-estate example in the lecture:** replacing separate `rooms` and `washrooms` columns with one `square feet` feature is a _domain-driven combination_ (closer to construction). Its extraction analogue is letting PCA learn a single "size" component from correlated columns, shown next.

## E2. Principal Component Analysis (PCA)

PCA finds new axes (**principal components**) along which the data varies the most. Components are **uncorrelated** and ordered by the share of variance they capture. Keep the first few, discard the rest.

### The intuition with correlated real-estate columns

```python
rng = np.random.default_rng(0)
n = 500
rooms = rng.integers(1, 7, n)
houses = pd.DataFrame({
    "rooms": rooms,
    "washrooms": np.clip(np.round(rooms / 2 + rng.normal(0, 0.4, n)), 1, None),
    "area_sqft": rooms * 350 + rng.normal(0, 150, n),
})

from sklearn.decomposition import PCA
Z = StandardScaler().fit_transform(houses)
pca = PCA().fit(Z)
print(pca.explained_variance_ratio_.round(3))        # the first component carries most of the variance
```

All three columns mostly measure "house size", so one component captures most of the information; it replaces three columns by one "size" feature that nobody had to define by hand.

### PCA on image pixels (digits)

```python
from sklearn.decomposition import PCA
from sklearn.pipeline import make_pipeline

pca = PCA(n_components=0.95).fit(StandardScaler().fit_transform(Xd))     # keep 95% of the variance
print(pca.n_components_, "components instead of", Xd.shape[1])           # roughly half of the 64 columns

cum = np.cumsum(PCA().fit(Xd).explained_variance_ratio_)
plt.plot(cum, marker="."); plt.axhline(0.95, ls="--", color="red")
plt.xlabel("components"); plt.ylabel("cumulative explained variance"); plt.show()

model = make_pipeline(StandardScaler(), PCA(n_components=0.95), RandomForestClassifier(random_state=0))
print("with PCA:", cross_val_score(model, Xd, yd, cv=5).mean().round(3))
```

On full MNIST, 784 features typically compress to a few hundred or fewer components that retain most of the variance.

### Visualising in 2D

```python
Z2 = PCA(n_components=2).fit_transform(StandardScaler().fit_transform(Xd))
plt.scatter(Z2[:, 0], Z2[:, 1], c=yd, cmap="tab10", s=8); plt.colorbar(label="digit"); plt.show()
```

### PCA rules

- **Scale first** (standardise); otherwise large-valued columns dominate.
- Fit on the training set only (pipeline).
- Components are linear mixtures: harder to interpret (check `pca.components_` loadings).
- It captures **variance**, not predictive power: a low-variance direction might still predict the target.
- Choose the number of components by explained variance (such as 90 to 99%), a scree plot, or cross-validated performance.
- Only linear structure; for non-linear structure see kernel PCA or autoencoders.

## E3. Linear Discriminant Analysis (LDA)

**Supervised** extraction: finds axes that **maximise the separation between classes** (using the labels), unlike PCA, which ignores them.

```python
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis

lda = LinearDiscriminantAnalysis(n_components=2)
Zl = lda.fit_transform(Xd, yd)                       # at most (number of classes - 1) components
plt.scatter(Zl[:, 0], Zl[:, 1], c=yd, cmap="tab10", s=8); plt.title("LDA projection of digits"); plt.show()
```

||PCA|LDA|
|---|---|---|
|Uses labels|no (unsupervised)|**yes** (supervised)|
|Goal|maximise variance|maximise class separation|
|Max components|min(samples, features)|classes - 1|
|Typical use|compression, noise removal, visualisation|classification pre-processing|

Because LDA uses labels, it must be fit inside cross-validation, or its evaluation leaks.

## E4. Other extraction methods

|Method|Idea|Typical use|
|---|---|---|
|**t-SNE**, **UMAP**|non-linear embeddings that keep neighbourhoods|2D visualisation (not for general features; t-SNE cannot transform new data)|
|**Kernel PCA**|PCA with non-linear kernels|curved structures|
|**Truncated SVD (LSA)**|PCA-like for sparse matrices|text (TF-IDF)|
|**Autoencoders**|neural network learns a compressed code|images, complex data|
|**Factor analysis, ICA, NMF**|other latent-factor models|domain-specific|
|**Word / sentence embeddings**|dense vectors from text|NLP|

## E5. Selection vs extraction

||**Selection**|**Extraction**|
|---|---|---|
|Output columns|a **subset** of the originals|**new** columns|
|Interpretability|kept (original meaning)|lost (components)|
|Information about dropped features|discarded entirely|partly retained in components|
|Needs all original features at prediction time?|only the selected ones|**yes**, all (to compute the projection)|
|Use when|cost and interpretability matter|features are correlated and numerous, and compression matters more than meaning|

# Part F: End-to-end: a leak-free Titanic pipeline

This combines every pillar and measures whether it helps.

```python
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import StratifiedKFold, cross_val_score

df = pd.read_csv("train.csv")

# --- Stateless construction (safe before the split) ---
def add_features(d):
    d = d.copy()
    d["Family_Size"] = d["SibSp"] + d["Parch"]
    d["IsAlone"] = (d["Family_Size"] == 0).astype(int)
    d["Family_Type"] = pd.cut(d["Family_Size"], [-1, 0, 4, np.inf],
                              labels=["Alone", "Small", "Large"]).astype(str)
    d["Title"] = d["Name"].str.extract(r",\s*([^\.]+)\.", expand=False).str.strip()
    d["Title"] = d["Title"].replace({"Mlle": "Miss", "Ms": "Miss", "Mme": "Mrs"})
    d["Title"] = d["Title"].where(d["Title"].isin(["Mr", "Miss", "Mrs", "Master"]), "Rare")
    d["HasCabin"] = d["Cabin"].notna().astype(int)
    d["TicketGroupSize"] = d.groupby("Ticket")["Ticket"].transform("count")      # uses only the features, not the target
    d["Fare_log"] = np.log1p(d["Fare"])
    return d

X = df.drop(columns=["Survived", "PassengerId"])
y = df["Survived"]
X_fe = add_features(X)

# --- Baseline: raw numeric features only ---
raw_num = ["Age", "Fare", "SibSp", "Parch", "Pclass"]
baseline = Pipeline([
    ("prep", ColumnTransformer([("num", SimpleImputer(strategy="median"), raw_num)])),
    ("model", LogisticRegression(max_iter=1000)),
])

# --- Engineered: stateful steps live in the pipeline ---
num_cols = ["Age", "Fare_log", "Family_Size", "TicketGroupSize"]
cat_cols = ["Sex", "Embarked", "Title", "Family_Type", "Pclass"]
flag_cols = ["IsAlone", "HasCabin"]

prep = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")), ("scale", StandardScaler())]), num_cols),
    ("cat", Pipeline([("imp", SimpleImputer(strategy="most_frequent")),
                      ("ohe", OneHotEncoder(handle_unknown="ignore"))]), cat_cols),
    ("flag", "passthrough", flag_cols),
])

engineered_lr = Pipeline([("prep", prep), ("model", LogisticRegression(max_iter=1000))])
engineered_rf = Pipeline([("prep", prep), ("model", RandomForestClassifier(n_estimators=300, random_state=0))])

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
results = {
    "Logistic, raw numeric only":     cross_val_score(baseline, X, y, cv=cv).mean(),
    "Logistic, engineered features":  cross_val_score(engineered_lr, X_fe, y, cv=cv).mean(),
    "Random forest, engineered":      cross_val_score(engineered_rf, X_fe, y, cv=cv).mean(),
}
pd.Series(results).round(3)
```

**What to expect:** the engineered logistic regression should clearly beat the raw-numeric baseline (sex and title carry most of the signal, and the baseline ignores the text columns entirely), and the random forest should be at least as good. Exact numbers depend on your scikit-learn version and random seeds, so use cross-validation to judge, not a single split.

### Ablation: which feature helped?

```python
def score_with(num, cat, flags):
    p = ColumnTransformer([
        ("num", Pipeline([("i", SimpleImputer(strategy="median")), ("s", StandardScaler())]), num),
        ("cat", Pipeline([("i", SimpleImputer(strategy="most_frequent")), ("o", OneHotEncoder(handle_unknown="ignore"))]), cat),
        ("flag", "passthrough", flags),
    ])
    m = Pipeline([("prep", p), ("model", LogisticRegression(max_iter=1000))])
    return cross_val_score(m, X_fe, y, cv=cv).mean()

full = score_with(num_cols, cat_cols, flag_cols)
for drop in ["Title", "Family_Type", "Sex"]:
    print(f"without {drop:12s}: {score_with(num_cols, [c for c in cat_cols if c != drop], flag_cols) - full:+.3f}")
```

Dropping one feature at a time shows each one's marginal contribution. `Sex` and `Title` overlap, so removing only one may barely hurt; remove both to see the combined effect.

### Add selection and extraction

```python
from sklearn.feature_selection import SelectFromModel

with_selection = Pipeline([
    ("prep", prep),
    ("select", SelectFromModel(RandomForestClassifier(n_estimators=200, random_state=0), threshold="median")),
    ("model", LogisticRegression(max_iter=1000)),
])
print("with embedded selection:", cross_val_score(with_selection, X_fe, y, cv=cv).mean().round(3))
```

(Use PCA the same way: `("pca", PCA(n_components=0.95))` after the preprocessor. Note that PCA on mostly one-hot columns is rarely a good idea; it shines on dense numeric data.)

### The pipeline template

```
Raw data -> stateless construction (add_features)
         -> train/test split (or cross-validation)
         -> ColumnTransformer [ impute -> encode -> transform -> scale ]
         -> selection / extraction (optional)
         -> model
         -> cross-validated evaluation, then final test-set check
```

Save the fitted pipeline (`joblib.dump`) so exactly the same transformations apply at prediction time.

# Part G: Mastery

## G1. Which pillar for which problem?

|Problem you see|Pillar|Action|
|---|---|---|
|Missing values|Transformation|impute / indicator / drop|
|Text categories|Transformation|one-hot, ordinal, target encoding|
|Numeric with a long tail|Transformation|log, Yeo-Johnson|
|Features on different scales|Transformation|StandardScaler, MinMaxScaler|
|Extreme values distorting a linear model|Transformation|cap, transform, RobustScaler|
|Linear model misses a non-linear pattern|Transformation / construction|binning, polynomial, interaction|
|Two columns only meaningful together|**Construction**|sum, ratio, product|
|Dates, text, IDs with hidden information|**Construction**|extract parts|
|Hundreds of features, many useless|**Selection**|filter / RFE / L1|
|Many correlated features, need compression|**Extraction**|PCA|
|Need class-separating low-dimensional features|**Extraction**|LDA|
|Need a 2D picture of high-dimensional data|Extraction (visual only)|PCA, UMAP|

## G2. Common mistakes

|Mistake|Why it hurts|Fix|
|---|---|---|
|Fitting imputer/scaler/encoder on all data|train-test leakage|`Pipeline` + `fit` on train only|
|Using target-derived features without cross-fitting|target leakage|out-of-fold target encoding|
|Using information unavailable at prediction time|model fails in production|check availability for every feature|
|One-hot encoding thousands of categories|huge, sparse, overfit|group rare labels, frequency/target encode|
|Ordinal-encoding nominal categories for linear models|false ordering|one-hot|
|Scaling for tree models "just in case"|wasted effort|skip it|
|Removing every outlier automatically|deletes real signal, distorts test|investigate; cap or transform|
|Dropping test rows with outliers|inflated scores|never|
|Blindly applying log to values with zeros or negatives|NaN / errors|`log1p`, Yeo-Johnson|
|Creating hundreds of features without validation|overfitting, slow|test in small batches, prune|
|PCA without scaling|dominated by large-scale columns|scale first|
|PCA before the train/test split|leakage|pipeline|
|Selecting features on the full dataset, then cross-validating|optimistic scores|selection inside the CV folds|
|Interpreting PCA components as original features|misleading|read loadings|
|Forgetting to apply the same pipeline in production|train-serve skew|save and reuse the fitted pipeline|

## G7. Final checklist

- [ ] EDA findings written down and mapped to feature actions
- [ ] Train/test (or CV) split defined **before** any fitted step
- [ ] Missing values handled with a justified strategy (and indicators where informative)
- [ ] Categorical variables encoded by type (nominal, ordinal, high cardinality)
- [ ] Skewed numeric features transformed; outliers investigated and handled deliberately
- [ ] Scaling applied for models that need it, via a pipeline
- [ ] Constructed features based on domain knowledge, each checked for availability at prediction time
- [ ] No target leakage, no train-test leakage

- [ ] Every change measured against a baseline with cross-validation
- [ ] Final pipeline saved and reusable for new data
- [ ] Decisions documented (what, why, effect)

## Key takeaways

- Feature engineering turns **raw data into model-ready inputs** using domain knowledge; it sits between EDA and model training, and it is part science, part art.
- Good features can make a simple model competitive with a complex one, especially on tabular data. Always measure the gain against a baseline.
- **Four pillars:** transformation (impute, encode, bin, handle outliers, scale, transform), construction (manual new features such as `Family_Size`), selection (keep the useful subset, such as dropping blank MNIST pixels), extraction (algorithmic projection such as PCA or LDA).
- **Construction** is manual and interpretable; **extraction** is algorithmic and produces fewer, harder-to-interpret features.
- **Fit on train, transform on test.** Put stateful steps in a pipeline and use cross-validation to prevent leakage.
- Tree models rarely need scaling or log transforms; linear models, KNN, SVM, PCA and neural nets usually do.
- Do not remove outliers blindly; investigate them first.
- Selection comes in three flavours (filter, wrapper, embedded); extraction trades interpretability for compression.
- Iterate: propose, test, keep what helps, document everything, and save the final pipeline.
