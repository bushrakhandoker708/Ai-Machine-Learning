# 1. What normalization is, and the vocabulary trap

**Normalization** is a feature scaling technique applied during data preparation. It adjusts the numerical values of a column to a **common scale without distorting the differences in the ranges of values and without losing information**: the order of the values and their relative spacing are preserved.

Normalization sits in the same pipeline position as standardization, as the **last** preprocessing step before the model:

```
impute -> handle outliers -> transform skew -> encode categoricals -> SCALE -> model
```

## The word "normalization" means different things

|Term|What it means|In this note?|
|---|---|---|
|**Normalization (broad sense)**|any column-wise rescaling: min-max, mean, max-abs, robust|**yes**|
|**Min-Max normalization**|rescale to a fixed range, usually [0, 1]|yes (4)|
|**Standardization / Z-score**|mean 0, standard deviation 1|see [[09.Feature Scaling - Standardization]]|
|**`sklearn.preprocessing.Normalizer`**|rescales each **row** to unit norm|yes, short section (8)|
|**Normal distribution / "normalizing" a distribution**|making data bell-shaped (log, Box-Cox, Yeo-Johnson)|**no** (that is a transformation, not scaling)|
|**Database normalization**|organising tables to avoid redundancy|unrelated|

Scaling changes the **range or spread**. It does not change the **shape** of a distribution. A skewed feature is still skewed after min-max scaling.

# 2. Why scaling is needed: units and how scaling removes them

## 2.1 Numbers carry units

A numerical variable has a **magnitude and a unit**: 70 kg, 70,000 g, 154.3 lb. These describe the same person, but a model that sees only the numbers 70, 70,000, and 154.3 sees three very different features. Distance-based algorithms (KNN, K-Means, SVM) and gradient-based optimisers (see the conditioning derivation in [[09.Feature Scaling - Standardization]]) are sensitive to this.

### The unit choice changes the answer

Three people, with height (cm) and weight (kg or g):

|Person|Height (cm)|Weight (kg)|Weight (g)|
|---|---|---|---|
|A|170|70|70,000|
|B|180|71|71,000|
|C|171|80|80,000|

With weight in **kg**: d(A, B) = sqrt(10^2 + 1^2) = **10.05**; d(A, C) = sqrt(1^2 + 10^2) = **10.05**. A tie. With weight in **grams**: d(A, B) = sqrt(10^2 + 1000^2) = **1000.05**; d(A, C) = sqrt(1^2 + 10000^2) = **10000.0**. Now B is far closer than C, and height is practically ignored.

The "closest neighbour" changed only because we switched units. A good preprocessing step should make the result **independent of the unit**.

```python
import numpy as np

A, B, C = np.array([170, 70]), np.array([180, 71]), np.array([171, 80])
d = lambda p, q: np.linalg.norm(p - q).round(2)
print("kg :", d(A, B), d(A, C))                           # 10.05 10.05

g = np.array([1, 1000])
print("g  :", d(A * g, B * g), d(A * g, C * g))           # 1000.05 10000.0
```

## 2.2 Proof: min-max scaling removes units

Changing units is a **positive affine transformation**: $x \to ax + c$ with $a > 0$ (kg to grams: $a = 1000, c = 0$; Celsius to Fahrenheit: $a = 1.8, c = 32$).

Apply min-max scaling to the converted values: $$x'' = \frac{(ax + c) - (a x_{\min} + c)}{(a x_{\max} + c) - (a x_{\min} + c)} = \frac{a(x - x_{\min})}{a(x_{\max} - x_{\min})} = \frac{x - x_{\min}}{x_{\max} - x_{\min}} = x'$$ The scale factor $a$ and the shift $c$ **cancel**. The scaled values are identical no matter which unit you started in. The same holds for standardization, mean normalization, and robust scaling, because each divides a distance (in the feature's unit) by another distance (in the same unit), leaving a **unitless** number.

```python
w_kg = np.array([70, 71, 80, 65, 90.0])
w_g = w_kg * 1000
mm = lambda v: (v - v.min()) / (v.max() - v.min())
print(np.allclose(mm(w_kg), mm(w_g)))                      # True
```

## 2.3 Other reasons (recap)

|Reason|Note|
|---|---|
|Distance-based algorithms|KNN, K-Means, DBSCAN, RBF-SVM|
|Gradient descent|better-conditioned loss surface|
|Regularisation|fair penalty across coefficients|
|Bounded inputs required|image pixels, sigmoid/tanh networks|
|Sparse data|must keep zeros as zeros|

# 3. The unified view: every scaler is `(x - center) / scale`

All the column-wise scalers are the **same operation** with different choices of two numbers: $$x' = \frac{x - \text{center}}{\text{scale}}$$

|Scaler|center|scale|Resulting range|
|---|---|---|---|
|**Min-Max**|$x_{\min}$|$x_{\max} - x_{\min}$ (range)|exactly [0, 1]|
|**Mean normalization**|$\mu$ (mean)|$x_{\max} - x_{\min}$ (range)|within [-1, 1], width 1|
|**MaxAbs**|0 (no centering)|$\max\lvert x\rvert$|within [-1, 1]|
|**Robust**|median|IQR ($Q_3 - Q_1$)|unbounded|
|**Standard** (previous note)|$\mu$|$\sigma$|unbounded|

Why this view helps:

- All are **affine** (shift and stretch), so all preserve the **order**, the **shape**, and the **correlation** of the data.
- They differ only in **what is held fixed** (the endpoints, the mean, the median) and in **how robust** the centre and scale are to extreme values.
- scikit-learn exposes the fitted numbers: `center_` and `scale_` (Robust), `data_min_`, `data_range_`, `scale_` (MinMax), `max_abs_` (MaxAbs).

Distance consequence: after any of these, Euclidean distance is $$d(p, q)^2 = \sum_j \left(\frac{p_j - q_j}{s_j}\right)^2$$ a weighted Euclidean distance with weights $1/s_j^2$, where $s_j$ is that scaler's scale for feature $j$ (range, max-abs, IQR, or standard deviation).

# 4. Min-Max scaling

## 4.1 Formula

$$\boxed{x'_i = \frac{x_i - x_{\min}}{x_{\max} - x_{\min}}}$$ Output range: **exactly 0 to 1** on the data used to fit it. The minimum maps to 0, the maximum maps to 1, everything else falls proportionally in between.

## 4.2 Derivation

We want a linear map $x' = a x + b$ with $x_{\min} \to 0$ and $x_{\max} \to 1$: $$a,x_{\min} + b = 0, \qquad a,x_{\max} + b = 1$$ Subtract the first from the second: $a(x_{\max} - x_{\min}) = 1$, so $a = \frac{1}{x_{\max} - x_{\min}}$. Then $b = -a,x_{\min} = -\frac{x_{\min}}{x_{\max} - x_{\min}}$. Therefore $$x' = \frac{x}{x_{\max} - x_{\min}} - \frac{x_{\min}}{x_{\max} - x_{\min}} = \frac{x - x_{\min}}{x_{\max} - x_{\min}}$$

### Any target range $[a, b]$

To scale to $[a, b]$ instead of [0, 1], first scale to [0, 1], then stretch and shift: $$x'' = a + \frac{(x - x_{\min})(b - a)}{x_{\max} - x_{\min}}$$

```python
MinMaxScaler(feature_range=(-1, 1))      # maps to [-1, 1], handy for tanh networks
```

### Inverse

$$x = x',(x_{\max} - x_{\min}) + x_{\min}$$

## 4.3 Worked example

Data `[2, 4, 4, 4, 5, 5, 7, 9]`: min = 2, max = 9, range = 7.

|x|2|4|4|4|5|5|7|9|
|---|---|---|---|---|---|---|---|---|
|x' = (x - 2) / 7|0|0.286|0.286|0.286|0.429|0.429|0.714|1|

```python
x = np.array([2, 4, 4, 4, 5, 5, 7, 9], dtype=float)
x_mm = (x - x.min()) / (x.max() - x.min())
print(x_mm.round(3))
```

## 4.4 Properties

|Property|Result|
|---|---|
|Range|[0, 1] on the fitting data|
|Mean and standard deviation|**not** 0 and 1 (they depend on the data)|
|Shape of the distribution|preserved (only axis labels change)|
|Order and correlation|preserved|
|Zeros|not preserved (a 0 maps to $-x_{\min}/\text{range}$)|
|Sensitive to outliers|**very**: the range depends on the two most extreme points|

## 4.5 Geometric intuition

Min-max scaling stretches or squeezes each axis so that the data fits inside a **unit square** (2D), a **unit cube** (3D), or a **unit hypercube** (many dimensions), spanning the full 0 to 1 interval on every axis. The overall picture of the point cloud is preserved apart from the different stretching per axis. Unlike standardization, it does not centre the cloud at the origin: the cloud occupies the **positive corner** $[0,1]^d$.

```python
import matplotlib.pyplot as plt
rng = np.random.default_rng(0)
X = np.c_[rng.normal(40, 10, 300), rng.normal(60_000, 15_000, 300)]
Xm = (X - X.min(0)) / (X.max(0) - X.min(0))

fig, axes = plt.subplots(1, 2, figsize=(11, 4.5))
axes[0].scatter(*X.T, s=8); axes[0].set_title("Raw")
axes[1].scatter(*Xm.T, s=8); axes[1].set_title("Min-Max: fits the unit square")
axes[1].set_xlim(-0.05, 1.05); axes[1].set_ylim(-0.05, 1.05); axes[1].set_aspect("equal")
axes[1].add_patch(plt.Rectangle((0, 0), 1, 1, fill=False, ec="red"))
plt.tight_layout(); plt.show()
```

## 4.6 Implementation with `MinMaxScaler`

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import MinMaxScaler

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)   # split FIRST

scaler = MinMaxScaler()                       # default feature_range=(0, 1)
X_train_s = scaler.fit_transform(X_train)     # learns x_min and x_max from TRAIN only
X_test_s = scaler.transform(X_test)           # applies the TRAIN min and max

print(scaler.data_min_, scaler.data_max_)     # learned minimum and maximum per column
print(scaler.data_range_)                     # max - min
print(X_train_s.min(axis=0), X_train_s.max(axis=0))     # [0 0] [1 1] exactly (train)
```

Rules (identical to standardization): **split first, fit on train, transform train and test, never fit on test**.

### The test set can fall outside [0, 1]

Min and max come from the training data. If a test value is below the training minimum or above the training maximum, its scaled value leaves [0, 1]. This is normal and correct.

```python
train = np.array([[10.], [15.], [20.]])
test = np.array([[5.], [12.], [25.]])
sc = MinMaxScaler().fit(train)
print(sc.transform(test).ravel())                 # [-0.5  0.2   1.5]

sc_clip = MinMaxScaler(clip=True).fit(train)      # force results into the range
print(sc_clip.transform(test).ravel())            # [0.  0.2 1. ]
```

Use `clip=True` only if your downstream model really requires strictly bounded inputs; clipping hides how far out-of-range a new value is.

### As a DataFrame

```python
X_train_df = pd.DataFrame(X_train_s, columns=X_train.columns, index=X_train.index)
# or: MinMaxScaler().set_output(transform="pandas")   (scikit-learn 1.2+)
```

### Functional shortcut (no fitted object, so use with care)

```python
from sklearn.preprocessing import minmax_scale
minmax_scale(x)       # fine for exploration; for modelling use the class so train/test share parameters
```

## 4.7 The main drawback: outliers

Because $x_{\min}$ and $x_{\max}$ are used, **one extreme value defines the whole range**, squeezing all the normal values into a tiny band.

```python
rng = np.random.default_rng(1)
salary = rng.normal(60_000, 10_000, 200)
salary_out = np.append(salary, 1_000_000)

mm = lambda a: (a - a.min()) / (a.max() - a.min())
print("clean   : inlier range after scaling =", np.ptp(mm(salary)).round(2))               # 1.00
print("outlier : inlier range after scaling =", np.ptp(mm(salary_out)[:-1]).round(3))      # about 0.06
```

The 200 genuine values now occupy about 6% of the [0, 1] interval, so the model cannot tell them apart well. Fix the outlier first (cap, log, remove if invalid), or use `RobustScaler`.

## 4.8 Use cases

- **Image pixels** (0 to 255): known bounds, so divide by 255 (see section 13).
- **Neural networks** with sigmoid or tanh units and bounded inputs.
- **KNN, K-Means, SVM** when features have no serious outliers.
- **Features with natural bounds**: percentages, ratings 1 to 5, exam scores 0 to 100.
- **Any algorithm or visual needing values in a fixed range** (heat maps, weights, color scales).

# 5. Mean normalization

## 5.1 Formula

$$\boxed{x'_i = \frac{x_i - \mu}{x_{\max} - x_{\min}}}$$ where $\mu$ is the feature mean. Output range: **between -1 and +1**. It **mean-centres** the data (new mean exactly 0) and divides by the range.

## 5.2 Derivation of the range and mean

**Mean is exactly 0:** averaging $x'_i$ gives $\frac{\bar{x} - \mu}{R} = 0$ (with $R = x_{\max} - x_{\min}$).

**Range is within [-1, 1]:** the smallest and largest values map to $$x'_{\min} = \frac{x_{\min} - \mu}{R} \in [-1, 0], \qquad x'_{\max} = \frac{x_{\max} - \mu}{R} \in [0, 1]$$ because $\mu$ lies between $x_{\min}$ and $x_{\max}$. Their difference is $$x'_{\max} - x'_{\min} = \frac{x_{\max} - x_{\min}}{R} = 1$$ So the transformed data spans an interval of **width exactly 1** that contains 0, which sits inside [-1, 1]. (It is the min-max result shifted down by $\frac{\mu - x_{\min}}{R}$, which is the mean's position in the min-max scale.)

## 5.3 Worked example

Data `[2, 4, 4, 4, 5, 5, 7, 9]`: mean = 5, range = 7.

|x|2|4|4|4|5|5|7|9|
|---|---|---|---|---|---|---|---|---|
|(x - 5) / 7|-0.429|-0.143|-0.143|-0.143|0|0|0.286|0.571|

Mean = 0, width of the interval = 0.571 - (-0.429) = 1.

## 5.4 Properties and when it appears

- Combines **centring** (like standardization) with **range-based scaling** (like min-max).
- Sensitive to outliers (both $\mu$ and the range are).
- Classically used when **gradient descent** is hand-implemented (for example, in introductory machine learning courses) to centre features and keep them in a small range.
- In practice, standardization is usually preferred because $\sigma$ is more stable than the range.

## 5.5 Implementation: scikit-learn has no built-in class

There is no `MeanNormalizer` in scikit-learn, so implement it manually, preferably as a transformer that follows the `fit` / `transform` API (so it works in pipelines and respects the train/test rule).

```python
from sklearn.base import BaseEstimator, TransformerMixin

class MeanNormalizer(BaseEstimator, TransformerMixin):
    """x' = (x - mean) / (max - min), parameters learned on the training data only."""
    def fit(self, X, y=None):
        X = np.asarray(X, dtype=float)
        self.mean_ = X.mean(axis=0)
        rng = X.max(axis=0) - X.min(axis=0)
        self.range_ = np.where(rng == 0, 1.0, rng)          # avoid dividing by zero for constant columns
        return self
    def transform(self, X):
        return (np.asarray(X, dtype=float) - self.mean_) / self.range_
    def inverse_transform(self, Z):
        return np.asarray(Z) * self.range_ + self.mean_

mn = MeanNormalizer().fit(X_train)
X_train_mn, X_test_mn = mn.transform(X_train), mn.transform(X_test)
print(X_train_mn.mean(axis=0).round(6), X_train_mn.min(axis=0).round(3), X_train_mn.max(axis=0).round(3))
```

A quick one-off version using standard tools:

```python
from sklearn.preprocessing import StandardScaler
center = StandardScaler(with_std=False).fit(X_train)              # subtract the mean
rng = (X_train.max() - X_train.min()).to_numpy()                  # range per column
X_train_mn = center.transform(X_train) / rng
X_test_mn = center.transform(X_test) / rng
```

Use it inside a pipeline just like any scaler: `make_pipeline(MeanNormalizer(), KNeighborsClassifier())`.

# 6. Max Absolute scaling (`MaxAbsScaler`)

## 6.1 Formula

$$\boxed{x'_i = \frac{x_i}{\max_k \lvert x_k\rvert}}$$ (the denominator is the largest **absolute** value in the column, which equals $\lvert x_{\max}\rvert$ when the largest magnitude is positive). Output range: **[-1, 1]**. If all values are non-negative, the range is [0, 1].

## 6.2 Properties and derivation

It is the affine map with **center = 0** and **scale = $\max\lvert x\rvert$**. Because nothing is subtracted:

- **Zero stays zero:** $0/\max\lvert x\rvert = 0$.
- **Signs are preserved.**
- **Sparsity is preserved:** a sparse matrix keeps the exact same non-zero pattern (no dense conversion).
- **No centring:** the mean is not 0.
- **Sensitive to outliers:** a single huge value sets the scale (like min-max).

Why centring is a problem for sparse data: subtracting a mean turns every zero into a non-zero ($0 - \mu$), so a matrix with 99% zeros becomes fully dense and can exhaust memory. Dividing keeps zeros at zero.

## 6.3 Worked example

`[-4, 0, 2, 8]`: max absolute value = 8, so x' = `[-0.5, 0, 0.25, 1]`.

## 6.4 Implementation

```python
from sklearn.preprocessing import MaxAbsScaler

scaler = MaxAbsScaler()
X_train_s = scaler.fit_transform(X_train)
X_test_s = scaler.transform(X_test)
print(scaler.max_abs_)         # learned maximum absolute value per column
```

### Sparse data

```python
from scipy import sparse
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
dense = rng.poisson(0.05, (1000, 500)) * rng.integers(1, 20, (1000, 500))     # about 95% zeros
S = sparse.csr_matrix(dense, dtype=float)

S_scaled = MaxAbsScaler().fit_transform(S)
print(type(S_scaled).__name__, S.nnz, S_scaled.nnz)                 # still sparse, same number of non-zeros

try:
    StandardScaler().fit_transform(S)                                # centring a sparse matrix is refused
except ValueError as e:
    print("StandardScaler:", str(e)[:70], "...")
StandardScaler(with_mean=False).fit_transform(S)                     # works, but only scales (no centring)
```

## 6.5 Use cases

- **Bag-of-words / TF-IDF** text features and other **sparse** matrices.
- **One-hot encoded** features with many columns plus a few numeric ones (scale numerics separately).
- Data **already centred** around zero (signed features) where you only need bounded magnitudes.
- Recommenders with sparse user-item matrices.

# 7. Robust scaling (`RobustScaler`)

## 7.1 Formula

$$\boxed{x'_i = \frac{x_i - \text{Median}}{\text{IQR}} = \frac{x_i - \text{Median}}{Q_{75} - Q_{25}}}$$ Output range: **unbounded**. After scaling, the **median is 0** and the **IQR is 1** (the middle 50% of the data spans one unit).

## 7.2 Why it is robust: the breakdown point

The **breakdown point** of a statistic is the fraction of arbitrarily bad values it can tolerate before it can be pushed to any value.

|Statistic|Breakdown point|Meaning|
|---|---|---|
|Mean, standard deviation, min, max, range|**0%**|one extreme value can change them arbitrarily|
|Median|50%|half the data must be bad to move it|
|IQR (quartiles)|25%|a quarter of the data must be bad|

Robust scaling uses only the median and the quartiles, so outliers (up to 25% of the data) **cannot distort the centre or the scale** used for the normal points.

## 7.3 Relation to standardization

For perfectly normal data, IQR $= 1.349,\sigma$, so robust-scaled values are about $z / 1.349$, a little larger than z-scores' reciprocal scale. For data without outliers the two scalers behave similarly; with outliers they diverge dramatically.

## 7.4 Worked example

Data `[10, 20, 30, 40, 1000]` (1000 is an outlier): median = 30, $Q_{25} = 20$, $Q_{75} = 40$, IQR = 20. x' = (x - 30) / 20 = **[-1, -0.5, 0, 0.5, 48.5]**. The first four values keep their natural spacing (0.5 apart) and the outlier clearly stands out at 48.5. Compare min-max, where the same four values are compressed to `[0, 0.010, 0.020, 0.030]` (section 9).

## 7.5 Implementation

```python
from sklearn.preprocessing import RobustScaler

scaler = RobustScaler()                          # default quantile_range=(25.0, 75.0)
X_train_s = scaler.fit_transform(X_train)
X_test_s = scaler.transform(X_test)

print(scaler.center_)                            # the medians
print(scaler.scale_)                             # the IQRs

RobustScaler(quantile_range=(10, 90))            # a wider "core": use the 10th to 90th percentile range
RobustScaler(with_centering=False)               # scale only (useful for sparse data)
```

## 7.6 Caveats

- The output is **not bounded**, so outliers can still produce large values (like 48.5 above). If the model needs bounded inputs, clip afterwards or combine with a transformation.
- If the IQR is 0 (a column with more than half of its values identical, such as many zeros), scikit-learn sets the scale to 1, but the scaling is then uninformative. Use another approach for such features.
- Robust scaling does not make skewed data symmetric; combine with a log or power transform if needed.

## 7.7 Use cases

- **Sensor data** with spikes and glitches.
- **Financial data**: transaction amounts, incomes, prices (with a log transform first for heavy skew).
- **Fraud and anomaly detection**, where outliers are real and must not distort the scale of normal behaviour.
- **Web analytics**: session durations, page loads.
- Any time a quick look at the box plot ([[06.Univariate Analysis]]) shows many outliers.

# 8. Row-wise normalization (`Normalizer`)

Everything above works **column by column** (per feature). `sklearn.preprocessing.Normalizer` works **row by row** (per sample): it rescales each row to have unit norm. $$x'_{\text{row}} = \frac{x_{\text{row}}}{\lVert x_{\text{row}}\rVert}$$

|Norm|Formula|Result|
|---|---|---|
|`"l2"` (default)|$\sqrt{\sum x_j^2}$|row has Euclidean length 1|
|`"l1"`|$\sum \lvert x_j\rvert$|absolute values sum to 1|
|`"max"`|$\max\lvert x_j\rvert$|largest absolute value is 1|

```python
from sklearn.preprocessing import Normalizer

M = np.array([[3.0, 4.0], [1.0, 1.0], [0.0, 10.0]])
print(Normalizer(norm="l2").fit_transform(M).round(3))
# [[0.6   0.8  ]      length sqrt(0.36 + 0.64) = 1
#  [0.707 0.707]
#  [0.    1.   ]]
print(Normalizer(norm="l1").fit_transform(M).round(3))        # each row sums to 1
```

It is stateless (nothing is learned from the data), so there is no leakage risk. After L2 row-normalization, the dot product between two rows equals their **cosine similarity**.

||Column-wise scalers (sections 4 to 7)|`Normalizer`|
|---|---|---|
|Acts on|each feature across rows|each sample across features|
|Goal|comparable feature scales|comparable sample magnitudes|
|Typical use|most tabular models|text (TF-IDF, word counts), cosine similarity, document clustering|

# 9. All scalers side by side

## 9.1 One small dataset, five scalers

Normal values plus one outlier: `[10, 20, 30, 40, 1000]`.

|x|Min-Max|Mean norm.|MaxAbs|Robust|Standard (z)|
|---|---|---|---|---|---|
|10|0.000|-0.212|0.010|-1.0|-0.538|
|20|0.010|-0.202|0.020|-0.5|-0.513|
|30|0.020|-0.192|0.030|0.0|-0.487|
|40|0.030|-0.182|0.040|0.5|-0.461|
|1000|1.000|0.788|1.000|48.5|1.999|

Look at the gaps between the four normal values: 0.010 (Min-Max, MaxAbs), 0.010 (Mean normalization), 0.026 (Standard), but **0.5 for Robust**. Only the robust scaler keeps the ordinary values spread out.

```python
from sklearn.preprocessing import MinMaxScaler, MaxAbsScaler, RobustScaler, StandardScaler

x = np.array([10, 20, 30, 40, 1000], dtype=float).reshape(-1, 1)
out = pd.DataFrame({
    "x": x.ravel(),
    "MinMax": MinMaxScaler().fit_transform(x).ravel(),
    "MeanNorm": ((x - x.mean()) / (x.max() - x.min())).ravel(),
    "MaxAbs": MaxAbsScaler().fit_transform(x).ravel(),
    "Robust": RobustScaler().fit_transform(x).ravel(),
    "Standard": StandardScaler().fit_transform(x).ravel(),
}).round(3)
print(out)
```

## 9.2 Without and with an outlier (inlier resolution)

```python
rng = np.random.default_rng(1)
clean = rng.normal(60_000, 10_000, 200).reshape(-1, 1)
dirty = np.vstack([clean, [[1_000_000]]])

scalers = {"MinMax": MinMaxScaler(), "Standard": StandardScaler(),
           "MaxAbs": MaxAbsScaler(), "Robust": RobustScaler()}
rows = []
for name, sc in scalers.items():
    spread_clean = np.ptp(sc.fit_transform(clean))                   # range of the 200 normal points
    spread_dirty = np.ptp(sc.fit_transform(dirty)[:-1])              # same 200 points, outlier present
    rows.append({"scaler": name, "inlier spread (clean)": spread_clean.round(2),
                 "inlier spread (with outlier)": spread_dirty.round(2),
                 "kept": f"{spread_dirty / spread_clean:.0%}"})
pd.DataFrame(rows)
```

Typical result: Min-Max keeps about 6%, MaxAbs about 6%, Standard about 15%, **Robust about 100%**. (The inliers' spread relative to what it was when no outlier was present.)

# 11. Which scaler should I use?

## 11.1 Step-by-step guidance

1. **Check necessity first.** Does the algorithm need scaling?
    - Needs it: KNN, K-Means, SVM, PCA, linear/logistic regression, neural networks, regularised models.
    - Does not: decision trees, random forests, gradient boosted trees (XGBoost, LightGBM).
2. **Default choice: `StandardScaler`.** It is the best starting point for most algorithms.
3. **Min-Max scaling** when the **bounds are known** in advance or a bounded range is required. The classic example is **images**, where pixel values lie between 0 and 255 (use CNNs with inputs in [0, 1]).
4. **Robust scaling** when the data contains **significant outliers**.
5. **MaxAbs scaling** for **sparse** data.
6. **Experiment.** Try several scalers in a pipeline with cross-validation and see what works best for your dataset.

## 11.2 Decision flowchart

```
Does the model use distances, gradients, or penalised coefficients?
 |-- no (trees) --------------------------------------> no scaling needed
 |
 yes
  |
  Is the data sparse (mostly zeros)?
  |-- yes ---------------------------------------------> MaxAbsScaler (or StandardScaler(with_mean=False))
  |
  Does it contain strong outliers you must keep?
  |-- yes ---------------------------------------------> RobustScaler (after log for heavy skew)
  |
  Are the feature bounds known / a bounded input range required?
  |-- yes ---------------------------------------------> MinMaxScaler (use known bounds, e.g. pixels / 255)
  |
  otherwise ----------------------------------------------> StandardScaler (default)
```

## 11.3 By algorithm

|Algorithm|Recommended|Why|
|---|---|---|
|KNN, K-Means|Standard, or Min-Max if no outliers|distances|
|SVM (RBF)|Standard|distance-based kernel, variance-based `gamma`|
|PCA|**Standard**|variance-based; min-max changes which direction has max variance in a less principled way|
|Linear / Logistic regression|Standard|interpretable coefficients, conditioning|
|Ridge / Lasso|Standard|fair penalty|
|Neural network (tabular)|Standard or Min-Max|stable gradients|
|CNN on images|Min-Max with **known bounds** ([0, 1] via `/255`) or per-channel standardization|pixel range is known|
|Sigmoid/tanh output layers|Min-Max to [0, 1] or [-1, 1]|match activation range|
|Sparse text features|MaxAbs|keep sparsity|
|Anomaly detection, fraud|Robust|outliers must not distort the scale|
|Trees, forests, boosting|none|order-based splits|

## 11.4 Using known bounds instead of observed ones

Min-max with **observed** min and max depends on the sample you happened to see. For a feature with natural limits (percentage 0 to 100, rating 1 to 5, pixels 0 to 255, temperature sensor 0 to 50 C), use those **fixed bounds**:

```python
score_scaled = (score - 0) / (100 - 0)                      # exam scores 0 to 100
rating_scaled = (rating - 1) / (5 - 1)                      # ratings 1 to 5
pixels = images.astype("float32") / 255.0                   # images 0 to 255
```

This makes the scale **stable across datasets and over time**, and avoids the training min and max shifting when new data arrives.

# 12. Pitfalls

|Pitfall|Consequence|Fix|
|---|---|---|
|Fitting on all the data before splitting|data leakage|split first; fit on train only|
|`fit_transform` on the test set|train and test scaled differently|`transform` only|
|Expecting test values inside [0, 1]|they can exceed it|normal; use `clip=True` only if required|
|Min-Max with outliers|inliers squeezed into a tiny band|cap, log-transform, or `RobustScaler`|
|Constant column (`max == min`)|division by zero|scikit-learn sets scale to 1; better to drop the column|
|Using min-max on skewed data|skew remains|log or power transform first|
|Scaling one-hot dummies|pointless|scale numerics only (`ColumnTransformer`)|
|Centring sparse data|memory blow-up|`MaxAbsScaler` or `with_mean=False`|
|Scaling the target|wrong predictions|scale `X` only (or invert `y` after)|
|Scaling for tree models|no gain|skip|
|Production data drifts past training min/max|scaled values outside expectation|monitor; refresh the model, or use known bounds|
|Forgetting to save the scaler|cannot reproduce|`joblib.dump(scaler, ...)`|
|Treating the unit-range as probabilities|min-max values are not probabilities|they are just rescaled numbers|
|Calling row-wise `Normalizer` for column scaling|wrong operation|use `MinMaxScaler`, etc.|

# 13. Use cases with code

## Use case 1: images (known bounds)

Pixel values are integers 0 to 255; many CNNs expect inputs in [0, 1] or [-1, 1].

```python
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.svm import SVC
from sklearn.neural_network import MLPClassifier

X, y = digits.data, digits.target
X01 = X / 16.0                                           # known bound (maximum is 16 for this dataset; use 255 for 8-bit images)
X_pm = (X - 8.0) / 8.0                                   # rescale to [-1, 1]: centre 8, half-range 8

Xtr, Xte, ytr, yte = train_test_split(X01, y, test_size=0.3, random_state=0)
print(SVC().fit(Xtr, ytr).score(Xte, yte).round(3))

```

For 8-bit images use `images.astype("float32") / 255.0`. Here you did not fit anything on the data, so there is no leakage and no risk of mismatched train/test scaling.

## Use case 6: gradient descent with mean normalization

```python
class MeanNormalizer(BaseEstimator, TransformerMixin):          # from section 5.5
    def fit(self, X, y=None):
        X = np.asarray(X, float); self.mean_ = X.mean(0)
        r = X.max(0) - X.min(0); self.range_ = np.where(r == 0, 1.0, r); return self
    def transform(self, X): return (np.asarray(X, float) - self.mean_) / self.range_

rng = np.random.default_rng(0)
size = rng.uniform(500, 4000, 300)               # square feet
rooms = rng.integers(1, 6, 300)                  # count
price = 50 * size + 10_000 * rooms + rng.normal(0, 20_000, 300)

Xn = MeanNormalizer().fit_transform(np.c_[size, rooms])
Xb = np.c_[np.ones(len(price)), Xn]
yn = (price - price.mean()) / price.std()

w = np.zeros(3)
for _ in range(2000):                                         # plain batch gradient descent
    w -= 0.5 * (-(Xb.T @ (yn - Xb @ w)) / len(yn))
print("final MSE (normalized units):", np.mean((yn - Xb @ w) ** 2).round(3))
```

Because both features are centred and within [-1, 1], one learning rate (0.5) works. On the raw features (size in thousands, price in hundreds of thousands) the same learning rate would diverge.

# 14. Reference and practice

## 14.1 Standardization vs normalization (min-max)

||Standardization|Min-Max normalization|
|---|---|---|
|Formula|$(x - \mu)/\sigma$|$(x - x_{\min})/(x_{\max} - x_{\min})$|
|Result|mean 0, std 1, unbounded|exactly [0, 1]|
|Outlier sensitivity|moderate (via $\mu, \sigma$)|high (via min, max)|
|Preserves shape|yes|yes|
|Typical use|default; distance, PCA, linear models|bounded inputs, images, no outliers|
|Needs bounds?|no|benefits from known bounds|
|Test data in range?|no fixed range|can fall outside [0, 1]|

## 14.5 Glossary

|Term|Meaning|
|---|---|
|**Normalization**|rescaling features to a common range without distorting relative differences|
|**Min-Max scaling**|linear map of the minimum to 0 and the maximum to 1|
|**Mean normalization**|centre by the mean, divide by the range|
|**MaxAbs scaling**|divide by the largest absolute value|
|**Robust scaling**|centre by the median, divide by the IQR|
|**IQR**|interquartile range, $Q_{75} - Q_{25}$|
|**Breakdown point**|share of bad data a statistic can tolerate|
|**Sparse matrix**|matrix with mostly zero entries stored compactly|
|**Affine transformation**|$ax + b$; scale and shift|
|**Unit hypercube**|the region $[0, 1]^d$|
|**Clipping**|forcing values into a fixed range|
|**Data leakage**|information from test data influencing preprocessing or training|

## Key takeaways

- **Normalization** rescales features to a common scale **without distorting relative differences**; it removes the dependence on units (kg, g, lb) because each scaled value divides a distance by another distance in the same unit.
- Every scaler is $x' = (x - \text{center})/\text{scale}$. Min-Max uses (min, range) and gives **[0, 1]**; Mean normalization uses (mean, range) and gives values in **[-1, 1]**; MaxAbs uses (0, max absolute) and gives **[-1, 1]** and keeps **sparsity**; Robust uses (median, IQR) and is **robust to outliers**.
- Min-Max geometry: the data is fitted into a **unit square, cube, or hypercube**. It is **very sensitive to outliers**, because the min and max set the scale.
- Scikit-learn provides `MinMaxScaler`, `MaxAbsScaler`, and `RobustScaler`; **mean normalization must be implemented manually**.
- Always **split first, fit on train, transform train and test**. Test values can legitimately fall outside [0, 1].
- Scaling changes **range, not shape**: skewed data stays skewed and outliers stay outliers (except that robust scaling stops them from distorting the normal points).
- **Choosing:** check if the algorithm needs scaling at all; start with **StandardScaler**; use **Min-Max for known bounds** (images 0 to 255); **Robust for outliers**; **MaxAbs for sparse data**; and **experiment** with scalers inside a cross-validated pipeline.
