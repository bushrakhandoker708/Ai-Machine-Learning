# Part 1: JSON

## What is JSON?
JSON (JavaScript Object Notation) is a text format for semi-structured data. It is built from objects (key-value pairs) and arrays (lists), and can be nested to any depth. It is the standard format for web APIs.

```json
{
  "id": 1,
  "name": "Asha",
  "skills": ["python", "sql"],
  "address": {"city": "Dhaka", "zip": "1207"}
}
```

**Pros:** flexible, human-readable, supports nesting and types (string, number, boolean, null).
**Cons:** not tabular, so it usually needs flattening before modeling. It is also verbose and slow for large data.

## Python type mapping
| JSON | Python |
|---|---|
| object | `dict` |
| array | `list` |
| string | `str` |
| number | `int` / `float` |
| true / false | `True` / `False` |
| null | `None` |

## Using the built-in `json` module
```python
import json

# Read from a file
with open("data.json", encoding="utf-8") as f:
    data = json.load(f)

# Parse from a string
data = json.loads('{"a": 1}')

# Write to a file
with open("out.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)

# Convert to a string
s = json.dumps(data, indent=2)
```

## Reading JSON with pandas
```python
import pandas as pd

df = pd.read_json("data.json")
```

### Flattening nested JSON
```python
df = pd.json_normalize(data)                      # nested keys become address.city
df = pd.json_normalize(data, sep="_")             # address_city
df = pd.json_normalize(data, record_path="orders", meta=["id", "name"])
```
Use `record_path` to explode a nested list into rows and `meta` to keep parent fields.

## JSON Lines (`.jsonl`)
One JSON object per line. Common for logs and large datasets, and can be streamed.
```python
df = pd.read_json("data.jsonl", lines=True)
df.to_json("out.jsonl", orient="records", lines=True)
```

## Common JSON problems
- **`JSONDecodeError`**: invalid syntax (trailing commas, single quotes, comments).
- **Nested columns holding dicts or lists**: flatten with `json_normalize` or `explode()`.
- **Inconsistent keys across records**: missing keys become `NaN`; check with `df.isnull().sum()`.
- **Large files**: use JSON Lines or `chunksize` with `lines=True`.

# Part 2: SQL

## What is SQL?
SQL (Structured Query Language) is used to query relational databases, where data is stored in tables with a fixed schema. Most real-world company data lives in a database, so you usually pull it with a query rather than a file.

**Common databases:** SQLite, PostgreSQL, MySQL, SQL Server, Oracle.

## Core SQL you need for data gathering
```sql
SELECT col1, col2
FROM table_name
WHERE col3 > 10 AND city = 'Dhaka'
ORDER BY col1 DESC
LIMIT 100;
```

| Clause | Purpose |
|---|---|
| `SELECT` | Choose columns |
| `FROM` | Choose table |
| `WHERE` | Filter rows |
| `GROUP BY` + aggregates (`COUNT`, `AVG`, `SUM`) | Summarize |
| `JOIN` | Combine tables |
| `ORDER BY` / `LIMIT` | Sort and cap results |

### Joins at a glance
```sql
SELECT o.id, c.name, o.total
FROM orders o
JOIN customers c ON o.customer_id = c.id;
```
- `INNER JOIN`: only matching rows
- `LEFT JOIN`: all rows from the left table, matches from the right
- `RIGHT` / `FULL JOIN`: the mirrored and combined versions

## Connecting from Python

### SQLite (built in, no server needed)
```python
import sqlite3
import pandas as pd

conn = sqlite3.connect("data.db")
df = pd.read_sql("SELECT * FROM customers", conn)
conn.close()
```

### Other databases with SQLAlchemy
```python
from sqlalchemy import create_engine, text
import pandas as pd

engine = create_engine("postgresql+psycopg2://user:password@host:5432/dbname")
# MySQL: "mysql+pymysql://user:password@host/dbname"

df = pd.read_sql(text("SELECT * FROM customers"), engine)
```

### Parameterized queries (avoid SQL injection)
```python
query = text("SELECT * FROM customers WHERE city = :city")
df = pd.read_sql(query, engine, params={"city": "Dhaka"})
```
Never build queries by pasting user input into a string.

## Writing data back to a database
```python
df.to_sql("clean_customers", engine, if_exists="replace", index=False)
```
`if_exists` can be `"fail"`, `"replace"`, or `"append"`.

## Reading large tables
```python
for chunk in pd.read_sql("SELECT * FROM big_table", engine, chunksize=50_000):
    process(chunk)
```
Filter and aggregate in SQL first, so less data is transferred to Python.

## Common SQL problems
- **Connection errors**: check host, port, credentials, firewall, and the driver package.
- **Slow queries**: select only the columns you need, add `WHERE` and `LIMIT`, and use indexed columns.
- **Duplicate rows after a join**: check that the join keys are unique.
- **Wrong dtypes in pandas**: set them explicitly or cast in SQL.
- **Credentials in code**: store them in environment variables or a `.env` file, never in notebooks you share.

## JSON vs SQL at a glance
| | JSON | SQL database |
|---|---|---|
| Structure | Flexible, nested | Fixed schema, tabular |
| Typical source | APIs, logs, configs | Company databases |
| Python tools | `json`, `pd.read_json`, `json_normalize` | `sqlite3`, SQLAlchemy, `pd.read_sql` |
| Main challenge | Flattening | Writing efficient queries |

## Key takeaways
- Use `json.load` for raw access and `pd.json_normalize` to turn nested JSON into a table.
- Use `pd.read_sql` with a connection or engine to pull query results straight into a DataFrame.
- Filter and aggregate in SQL before loading, and always parameterize queries.
- Run the same sanity checks as with CSVs: `df.shape`, `df.info()`, `df.isnull().sum()`.
