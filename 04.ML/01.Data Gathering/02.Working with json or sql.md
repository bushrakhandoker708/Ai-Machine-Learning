# Part 1: JSON

## What is JSON?

JSON (JavaScript Object Notation) is a text format for semi-structured data. It is built from objects (key-value pairs) and arrays (lists), and can be nested to any depth. It is the standard format for web APIs.

```json
{
  "id": 1,
  "name": "Asha",
  "skills": ["python", "sql"],
  "address": {"city": "Dhaka", "zip": "1207"}
}
```

**Pros:** flexible, human-readable, supports nesting and types (string, number, boolean, null). **Cons:** not tabular, so it usually needs flattening before modeling. It is also verbose and slow for large data.

## Python type mapping

|JSON|Python|
|---|---|
|object|`dict`|
|array|`list`|
|string|`str`|
|number|`int` / `float`|
|true / false|`True` / `False`|
|null|`None`|

## Using the built-in `json` module

```python
import json

# Read from a file
with open("data.json", encoding="utf-8") as f:
    data = json.load(f)

# Parse from a string
data = json.loads('{"a": 1}')

# Write to a file
with open("out.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)

# Convert to a string
s = json.dumps(data, indent=2)
```

## Reading JSON with pandas: `pd.read_json()`

### Loading a local JSON file

Example dataset: a recipe file (`train.json`) with roughly 39,000 dishes. Each record has an `id`, a `cuisine`, and a list of `ingredients`.

```python
import pandas as pd

df = pd.read_json("train.json")
print(df.shape)       # (~39774, 3)
df.head()
```

Output looks like:

|id|cuisine|ingredients|
|---|---|---|
|10259|greek|[romaine lettuce, black olives, grape tomatoes, ...]|
|25693|southern_us|[plain flour, ground pepper, salt, ...]|

The nested `ingredients` list stays inside one cell as a Python list. Work with it like this:

```python
# One row per ingredient
ingredients = df.explode("ingredients")
print(ingredients["ingredients"].value_counts().head(10))

# Number of ingredients per dish
df["n_ingredients"] = df["ingredients"].str.len()
print(df.groupby("cuisine")["n_ingredients"].mean().sort_values(ascending=False))
```

### Loading remote JSON from a URL or API

Pass the URL straight in. Pandas fetches the content and builds the DataFrame.

```python
# Example: a currency exchange-rate API that returns a JSON table
url = "https://example.com/api/exchange-rates.json"   # replace with a real endpoint

df = pd.read_json(url)
print(df.shape)       # e.g. ~160 rows x 7 columns
df.head()
```

If the API needs headers, an API key, or returns nested content, fetch it yourself with `requests` and flatten it:

```python
import requests

resp = requests.get(url, headers={"Accept": "application/json"}, timeout=30)
resp.raise_for_status()
data = resp.json()                      # -> dict / list

df = pd.json_normalize(data["rates"])   # adjust the key to match your API
```

### Key `read_json` parameters

#### `orient`: tell pandas how the JSON is laid out

```python
from io import StringIO

records = '[{"id": 1, "city": "Dhaka"}, {"id": 2, "city": "London"}]'
df = pd.read_json(StringIO(records))                   # orient="records" style, auto-detected

columns = '{"id": {"0": 1, "1": 2}, "city": {"0": "Dhaka", "1": "London"}}'
df = pd.read_json(StringIO(columns), orient="columns")
```

Other values: `"index"`, `"split"`, `"table"`. If the result looks transposed or empty, try a different `orient`.

> Recent pandas versions deprecate passing a raw JSON string directly, so wrap literal strings in `StringIO`.

#### `nrows`: limit rows loaded

`nrows` (and `chunksize`) require line-delimited JSON, so set `lines=True`.

```python
# Peek at the first 1,000 records of a large JSON Lines file
preview = pd.read_json("big.jsonl", lines=True, nrows=1000)
print(preview.shape)
```

#### `chunksize`: load huge files in batches to save RAM

```python
total = 0
reader = pd.read_json("big.jsonl", lines=True, chunksize=10_000)

for chunk in reader:
    total += len(chunk)
    # process(chunk): filter, aggregate, write to disk...

print("rows processed:", total)
```

With `chunksize`, `read_json` returns an iterator (a `JsonReader`), not a DataFrame. A regular single-document `.json` file cannot be chunked this way, so convert it to JSON Lines first if you need that.

#### `encoding`: fix character problems

```python
df = pd.read_json("reviews.json", encoding="utf-8")        # default
df = pd.read_json("reviews.json", encoding="latin-1")      # if you see UnicodeDecodeError
```

### Flattening nested JSON

```python
data = [
    {
        "id": 1,
        "name": "Asha",
        "address": {"city": "Dhaka", "zip": "1207"},
        "orders": [{"sku": "A1", "qty": 2}, {"sku": "B7", "qty": 1}],
    },
    {
        "id": 2,
        "name": "Ben",
        "address": {"city": "London", "zip": "E1"},
        "orders": [{"sku": "A1", "qty": 5}],
    },
]

pd.json_normalize(data)                      # nested keys become address.city
pd.json_normalize(data, sep="_")             # address_city
pd.json_normalize(data, record_path="orders", meta=["id", "name"])
```

The last call gives one row per order, with the parent `id` and `name` attached:

|sku|qty|id|name|
|---|---|---|---|
|A1|2|1|Asha|
|B7|1|1|Asha|
|A1|5|2|Ben|

Use `record_path` to explode a nested list into rows and `meta` to keep parent fields.

## JSON Lines (`.jsonl`)

One JSON object per line. Common for logs and large datasets, and can be streamed.

```python
df = pd.read_json("data.jsonl", lines=True)
df.to_json("out.jsonl", orient="records", lines=True)
```

## Writing JSON

```python
df.to_json("out.json", orient="records", indent=2)
```

## Common JSON problems

- **`JSONDecodeError` / `ValueError`**: invalid syntax (trailing commas, single quotes, comments).
- **Nested columns holding dicts or lists**: flatten with `json_normalize` or `explode()`.
- **Inconsistent keys across records**: missing keys become `NaN`; check with `df.isnull().sum()`.
- **Large files**: use JSON Lines with `lines=True` and `chunksize`.
- **`nrows` or `chunksize` raising an error**: you forgot `lines=True`.
- **Encoding errors**: set `encoding`.

# Part 2: SQL

## What is SQL?

SQL (Structured Query Language) is used to query relational databases, where data is stored in tables with a fixed schema. Most real-world company data lives in a database, so you usually pull it with a query rather than a file.

**Common databases:** SQLite, PostgreSQL, MySQL, SQL Server, Oracle.

## Core SQL you need for data gathering

```sql
SELECT col1, col2
FROM table_name
WHERE col3 > 10 AND city = 'Dhaka'
ORDER BY col1 DESC
LIMIT 100;
```

|Clause|Purpose|
|---|---|
|`SELECT`|Choose columns|
|`FROM`|Choose table|
|`WHERE`|Filter rows|
|`GROUP BY` + aggregates (`COUNT`, `AVG`, `SUM`)|Summarize|
|`JOIN`|Combine tables|
|`ORDER BY` / `LIMIT`|Sort and cap results|

### Joins at a glance

```sql
SELECT o.id, c.name, o.total
FROM orders o
JOIN customers c ON o.customer_id = c.id;
```

- `INNER JOIN`: only matching rows
- `LEFT JOIN`: all rows from the left table, matches from the right
- `RIGHT` / `FULL JOIN`: the mirrored and combined versions

## Worked example: MySQL with XAMPP and the `world` database

Because SQL data lives inside a database server, we first need a local database to talk to. This walkthrough uses XAMPP (Apache + MySQL) and the sample `world` database.

### Step A: Set up the database environment

1. **Install XAMPP.** It bundles a local web server (Apache) and a MySQL database server.
2. **Start the services.** Open the XAMPP Control Panel and start **Apache** and **MySQL**.
3. **Open phpMyAdmin.** Go to `http://localhost/phpmyadmin` in your browser to manage databases visually.
4. **Create a database and import data.** Create a database named `world`, then use the **Import** tab to load `world.sql`. It contains three related tables:
    - `city`
    - `country`
    - `countrylanguage`

### Step B: Connect Python to MySQL

Install the connector, which acts as the bridge between Python and MySQL:

```bash
pip install mysql-connector-python
```

Create a connection object:

```python
import mysql.connector

conn = mysql.connector.connect(
    host="localhost",    # the local machine
    user="root",         # XAMPP's default user
    password="",         # empty by default in XAMPP
    database="world",
)

print(conn.is_connected())   # True if everything is working
```

These defaults are fine for a local learning setup only. For anything real, use a dedicated user, a strong password, and keep credentials out of your code (see below).

### Step C: Read SQL queries into pandas with `pd.read_sql_query()`

It accepts a SQL query string and the connection, and returns a DataFrame.

```python
import pandas as pd

# 1) Fetch a whole table
city = pd.read_sql_query("SELECT * FROM city", conn)
print(city.shape)
city.head()
```

```python
# 2) Filter inside SQL: Indian cities only (~341 rows)
indian_cities = pd.read_sql_query(
    "SELECT * FROM city WHERE CountryCode = 'IND'", conn
)
print(indian_cities.shape)
```

The lecture uses `LIKE 'IND'`. That works, but with no wildcard it behaves like `=`, so `=` is clearer. Use `LIKE` when you want patterns, e.g. `WHERE Name LIKE 'New%'`.

```python
# 3) Countries with high life expectancy
high_life = pd.read_sql_query(
    "SELECT Name, Continent, LifeExpectancy FROM country WHERE LifeExpectancy > 60",
    conn,
)
print(high_life.sort_values("LifeExpectancy", ascending=False).head())
```

```python
# 4) A join across tables: cities with their country names
query = """
SELECT ci.Name AS city, co.Name AS country, ci.Population
FROM city ci
JOIN country co ON ci.CountryCode = co.Code
WHERE co.Continent = 'Asia'
ORDER BY ci.Population DESC
LIMIT 10
"""
top_asian_cities = pd.read_sql_query(query, conn)
```

### Key `read_sql_query` parameters

#### `index_col`: set a column as the DataFrame index

```python
countries = pd.read_sql_query("SELECT * FROM country", conn, index_col="Code")
countries.loc["BGD"]      # look up Bangladesh by its code
```

#### `chunksize`: process huge tables in batches

```python
total_pop = 0

for chunk in pd.read_sql_query("SELECT * FROM city", conn, chunksize=1000):
    total_pop += chunk["Population"].sum()

print(total_pop)
```

With `chunksize` you get an iterator of DataFrames instead of one big frame.

#### `params`: pass values safely

```python
df = pd.read_sql_query(
    "SELECT * FROM city WHERE CountryCode = %s AND Population > %s",
    conn,
    params=("IND", 1_000_000),
)
```

`%s` is the placeholder style for `mysql.connector`. Other drivers use `?` (SQLite) or named styles.

### Close the connection when done

```python
conn.close()
```

A safer pattern, so the connection closes even if a query fails:

```python
conn = mysql.connector.connect(host="localhost", user="root", password="", database="world")
try:
    df = pd.read_sql_query("SELECT * FROM city", conn)
finally:
    conn.close()
```

> **Heads-up:** pandas officially supports SQLAlchemy connections and `sqlite3`. Passing a raw `mysql.connector` connection usually still works but may print a `UserWarning`. The SQLAlchemy version below avoids it.

## Connecting from Python: other options

### MySQL via SQLAlchemy (recommended with pandas)

```bash
pip install sqlalchemy pymysql
```

```python
from sqlalchemy import create_engine, text
import pandas as pd

engine = create_engine("mysql+pymysql://root:@localhost/world")

df = pd.read_sql_query(text("SELECT * FROM city WHERE CountryCode = :code"),
                       engine, params={"code": "IND"})
```

### SQLite (built in, no server needed)

Good for practising without installing XAMPP.

```python
import sqlite3
import pandas as pd

conn = sqlite3.connect("data.db")
df = pd.read_sql("SELECT * FROM customers", conn)
conn.close()
```

### PostgreSQL and others with SQLAlchemy

```python
from sqlalchemy import create_engine, text
import pandas as pd

engine = create_engine("postgresql+psycopg2://user:password@host:5432/dbname")
# MySQL: "mysql+pymysql://user:password@host/dbname"

df = pd.read_sql(text("SELECT * FROM customers"), engine)
```

### Parameterized queries (avoid SQL injection)

```python
query = text("SELECT * FROM customers WHERE city = :city")
df = pd.read_sql(query, engine, params={"city": "Dhaka"})
```

Never build queries by pasting user input into a string.

### `read_sql_query` vs `read_sql`

|Function|Takes|Use when|
|---|---|---|
|`pd.read_sql_query(sql, con)`|a SQL query only|you always run queries|
|`pd.read_sql_table(name, engine)`|a table name (SQLAlchemy only)|you want a whole table|
|`pd.read_sql(sql_or_table, con)`|either|convenience wrapper|

## Writing data back to a database

```python
df.to_sql("clean_customers", engine, if_exists="replace", index=False)
```

`if_exists` can be `"fail"`, `"replace"`, or `"append"`.

## Reading large tables

```python
for chunk in pd.read_sql("SELECT * FROM big_table", engine, chunksize=50_000):
    process(chunk)
```

Filter and aggregate in SQL first, so less data is transferred to Python.

## Common SQL problems

- **Connection errors**: check that MySQL is actually running in XAMPP, plus host, port, credentials, firewall, and the driver package.
- **`Unknown database 'world'`**: you have not created or imported it in phpMyAdmin yet.
- **Slow queries**: select only the columns you need, add `WHERE` and `LIMIT`, and use indexed columns.
- **Duplicate rows after a join**: check that the join keys are unique.
- **Wrong dtypes in pandas**: set them explicitly or cast in SQL.
- **`UserWarning` about DBAPI2 connections**: switch to a SQLAlchemy engine.
- **Credentials in code**: store them in environment variables or a `.env` file, never in notebooks you share.

```python
import os
conn = mysql.connector.connect(
    host=os.getenv("DB_HOST", "localhost"),
    user=os.getenv("DB_USER"),
    password=os.getenv("DB_PASSWORD"),
    database=os.getenv("DB_NAME"),
)
```

## JSON vs SQL at a glance

| |JSON|SQL database|
|---|---|---|
|Structure|Flexible, nested|Fixed schema, tabular|
|Typical source|APIs, logs, configs|Company databases|
|Python tools|`json`, `pd.read_json`, `json_normalize`|`mysql.connector`, `sqlite3`, SQLAlchemy, `pd.read_sql_query`|
|Large-data options|`lines=True` + `chunksize`|`chunksize`, filter in SQL|
|Main challenge|Flattening|Writing efficient queries|

## Key takeaways

- Use `pd.read_json()` for local files and URLs; `nrows` and `chunksize` need `lines=True`; `encoding` fixes character errors.
- Use `json.load` for raw access and `pd.json_normalize` to turn nested JSON into a table.
- For SQL, set up a database (XAMPP + phpMyAdmin), connect with a connector or SQLAlchemy, then call `pd.read_sql_query(query, conn)`.
- `index_col` sets the index and `chunksize` streams big tables in batches.
- Filter and aggregate in SQL before loading, always parameterize queries, and close your connections.
- Run the same sanity checks as with CSVs: `df.shape`, `df.info()`, `df.isnull().sum()`.
