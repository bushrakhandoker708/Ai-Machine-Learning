# Data Gathering

## What it is
Data gathering is the first practical step of the ML pipeline: collecting raw data from the sources where it lives so it can be cleaned, explored, and used for modeling. The quality and coverage of what you collect set an upper limit on what any model can learn.

## Why it matters
- Garbage in, garbage out: a better algorithm can't fix biased, noisy, or missing data.
- The source determines the format, the volume, and the cleaning work that follows.
- Data collected without a clear problem framing (see [[08.How to Frame an ML Problem]]) often turns out to be the wrong data.

## Common sources
| Source | Typical format | Note |
|---|---|---|
| Flat files | CSV, TSV, Excel | [[01.Working with csv files]] |
| Structured/semi-structured | JSON, SQL databases | [[02.Working with json or sql]] |
| Web services | REST APIs | [[03.Fetching data from API]] |
| Websites | HTML pages | [[04.Web Scrapping]] |

Other sources include sensors/IoT, logs, surveys, public datasets (Kaggle, UCI, Hugging Face), and data warehouses.

## What to check while gathering
- **Relevance**: does it contain the features and target your problem needs?
- **Volume**: is there enough data for the model complexity you plan to use?
- **Representativeness**: does it match the real-world distribution the model will see?
- **Quality**: missing values, duplicates, inconsistent formats, label errors.
- **Legal and ethical**: licensing, privacy, consent, and terms of service (especially for scraping and APIs).
- **Freshness**: is it current, and how will you update it?

## Typical workflow
1. Define what data the problem requires.
2. Identify candidate sources.
3. Pull the data (files, queries, API calls, scraping).
4. Store it in a consistent, versioned location.
5. Do a quick sanity check (shape, dtypes, nulls, sample rows).
6. Hand off to cleaning and EDA.
