## What is an API?
An API (Application Programming Interface) lets your code request data from another service in a structured way. Most web APIs are REST APIs: you send an HTTP request to a URL (an endpoint) and get back a response, usually JSON (see [[02.Working with json or sql]]).

**Why use APIs instead of scraping:** the data is structured, the access is officially supported, and it is less likely to break when a website changes its layout.

## Key concepts
| Term | Meaning |
|---|---|
| Endpoint | The URL you send the request to, e.g. `https://api.example.com/v1/users` |
| Method | `GET` (read), `POST` (create), `PUT`/`PATCH` (update), `DELETE` (remove) |
| Query parameters | Filters added to the URL, e.g. `?city=Dhaka&limit=50` |
| Headers | Metadata such as authentication and content type |
| Status code | Result of the request: 200 OK, 401 unauthorized, 404 not found, 429 too many requests, 500 server error |
| Authentication | API key, bearer token, or OAuth |
| Rate limit | Maximum number of requests allowed in a time window |
| Pagination | Large results split across multiple pages |

## Making a basic request
```python
import requests

url = "https://api.example.com/v1/users"
params = {"city": "Dhaka", "limit": 50}

response = requests.get(url, params=params, timeout=10)
response.raise_for_status()   # raises an error for 4xx/5xx

data = response.json()
```

Always set a `timeout`, otherwise a request can hang forever.

## Authentication
```python
import os

API_KEY = os.environ["API_KEY"]   # never hardcode keys

# API key in a header (bearer token)
headers = {"Authorization": f"Bearer {API_KEY}"}
response = requests.get(url, headers=headers, timeout=10)

# API key as a query parameter (some APIs)
params = {"api_key": API_KEY}
```
Store keys in environment variables or a `.env` file (with `python-dotenv`), and keep that file out of Git.

## Sending data (POST)
```python
payload = {"name": "Asha", "age": 29}
response = requests.post(url, json=payload, headers=headers, timeout=10)
```

## Checking the response
```python
response.status_code    # 200
response.headers        # response metadata
response.text           # raw text
response.json()         # parsed JSON (dict or list)
```

## Turning the response into a DataFrame
```python
import pandas as pd

df = pd.DataFrame(data)                  # list of flat records
df = pd.json_normalize(data["results"])  # nested records
```

## Pagination
Most APIs return results in pages. Common patterns:

**Page number**
```python
all_rows = []
page = 1
while True:
    r = requests.get(url, params={"page": page, "per_page": 100}, headers=headers, timeout=10)
    r.raise_for_status()
    rows = r.json()
    if not rows:
        break
    all_rows.extend(rows)
    page += 1
```

**Cursor / next URL**
```python
next_url = url
while next_url:
    r = requests.get(next_url, headers=headers, timeout=10)
    r.raise_for_status()
    body = r.json()
    all_rows.extend(body["results"])
    next_url = body.get("next")
```

## Rate limits and retries
```python
import time

def get_with_retry(url, retries=3, **kwargs):
    for attempt in range(retries):
        r = requests.get(url, timeout=10, **kwargs)
        if r.status_code == 429:
            wait = int(r.headers.get("Retry-After", 2 ** attempt))
            time.sleep(wait)
            continue
        r.raise_for_status()
        return r
    raise RuntimeError("Too many retries")
```
- Respect the documented rate limit and add `time.sleep()` between calls if needed.
- Use exponential backoff for temporary failures (429, 500, 503).
- Use `requests.Session()` to reuse connections when making many calls.

## Saving the data
```python
import json

with open("raw_data.json", "w", encoding="utf-8") as f:
    json.dump(all_rows, f)

df.to_csv("data.csv", index=False)
```
Save the raw response before cleaning, so you do not have to hit the API again.

## Common problems and fixes
- **401 / 403**: missing or wrong key, expired token, or insufficient permissions.
- **404**: wrong endpoint or ID; check the docs and the API version.
- **429**: you are hitting the rate limit; slow down and back off.
- **Empty or partial data**: you forgot pagination.
- **`JSONDecodeError`**: the response is not JSON (often an HTML error page); print `response.text`.
- **Different results over time**: data changes, so record the date and parameters you used.
- **Key leaked in code**: rotate it immediately and move it to an environment variable.

## Good practices
- Read the API documentation first: endpoints, limits, terms of use.
- Test in a browser, Postman, or `curl` before writing the loop.
- Cache or save raw responses to avoid repeated calls.
- Log the request parameters and timestamp for reproducibility.
- Check the terms of service for restrictions on storing or redistributing data.

## Key takeaways
- `requests.get()` plus `.json()` covers most use cases; always use `timeout` and `raise_for_status()`.
- Handle authentication safely, with keys in environment variables.
- Loop through pagination and respect rate limits.
- Save the raw data, then flatten into a DataFrame with `pd.json_normalize`.
