# 1. What feature scaling is and where it sits in the pipeline

**Feature scaling** transforms numerical input features so that they lie on a comparable scale. For example, `Age` is measured in tens (18 to 60) while `Salary` is measured in tens of thousands (15,000 to 150,000). Scaling puts both into a similar, small numerical range.

## Position in the feature engineering pipeline

Scaling is typically the **last** step before the model:

```
Raw data
   |
   v
1. Handle missing values        (impute)
2. Handle outliers              (cap, remove, flag)
3. Transform skewed features    (log, Box-Cox, Yeo-Johnson)
4. Encode categorical variables (one-hot, ordinal, target encoding)
5. Feature creation / selection
6. FEATURE SCALING   <--- this note
   |
   v
Machine learning model
```

Why last?

- Imputing with the mean or median changes the mean and standard deviation, so scale **after** imputation.
- Log or power transforms change the shape and scale, so scale **after** them.
- One-hot dummies are usually **not** scaled (see section 13), so you only scale the numeric part after encoding.
- Within a project, **all scaling parameters must be learned from the training set only** (section 8).

# 2. Why scaling is necessary

## 2.1 Features live on different scales

|Feature|Typical range|Unit|
|---|---|---|
|Age|18 to 60|years|
|Salary|15,000 to 150,000|currency|
|Number of children|0 to 5|count|
|Height|1.5 to 2.0|metres|
|Distance to work|0.5 to 50|km|

A model that has no notion of units sees only raw numbers. Whichever feature has the largest numeric spread tends to dominate.

## 2.2 The distance problem (worked example)

Distance-based algorithms such as **K-Nearest Neighbours (KNN)** predict from the "closest" points, using a metric such as Euclidean distance:

$$d(A, B) = \sqrt{(\text{Age}_A - \text{Age}_B)^2 + (\text{Salary}_A - \text{Salary}_B)^2}$$

Take three customers:

|Customer|Age|Salary|
|---|---|---|
|A|25|50,000|
|B|60|51,000|
|C|26|70,000|

**Unscaled distances**

- d(A, B) = sqrt(35^2 + 1000^2) = sqrt(1,225 + 1,000,000) = **about 1,000.6**
- d(A, C) = sqrt(1^2 + 20,000^2) = sqrt(1 + 400,000,000) = **about 20,000.0**

So A's nearest neighbour is **B**, a 60-year-old, even though C is practically the same age (26 vs 25). The salary difference (1,000 vs 20,000) swamps the age difference (35 vs 1), and age effectively plays no role.

**Scaled distances.** Suppose the standard deviations are 10 years for age and 15,000 for salary. Divide each difference by its standard deviation:

- d(A, B) = sqrt((35/10)^2 + (1000/15000)^2) = sqrt(12.25 + 0.0044) = **about 3.50**
- d(A, C) = sqrt((1/10)^2 + (20000/15000)^2) = sqrt(0.01 + 1.78) = **about 1.34**

Now C is the nearest neighbour. Each feature contributes in proportion to how unusual the difference is _for that feature_, not in proportion to its units.

```python
import numpy as np

A, B, C = np.array([25, 50_000]), np.array([60, 51_000]), np.array([26, 70_000])
dist = lambda p, q: np.linalg.norm(p - q)
print("raw   :", dist(A, B).round(1), dist(A, C).round(1))               # 1000.6  20000.0

sd = np.array([10, 15_000])
print("scaled:", dist(A / sd, B / sd).round(2), dist(A / sd, C / sd).round(2))     # 3.5  1.34
```

## 2.3 Other reasons

|Reason|Explanation|
|---|---|
|**Distance-based models**|KNN, K-Means, DBSCAN, hierarchical clustering, RBF-kernel SVM all use distances|
|**Gradient descent**|Different scales give elongated loss surfaces, so convergence is slow or unstable (section 6.2)|
|**Regularisation**|Ridge and Lasso penalise coefficient size; a feature measured in small units needs a large coefficient and is penalised unfairly (section 6.3)|
|**PCA**|Components follow the directions of largest variance, which simply means the largest-unit features (section 6.4)|
|**Comparing coefficients**|Standardized features give coefficients that are comparable across features|
|**Numerical stability**|Neural networks and optimisers behave better with inputs near zero|

# 3. Standardization: the definition

**Standardization** (also called **Z-score normalization**) rescales each feature to have **mean 0 and standard deviation 1**:

$$\boxed{x'_i = \frac{x_i - \bar{x}}{\sigma}}$$

|Symbol|Meaning|
|---|---|
|$x_i$|original value of the feature for row $i$|
|$\bar{x}$ (or $\mu$)|mean of that feature column|
|$\sigma$|standard deviation of that feature column|
|$x'_i$ (also called $z_i$)|the standardized value, or **z-score**|

The z-score has a direct meaning: **how many standard deviations a value lies above (+) or below (-) the mean.**

- $z = 0$: exactly average
- $z = +2$: two standard deviations above average
- $z = -1.5$: one and a half standard deviations below average

### Tiny worked example

Data: `[2, 4, 4, 4, 5, 5, 7, 9]`

1. Mean: (2+4+4+4+5+5+7+9) / 8 = 40 / 8 = **5**
2. Deviations from the mean: -3, -1, -1, -1, 0, 0, 2, 4
3. Squared deviations: 9, 1, 1, 1, 0, 0, 4, 16 (sum = 32)
4. Variance: 32 / 8 = 4, so standard deviation $\sigma$ = **2**
5. Z-scores: (x - 5) / 2 = **-1.5, -0.5, -0.5, -0.5, 0, 0, 1, 2**

Check: the new mean is (-1.5 - 0.5 - 0.5 - 0.5 + 0 + 0 + 1 + 2) / 8 = 0 / 8 = **0**. The new variance is (2.25 + 0.25 + 0.25 + 0.25 + 0 + 0 + 1 + 4) / 8 = 8 / 8 = **1**.

```python
x = np.array([2, 4, 4, 4, 5, 5, 7, 9])
z = (x - x.mean()) / x.std()           # np.std uses ddof=0 by default
print(z)                               # [-1.5 -0.5 -0.5 -0.5  0.   0.   1.   2. ]
print(z.mean(), z.std())               # 0.0  1.0
```

# 4. Mathematical derivation

## 4.1 Standardization is an affine (linear) transformation

We want a transformation of the form $z = a x + b$ such that $E[z] = 0$ and $\text{Var}(z) = 1$.

Two facts about any random variable $X$ and constants $a, b$: $$E[aX + b] = a,E[X] + b \qquad\qquad \text{Var}(aX + b) = a^2,\text{Var}(X)$$

**Step 1: make the mean zero.** Require $a\mu + b = 0$, which gives $b = -a\mu$. So $z = a(x - \mu)$. This is **mean centering**.

**Step 2: make the variance one.** Require $a^2 \sigma^2 = 1$, which gives $a = 1/\sigma$ (taking the positive root so the order of values is preserved).

**Result:** $$z = \frac{1}{\sigma}(x - \mu) = \frac{x - \mu}{\sigma}$$ This is exactly the standardization formula, so it is not arbitrary: it is the _unique_ positive-slope linear map that produces mean 0 and variance 1.

## 4.2 Proof that the mean is 0

With $n$ values and $\bar{x} = \frac{1}{n}\sum x_i$: $$\bar{z} = \frac{1}{n}\sum_{i=1}^{n} \frac{x_i - \bar{x}}{\sigma} = \frac{1}{\sigma}\left(\frac{1}{n}\sum x_i - \bar{x}\right) = \frac{1}{\sigma}(\bar{x} - \bar{x}) = 0$$

## 4.3 Proof that the standard deviation is 1

Using the population variance $\sigma^2 = \frac{1}{n}\sum (x_i - \bar{x})^2$: $$\text{Var}(z) = \frac{1}{n}\sum_{i=1}^{n} z_i^2 = \frac{1}{n}\sum \frac{(x_i - \bar{x})^2}{\sigma^2} = \frac{1}{\sigma^2}\cdot\underbrace{\frac{1}{n}\sum (x_i - \bar{x})^2}_{=,\sigma^2} = 1$$ (The mean of $z$ is 0, so its variance equals the mean of $z_i^2$.)

## 4.4 What standardization does NOT change

Because it is just shift-and-stretch with positive slope $a = 1/\sigma$:

|Property|Preserved?|Why|
|---|---|---|
|Order of values (ranks)|yes|positive slope|
|Shape of the distribution (skewness, kurtosis, modes)|**yes**|linear maps do not bend a distribution|
|Relative distances between points|yes (in proportion)|all gaps scaled by the same $1/\sigma$|
|Correlation between features|**yes**|correlation is scale- and shift-invariant|
|Outliers|still outliers (section 12)|a far point stays far in z units|
|Distribution becoming "normal"|**no**|standardization is not normalisation of shape|

Skewness is a standardized third moment, so it is invariant: $$\text{skew}(z) = E!\left[\left(\frac{z - 0}{1}\right)^3\right] = E!\left[\left(\frac{x-\mu}{\sigma}\right)^3\right] = \text{skew}(x)$$

## 4.5 Population vs sample standard deviation (`ddof`)

|Version|Formula|Used by|
|---|---|---|
|Population ($\sigma$, `ddof=0`)|divide by $n$|`numpy.std` default, **`StandardScaler`**|
|Sample ($s$, `ddof=1`)|divide by $n-1$|**`pandas.Series.std()`** default|

```python
s = pd.Series([2, 4, 4, 4, 5, 5, 7, 9])
print(s.std(), s.std(ddof=0))                 # 2.138 vs 2.0
z_pandas_default = (s - s.mean()) / s.std()   # std = 1.0 only when ddof=0 is used
(s - s.mean()).div(s.std(ddof=0)).std(ddof=0) # 1.0
```

For large $n$ the difference is negligible, but if you compare manual pandas results with `StandardScaler`, use `ddof=0`.

## 4.6 Standardizing a whole dataset (matrix form)

For a data matrix $X$ with $n$ rows and $d$ columns: $$Z = (X - \mathbf{1}\mu^\top),D^{-1}, \qquad D = \text{diag}(\sigma_1, \dots, \sigma_d)$$ Each column $j$ is centered by $\mu_j$ and divided by $\sigma_j$ independently. After standardization, the covariance matrix of $Z$ equals the **correlation matrix** of $X$: $$\text{Cov}(Z) = D^{-1},\Sigma,D^{-1} = R$$

## 4.7 Euclidean distance in standardized space

For two points $p, q$: $$d_Z(p, q)^2 = \sum_{j=1}^{d} \left(\frac{p_j - q_j}{\sigma_j}\right)^2 = \sum_{j=1}^{d} \frac{1}{\sigma_j^2}(p_j - q_j)^2$$ So standardization is **equivalent to a weighted Euclidean distance with weight $1/\sigma_j^2$** per feature. Features with big variance are down-weighted, which is exactly the fix for the distance problem in section 2.2. (This is the Mahalanobis distance with the off-diagonal terms of the covariance ignored.)

# 5. Geometric intuition

Standardization performs **two operations** on the cloud of data points.

```
 Original data                  Step 1: mean centering          Step 2: divide by std
 (salary axis is huge)          (shift mean to the origin)      (equal spread on every axis)

 Salary                          Salary                          z2
   |        .  .                   |  .   .                       |   . .
   |     . . ..  .                 | . .+. .                      |  .. + ..
   |  .  .. +  . .   --->    ---- |-.-.-O-.-.--- Age  --->  -----|..---O---..--- z1
   | .. .  .                      |  . .  .                      |   ..  .
   |_______________ Age           |                              |
```

1. **Mean centering (translation).** Subtract the mean of each feature, shifting the cloud so that its centre of mass sits at the origin $(0, 0)$.
2. **Scaling by the standard deviation (dilation).** Divide each axis by its standard deviation, compressing a wide axis (like salary) and expanding a narrow one (like age) so every axis has spread 1.

### What happens to the shape of the cloud

Before scaling, the contours of equal density are **long ellipses** aligned with the high-variance axis. After standardizing, an axis-aligned elongated cloud becomes roughly **circular** (if the features are uncorrelated). A circle treats every direction equally, which is what a distance-based or gradient-based method wants.

Standardization does **not** rotate the data or remove correlation. If Age and Salary are correlated, the cloud stays a tilted ellipse, only less stretched. Removing correlation requires **whitening** (PCA with unit-variance components).

```python
import matplotlib.pyplot as plt
import numpy as np

rng = np.random.default_rng(0)
age = rng.normal(40, 10, 300)
salary = 60_000 + 1_500 * (age - 40) + rng.normal(0, 12_000, 300)       # correlated
X = np.c_[age, salary]
Z = (X - X.mean(0)) / X.std(0)

fig, axes = plt.subplots(1, 3, figsize=(15, 4))
axes[0].scatter(*X.T, s=8); axes[0].set_title("Raw (axes in different units)")
axes[1].scatter(*(X - X.mean(0)).T, s=8); axes[1].set_title("After centering")
axes[2].scatter(*Z.T, s=8); axes[2].set_title("After standardizing"); axes[2].set_aspect("equal")
for ax in axes: ax.axhline(0, c="gray", lw=.5); ax.axvline(0, c="gray", lw=.5)
plt.tight_layout(); plt.show()
```

Use `set_aspect("equal")` on the standardized plot, otherwise matplotlib will stretch it and hide the geometry.

# 6. Why algorithms care

## 6.1 Distance-based algorithms

KNN, K-Means, DBSCAN, hierarchical clustering, and kernel SVMs compute distances (section 2.2 and 4.7). Standardization gives each feature comparable influence.

## 6.2 Gradient descent: conditioning derivation

Take linear regression with mean squared error loss: $$L(w) = \frac{1}{2n}\lVert y - Xw\rVert^2, \qquad \nabla L = -\frac{1}{n}X^\top(y - Xw), \qquad H = \nabla^2 L = \frac{1}{n}X^\top X$$

Gradient descent updates $w \leftarrow w - \eta \nabla L$. For a quadratic loss with Hessian $H$ whose eigenvalues range from $\lambda_{\min}$ to $\lambda_{\max}$:

- **Stability** requires the learning rate $\eta < 2/\lambda_{\max}$.
- **Convergence speed** along the slowest direction is governed by the **condition number** $\kappa = \lambda_{\max}/\lambda_{\min}$. The error shrinks per step by a factor of about $\frac{\kappa - 1}{\kappa + 1}$, so you need on the order of $\kappa$ iterations.

For centered, uncorrelated features, the eigenvalues of $H$ are simply the feature variances $\sigma_j^2$: $$\kappa = \frac{\sigma_{\max}^2}{\sigma_{\min}^2}$$ With Age ($\sigma \approx 10$) and Salary ($\sigma \approx 15{,}000$): $$\kappa \approx \left(\frac{15{,}000}{10}\right)^2 = 2.25 \times 10^6$$ The loss surface is an extremely narrow valley: you must use a tiny learning rate (to avoid diverging along the salary direction) and then you need millions of steps along the age direction.

**After standardization**, every $\sigma_j = 1$, so $H \approx I$ (for uncorrelated features), $\kappa \approx 1$, the contours are circles, and gradient descent heads straight to the minimum.

```python
rng = np.random.default_rng(0)
n = 500
age = rng.normal(40, 10, n)
salary = rng.normal(60_000, 15_000, n)
y = 0.5 * age + 0.0002 * salary + rng.normal(0, 1, n)

def design(a, s, scale):
    if scale:
        a, s = (a - a.mean()) / a.std(), (s - s.mean()) / s.std()
    return np.c_[np.ones(n), a, s]

for scale in (False, True):
    X = design(age, salary, scale)
    H = X.T @ X / n
    print(f"scaled={scale!s:5}  condition number = {np.linalg.cond(H):,.0f}")
# scaled=False  condition number = about 10^9 or more
# scaled=True   condition number = about 1 to 2

def gradient_descent(X, y, lr, iters=500):
    w = np.zeros(X.shape[1])
    for _ in range(iters):
        w -= lr * (-(X.T @ (y - X @ w)) / len(y))
    return w, np.mean((y - X @ w) ** 2)

Xs = design(age, salary, True)
print("scaled, lr=0.1  ->", gradient_descent(Xs, y, 0.1)[1].round(3))       # converges (loss near 1)
Xr = design(age, salary, False)
with np.errstate(all="ignore"):
    print("raw,    lr=0.1  ->", gradient_descent(Xr, y, 0.1)[1])             # diverges (inf or nan)
```

The same reasoning applies to logistic regression and neural networks. Centering also matters: if features are not centered, the Hessian has large off-diagonal terms involving the mean (via the intercept column), which worsens conditioning even more.

## 6.3 Regularisation (Ridge / Lasso / Elastic Net)

Ridge adds a penalty $\lambda\sum_j w_j^2$. The size of a coefficient depends on the unit of its feature: if you measure salary in dollars, its coefficient is tiny and barely penalised; in thousands of dollars, it is 1,000x larger and heavily penalised. The result depends on arbitrary units. With standardized features, all coefficients are on a common scale and the penalty is applied fairly.

## 6.4 PCA

PCA finds the directions of maximum variance. With raw data the first component simply points along the feature with the largest numeric variance (salary), no matter how informative the other features are. PCA on standardized data equals PCA on the **correlation matrix** and is the standard choice when features have different units.

## 6.5 Why trees do not care

A decision tree picks a feature and a threshold $t$ to split on ("Age <= 30"). Standardization is a monotonic increasing map, so it preserves the order of values: the same partition of rows exists at the scaled threshold $t' = (t - \mu)/\sigma$. The tree builds the same splits, so predictions are identical. Trees do not use distances or gradients with respect to feature values.

# 7. Implementation with `StandardScaler`

## 7.1 The basics

```python
import numpy as np
import pandas as pd
from sklearn.preprocessing import StandardScaler

X = pd.DataFrame({"Age": [20, 30, 40, 50, 60],
                  "Salary": [30_000, 45_000, 60_000, 90_000, 120_000]})

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)               # returns a NumPy array

print(X_scaled.mean(axis=0).round(6))            # [0. 0.]
print(X_scaled.std(axis=0).round(6))             # [1. 1.]
```

## 7.2 `fit()` and `transform()` separately

|Method|What it does|
|---|---|
|`fit(X_train)`|**learns** the mean and standard deviation of every column from `X_train`|
|`transform(X)`|**applies** $(x - \text{mean})/\text{std}$ using the learned values|
|`fit_transform(X_train)`|both steps in one call (for the training set only)|
|`inverse_transform(Z)`|maps standardized values back to the original units|

```python
scaler = StandardScaler().fit(X)                 # learn
print(scaler.mean_)                              # per-column means:           [  40.  69000.]
print(scaler.scale_)                             # per-column std (ddof=0):    [14.14 31000-ish]
print(scaler.var_)                               # per-column variance
print(scaler.n_samples_seen_)                    # 5

Z = scaler.transform(X)
X_back = scaler.inverse_transform(Z)             # recovers the original values
np.allclose(X_back, X)                           # True
```

## 7.3 Getting a DataFrame back

`StandardScaler` returns a NumPy array, which loses column names and index. Convert back for inspection:

```python
X_scaled_df = pd.DataFrame(X_scaled, columns=X.columns, index=X.index)
X_scaled_df.describe().round(2)
```

In scikit-learn 1.2 and later you can ask for DataFrames directly:

```python
scaler = StandardScaler().set_output(transform="pandas")
X_scaled_df = scaler.fit_transform(X)
```

## 7.4 Options

```python
StandardScaler(with_mean=True, with_std=True, copy=True)
```

|Parameter|Effect|
|---|---|
|`with_mean=False`|skip centering; required for **sparse** matrices (centering would make them dense)|
|`with_std=False`|only center the data|
|`copy=False`|scale in place to save memory|

## 7.5 Implementing it yourself (to verify you understand it)

```python
class MyStandardScaler:
    def fit(self, X):
        X = np.asarray(X, dtype=float)
        self.mean_ = X.mean(axis=0)
        self.scale_ = X.std(axis=0)                       # ddof=0, like scikit-learn
        self.scale_[self.scale_ == 0] = 1.0                # constant column: avoid division by zero
        return self
    def transform(self, X):
        return (np.asarray(X, dtype=float) - self.mean_) / self.scale_
    def fit_transform(self, X):
        return self.fit(X).transform(X)
    def inverse_transform(self, Z):
        return Z * self.scale_ + self.mean_

mine = MyStandardScaler().fit_transform(X)
print(np.allclose(mine, StandardScaler().fit_transform(X)))       # True
```

Note the **constant column** case: if $\sigma = 0$, dividing by zero would produce `NaN`. scikit-learn sets the scale to 1 so the column becomes all zeros.

## 7.6 Incremental and large data

```python
scaler = StandardScaler()
for chunk in pd.read_csv("big.csv", chunksize=100_000):
    scaler.partial_fit(chunk[["Age", "Salary"]])         # running mean and variance across chunks
```

## 7.7 Saving the scaler for deployment

The scaler's learned `mean_` and `scale_` are part of your model. Save and reload them:

```python
import joblib
joblib.dump(scaler, "scaler.joblib")

scaler = joblib.load("scaler.joblib")
new_customer = pd.DataFrame({"Age": [35], "Salary": [72_000]})
scaler.transform(new_customer)                           # uses the TRAINING mean/std
```

Never refit on new incoming data in production.

# 8. The train/test rule and data leakage

## 8.1 The rule

> **Split first, then scale.** Learn $\bar{x}$ and $\sigma$ from `X_train` only, then apply those same numbers to both `X_train` and `X_test`.

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)     # fit on TRAIN, then transform TRAIN
X_test_scaled = scaler.transform(X_test)           # only transform TEST (never fit)
```

## 8.2 Why: data leakage

The test set is supposed to simulate **unseen future data**. If you compute the mean and standard deviation on the full dataset, information about the test rows leaks into the preprocessing. The model's evaluation becomes slightly optimistic, and it no longer mimics deployment where you only know past data.

Leakage with scaling is usually mild, but it can become serious with small datasets, strong outliers in the test set, or time series.

```python
# WRONG: fit on everything before the split
X_scaled = StandardScaler().fit_transform(X)
X_train, X_test = train_test_split(X_scaled, ...)

# WRONG: fit a separate scaler on the test set
X_test_scaled = StandardScaler().fit_transform(X_test)       # test now uses its own mean/std

# RIGHT
scaler = StandardScaler().fit(X_train)
X_test_scaled = scaler.transform(X_test)
```

Notice that the test set will **not** have mean exactly 0 and std exactly 1, and that is correct. It is scaled with the training statistics.

```python
print(X_train_scaled.mean(axis=0).round(3), X_train_scaled.std(axis=0).round(3))     # [0, 0] [1, 1]
print(X_test_scaled.mean(axis=0).round(3), X_test_scaled.std(axis=0).round(3))       # near, but not exactly, 0 and 1
```

## 8.3 In cross-validation

If you scale once before cross-validation, every fold's validation data has influenced the scaler. Put the scaler **inside a pipeline** so it is re-fit on each training fold (section 9).

## 8.4 Time series

Fit the scaler on the **past** only (the training window). For rolling forecasts, refit or update with only the data available at that time.

# 9. Pipelines and `ColumnTransformer`

## 9.1 Scaler + model in a pipeline

```python
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

pipe = make_pipeline(StandardScaler(), LogisticRegression())
pipe.fit(X_train, y_train)                       # scaler fits on train, then the model fits on scaled train
pipe.score(X_test, y_test)                       # test is transformed with the train statistics automatically

cross_val_score(pipe, X, y, cv=5).mean()         # no leakage: scaler refit inside each fold
```

## 9.2 Different treatment for different columns

Scale numerics, one-hot encode categoricals, leave dummies alone.

```python
import seaborn as sns
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder
from sklearn.pipeline import Pipeline

titanic = sns.load_dataset("titanic")
X = titanic[["age", "fare", "sibsp", "parch", "sex", "embarked", "pclass"]]
y = titanic["survived"]

numeric = ["age", "fare", "sibsp", "parch"]
categorical = ["sex", "embarked", "pclass"]

pre = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale", StandardScaler())]), numeric),
    ("cat", Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                      ("onehot", OneHotEncoder(handle_unknown="ignore"))]), categorical),
])

model = Pipeline([("pre", pre), ("clf", LogisticRegression(max_iter=1000))])
print(cross_val_score(model, X, y, cv=5).mean().round(3))
```

This follows the order from section 1: **impute, then scale; encode categoricals separately**.

|---|---|---|
|**Logistic Regression**|about 65%|**about 86%**|
|**Decision Tree**|about 79%|about 79% (**identical**)|

**Why logistic regression jumps.** Its optimiser (gradient-based) sees `EstimatedSalary` values around 70,000 next to ages around 38. The loss surface is badly conditioned (section 6.2), the optimiser may stop before converging (you may see a `ConvergenceWarning`), and the decision boundary ends up poor. **Why the decision tree does not change.** It splits on thresholds ("Age <= 36.5", "Salary <= 90,500"). Standardization preserves order, so the same row partitions are available and the tree structure and accuracy are identical (section 6.5). The thresholds simply move to the scaled axis.

# 11. Standardization and the shape of the distribution

Standardization changes the **axis values** but not the **shape**.

```python
import seaborn as sns
import matplotlib.pyplot as plt
from scipy import stats

fig, axes = plt.subplots(2, 2, figsize=(11, 7))
for j, col in enumerate(["Age", "EstimatedSalary"]):
    sns.kdeplot(X_train[col], fill=True, ax=axes[0, j]).set_title(f"{col} (raw)")
    sns.kdeplot(X_train_s[col], fill=True, ax=axes[1, j]).set_title(f"{col} (standardized)")
plt.tight_layout(); plt.show()

for col in ["Age", "EstimatedSalary"]:
    print(col, "skew raw/scaled:", round(stats.skew(X_train[col]), 4), round(stats.skew(X_train_s[col]), 4))
```

The KDE curves have identical outlines; only the x-axis tick labels differ (from 20 to 60 for age, from 20,000 to 150,000 for salary, versus about -2 to +2 for both after scaling). Skewness and kurtosis are unchanged.

### Misconception: "standardization makes data normal"

No. The word "normalization" in "Z-score normalization" refers to bringing to a standard _scale_, not to a Gaussian _shape_. A skewed feature stays skewed:

```python
income = np.random.default_rng(0).lognormal(10, 1, 5000)
z = (income - income.mean()) / income.std()
print(stats.skew(income).round(2), stats.skew(z).round(2))       # same strongly positive skew
```

To fix skew, apply a log, Box-Cox, or Yeo-Johnson **before** (or together with) scaling. `PowerTransformer(standardize=True)` does both.

### Interpreting z-scores

If a feature is roughly normal, the **empirical rule** applies: | |z| within | Share of data | |---|---| | 1 | about 68% | | 2 | about 95% | | 3 | about 99.7% |

So $|z| > 3$ is a common rule of thumb for an outlier. For skewed data the rule is unreliable (section 12).

# 12. Standardization and outliers

**Standardization does not remove or compress outliers.** An extreme value stays extreme, just expressed in standard deviations. Worse, outliers **distort the mean and standard deviation themselves**, so they distort the scaling of all the _normal_ points.

```python
rng = np.random.default_rng(1)
salary = rng.normal(60_000, 10_000, 200)
salary_out = np.append(salary, 1_000_000)                  # one extreme value (a CEO, or a data-entry error)

def z(a): return (a - a.mean()) / a.std()

zs, zo = z(salary), z(salary_out)
print("std without outlier :", salary.std().round(0))              # about 10,000
print("std with outlier    :", salary_out.std().round(0))          # about 66,000+ (inflated 6 to 7x)
print("inlier z range, clean :", zs.min().round(2), zs.max().round(2))                      # about -2.8 .. 2.8
print("inlier z range, w/ outlier:", zo[:-1].min().round(2), zo[:-1].max().round(2))        # squeezed to about -0.5 .. 0.4
print("outlier z-score        :", zo[-1].round(1))                                          # roughly 14
```

What happened:

1. The outlier inflated the standard deviation about 6 to 7 times.
2. The 200 genuine points were **squeezed into a narrow band** around 0, losing resolution.
3. The outlier itself is still far away (about 14 standard deviations).

**Handling outliers (do this before or instead of standardizing)**

|Option|When|
|---|---|
|Investigate; fix errors|the value is impossible or mistyped|
|**Cap / winsorise** at 1st and 99th percentile|real but extreme; keep the row|
|**Log transform** first|right-skewed data (income, prices)|
|**`RobustScaler`**|uses median and IQR, ignoring extremes (section 16)|
|Remove rows|clearly invalid and few|
|Use tree models|insensitive to outliers and scale|

```python
from sklearn.preprocessing import RobustScaler
RobustScaler().fit_transform(salary_out.reshape(-1, 1))      # inliers keep a sensible spread
```

# 13. When to use it, and when not to

## 13.1 Algorithms that benefit from or require standardization

|Family|Algorithms|Reason|
|---|---|---|
|**Distance-based**|KNN, K-Means, DBSCAN, hierarchical clustering|Euclidean distance is dominated by large-scale features|
|**Kernel methods**|SVM (RBF, polynomial kernels)|kernels are functions of distances|
|**Dimensionality reduction**|PCA, LDA (for stable numerics), t-SNE, UMAP|variance- or distance-driven|
|**Gradient-descent models**|Linear Regression (SGD), Logistic Regression, Neural Networks / Deep Learning|scaling gives even weight updates and faster, stable convergence|
|**Regularised linear models**|Ridge, Lasso, Elastic Net|penalty depends on the coefficient size, which depends on units|
|**Others**|Gaussian Mixture Models, Perceptron, Linear SVM|optimisation and distance effects|

## 13.2 Algorithms that do not need it

|Algorithm|Why|
|---|---|
|**Decision Trees, Random Forest, Extra Trees**|split on thresholds; invariant to monotonic transforms|
|**Gradient boosted trees (XGBoost, LightGBM, CatBoost)**|tree-based|
|**Naive Bayes (Gaussian)**|models each feature's own mean and variance|
|**Plain OLS linear regression** (closed form)|predictions are invariant to scaling; only the coefficients change|

> Even when it is not required, standardizing a linear model's inputs is useful for **interpretation** (section 15).

## 13.3 Features you usually should not standardize

|Feature|Reason|
|---|---|
|One-hot dummies (0/1)|they are already on a small scale, and standardization destroys their simple meaning (and sparsity)|
|ID columns|no information; drop them|
|Already bounded features (percentages 0 to 1)|usually fine as is; scaling is optional|
|Target variable|do not scale `y` by accident; if you do (neural-net regression), invert predictions afterwards|
|Sparse matrices (text TF-IDF, one-hot)|centering turns zeros into non-zeros and blows up memory; use `with_mean=False` or `MaxAbsScaler`|
|Heavily skewed features|transform first|

## 13.4 Quick decision guide

```
Does the model use distances or gradients, or regularise coefficients?
  yes -> scale (standardization is the default choice)
  no (trees) -> skip

Are there strong outliers in the feature?
  yes -> handle outliers first, or use RobustScaler
Is the feature skewed?
  yes -> log / power transform, then scale
Is the data sparse?
  yes -> with_mean=False or MaxAbsScaler
Do you need a fixed bounded range (e.g., 0 to 1 for image pixels or neural-net inputs)?
  yes -> consider MinMaxScaler (normalization)
```

## Use case 2: K-Means customer segmentation

RFM features: Recency (days), Frequency (orders), Monetary (spend). Monetary spans thousands, Frequency spans single digits.

```python
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

rng = np.random.default_rng(0)
n = 900
seg = rng.choice(3, n, p=[0.5, 0.3, 0.2])
rfm = pd.DataFrame({
    "recency":   np.where(seg == 0, rng.normal(60, 15, n), np.where(seg == 1, rng.normal(25, 8, n), rng.normal(5, 3, n))).clip(1),
    "frequency": np.where(seg == 0, rng.normal(2, 1, n),   np.where(seg == 1, rng.normal(8, 2, n),  rng.normal(20, 4, n))).clip(1),
    "monetary":  np.where(seg == 0, rng.normal(150, 50, n), np.where(seg == 1, rng.normal(900, 250, n), rng.normal(6000, 1200, n))).clip(10),
})

for name, data in [("raw", rfm), ("standardized", StandardScaler().fit_transform(rfm))]:
    labels = KMeans(n_clusters=3, n_init=10, random_state=0).fit_predict(data)
    print(f"{name:13s} silhouette = {silhouette_score(data, labels):.2f}   cluster sizes = {np.bincount(labels)}")

# Agreement with the true segments
from sklearn.metrics import adjusted_rand_score
lab_raw = KMeans(3, n_init=10, random_state=0).fit_predict(rfm)
lab_std = KMeans(3, n_init=10, random_state=0).fit_predict(StandardScaler().fit_transform(rfm))
print("ARI raw:", adjusted_rand_score(seg, lab_raw).round(2), "| ARI scaled:", adjusted_rand_score(seg, lab_std).round(2))
```

Note that silhouette scores from different spaces are not directly comparable; the agreement with true labels (ARI) is a fairer check here. In real projects, standardize, cluster, then **profile clusters in the original units** with `inverse_transform` or by grouping the original data by cluster label.

# 15. Interpreting coefficients and converting back

## 15.1 What a standardized coefficient means

Fit $\hat{y} = b_z + \sum_j w_{zj} z_j$ with $z_j = (x_j - \mu_j)/\sigma_j$. A one-unit change in $z_j$ is a one-standard-deviation change in $x_j$, so $w_{zj}$ is the change in $\hat{y}$ per **one standard deviation** of feature $j$. Because every feature is in the same unit, **you can compare their sizes**.

```python
pipe = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)
pd.Series(pipe[-1].coef_[0], index=X_train.columns).sort_values()
# larger absolute value = stronger effect per standard deviation
```

## 15.2 Derivation: coefficients in original units

Substitute $z_j$ into the model: $$\hat{y} = b_z + \sum_j w_{zj}\frac{x_j - \mu_j}{\sigma_j} = \underbrace{\left(b_z - \sum_j \frac{w_{zj}\mu_j}{\sigma_j}\right)}_{b} + \sum_j \underbrace{\frac{w_{zj}}{\sigma_j}}_{w_j}, x_j$$ So: $$\boxed{w_j = \frac{w_{zj}}{\sigma_j}, \qquad b = b_z - \sum_j \frac{w_{zj},\mu_j}{\sigma_j}}$$

```python
from sklearn.linear_model import LinearRegression

Xh, yh = fetch_california_housing(return_X_y=True, as_frame=True)

sc = StandardScaler().fit(Xh)
m_z = LinearRegression().fit(sc.transform(Xh), yh)

w = m_z.coef_ / sc.scale_
b = m_z.intercept_ - np.sum(m_z.coef_ * sc.mean_ / sc.scale_)

m_raw = LinearRegression().fit(Xh, yh)
print(np.allclose(w, m_raw.coef_), np.isclose(b, m_raw.intercept_))        # True True
```

Plain OLS therefore gives the **same predictions** with or without scaling; only the coefficient values change. The check above confirms the algebra.

# 16. Standardization vs other scalers

|Scaler|Formula|Result range|Sensitive to outliers?|Use when|
|---|---|---|---|---|
|**StandardScaler** (Z-score)|$(x - \mu)/\sigma$|unbounded; mean 0, std 1|yes|default for gradient and distance methods, roughly bell-shaped data, PCA|
|**MinMaxScaler**|$(x - x_{\min})/(x_{\max} - x_{\min})$|[0, 1]|very|bounded inputs (images, some NNs), no outliers|
|**MaxAbsScaler**|$x / \lvert x\rvert_{\max}$|[-1, 1]|yes|**sparse** data|
|**RobustScaler**|$(x - \text{median})/\text{IQR}$|unbounded|**no**|outliers present|
|**PowerTransformer** (Yeo-Johnson / Box-Cox)|power transform, then z-score|unbounded|moderate|skewed data; also fixes shape|
|**QuantileTransformer**|maps ranks to a uniform or normal|[0, 1] or normal|no|arbitrary shapes; destroys distances|
|**Normalizer**|divides each **row** by its norm|unit-length rows|n/a|text and cosine-similarity use cases (row-wise, not column-wise)|

Min-max normalization is the subject of [[10.Feature Scaling - Normalization]].

# 17. Reference and practice

## 17.1 Common mistakes

|Mistake|Consequence|Fix|
|---|---|---|
|Fitting the scaler on the full dataset before splitting|data leakage, optimistic scores|split first; fit on train only|
|`fit_transform` on the test set|test is scaled with its own statistics|use `transform` only|
|Scaling in cross-validation outside the pipeline|leakage across folds|put the scaler in a `Pipeline`|
|Scaling the target by accident|wrong predictions and metrics|scale `X` only (or invert `y`)|
|Scaling one-hot columns|lost meaning, dense sparse data|scale numeric columns only (`ColumnTransformer`)|
|Standardizing before imputation|mean and std computed with NaNs ignored, then imputed values distort the stats|impute first|
|Expecting normal-shaped data afterward|skew remains|transform skew first|
|Expecting outliers to vanish|outlier remains and inflates std|handle outliers or use `RobustScaler`|
|Forgetting to save the scaler|cannot reproduce preprocessing in production|`joblib.dump` and reuse|
|Refitting on production data|training and serving mismatch|reuse the saved training scaler|
|Comparing a pandas `std()` result to `StandardScaler`|`ddof` mismatch|use `ddof=0`|
|Scaling ID columns|noise features|drop them|
|Scaling for tree models "just in case"|no benefit, loses raw interpretability of thresholds|skip it|
|Applying `with_mean=True` to sparse data|memory error|`with_mean=False`|

## 17.4 Cheat sheet

```python
from sklearn.preprocessing import StandardScaler

# split FIRST
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)

scaler = StandardScaler()
X_train_s = scaler.fit_transform(X_train)        # learn mean/std on train, transform train
X_test_s  = scaler.transform(X_test)             # reuse train mean/std on test

scaler.mean_, scaler.scale_, scaler.var_         # learned parameters
scaler.inverse_transform(X_test_s)               # back to original units
pd.DataFrame(X_train_s, columns=X_train.columns, index=X_train.index)

# safest pattern
pipe = make_pipeline(StandardScaler(), LogisticRegression())
cross_val_score(pipe, X, y, cv=5)

# mixed data
ColumnTransformer([("num", StandardScaler(), num_cols), ("cat", OneHotEncoder(), cat_cols)])
```

|Question|Answer|
|---|---|
|Formula|$z = (x - \mu)/\sigma$|
|Result|mean 0, std 1, shape unchanged|
|Fit on|training data only|
|Needed by|KNN, K-Means, SVM, PCA, linear/logistic regression, NN, Ridge/Lasso|
|Not needed by|decision trees, random forest, XGBoost, Gaussian NB|
|Outliers?|not removed; use `RobustScaler` or cap first|
|Sparse data|`with_mean=False`|

## 17.5 Glossary

|Term|Meaning|
|---|---|
|**Feature scaling**|transforming features onto comparable ranges|
|**Standardization / Z-score normalization**|subtract the mean, divide by the standard deviation|
|**Z-score**|number of standard deviations from the mean|
|**Mean centering**|subtracting the mean so the new mean is 0|
|**Condition number**|ratio of largest to smallest eigenvalue of the Hessian; measures how elongated the loss surface is|
|**Data leakage**|information from test data influencing training or preprocessing|
|**Invariant**|unchanged by a transformation (trees are invariant to monotonic scaling)|
|**Whitening**|transforming to zero mean, unit variance, and zero correlation|
|**Affine transformation**|$ax + b$: a scale and a shift|
|**Winsorising**|capping extreme values at chosen percentiles|

## 17.6 Checklist

- [ ] Decided whether the model needs scaling (distance, gradient, regularised, PCA)
- [ ] Imputed missing values, transformed skewed features, handled outliers, encoded categoricals **before** scaling
- [ ] Split the data **before** fitting the scaler
- [ ] Fit the scaler on `X_train` only; used `transform` for validation, test, and new data
- [ ] Did not scale the target, IDs, or one-hot dummies
- [ ] Used a `Pipeline` / `ColumnTransformer` for cross-validation and deployment
- [ ] Verified train mean about 0 and std about 1 (not exactly so on the test set)
- [ ] Saved the fitted scaler with the model
- [ ] Checked that results make sense (compare scaled vs unscaled on one or two models)

## Key takeaways

- **Feature scaling** puts features on comparable scales and is normally the **last** preprocessing step before modelling, after imputation, transformation, and encoding.
- **Standardization** uses $z = (x - \mu)/\sigma$. It is the unique positive-slope linear map to mean 0 and standard deviation 1, which you can prove with $E[aX+b]$ and $\text{Var}(aX+b)$.
- Geometrically it **centres** the cloud at the origin and **equalises the spread** along each axis, making elongated clouds more circular. It does not rotate the data or remove correlation.
- It **preserves the shape of the distribution**, ranks, and correlations; it does **not** make data normal and does **not** remove outliers (which also distort the mean and standard deviation).
- Scaling is **required** for KNN, K-Means, SVM, PCA, linear and logistic regression, neural networks, and regularised models (it fixes dominated distances, poorly conditioned gradient descent, and unfair penalties). It is **not needed** for decision trees, random forests, and gradient boosted trees.
- Lecture experiment: **logistic regression rose from about 65% to about 86%** after scaling, while the **decision tree stayed at about 79%**.
- **Always split first**, `fit` the scaler on training data only, `transform` everything else, put it inside a **pipeline**, and save it for deployment.
- Standardized coefficients let you compare feature effects per standard deviation, and $w_j = w_{zj}/\sigma_j$ converts them back to original units.
